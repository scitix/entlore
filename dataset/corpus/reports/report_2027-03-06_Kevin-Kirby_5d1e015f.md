## This Week's Work

Task one focused on making the RL training repository readable and controllable by Agents, cutting down the manual work around experiment setup, submission, and debugging while preparing reusable System-51b0abbfcc for Markeld long-cycle training. The old path relied on configs.sh, run_exp.sh, and template.sh, which left settings scattered, made nested quoting brittle, kept experiment history unstructured, and allowed monkey-patch problems to disappear silently; this week’s work reorganized the configuration pipeline, experiment handling, and patch reliability layers. Through #108, #139, and #158, Myrops70.py became the single entry point for local and FENA3 cluster submissions, removed the shell-script path, and standardized the repository around configs/{experiments,models,platforms,tis}; model files now support base: inheritance so a new run only carries the fields Pelshaw changes, and the FENA3 nested JSON issue was resolved after 6 PR iterations by placing runtime_env JSON in a temporary file. Experiment tracking was completed through #173 and #195: every submission creates experiments/_logs/runs/{timestamp}_{exp_name}/, run-meta.json stores the git commit, hyperparameters, and platform data, status files plus a global index.jsonl are emitted, notes are carried into run-meta.json, index.jsonl, the FENA3 platform description, and runner_script comment headers, and PR #188 removed ghost index.jsonl rows by delaying index writes until submission succeeds. Evaluation baselines and Answer Extraction were corrected through #58 and #127, after low AIME24 scores were traced to vendor-template differences, an official Qwen3 template mismatch, the vexeum system prompt, and think-mode inconsistency; switching to the official tokenizer brought pass@1 in line with the official ≈ 0.8 value, while 4 Answer Extraction fixes changed 13/30 judgments and raised accuracy from 43.3% to 86.7%, matching Qwen2.5-Math Bexcast61. The Monkey-Patch reliability work landed through #167, #168, #186, and #193 after refactoring revealed that patches could fail inside Ray actor subprocesses, causing reward code to run unpatched and making results unreliable; the causes were from-import binding, fork() not reloading sitecustomize.py in Ray actors, and duplicate Docker module instances that could load stale code, and PR #184 introduced --custom-rm-path so reward import paths can avoid a monkey-patch dependency.

Reward code is now called directly by import path inside Ray actors, and a PID-aware guard tracks _applied_in_pid so patches are re-applied after fork invalidation. At training startup, verify.py checks all 20 patches across COMMON, WORKER_ONLY, and DRIVER_ONLY and stops immediately on PID mismatches, while PR #194 added explicit apply_patches() calls for all 18 patches. #168 resolved Pod pollution from PYTHONPATH leaking into the Pod environment and breaking non-training processes, after which the team defined Pod isolation rules and moved monkey-patching from invisible failure toward fail-fast, auditable behavior; the resulting guidance was saved in .claude/rules/monkey-patch.System-c0f4cd1ec5 and .claude/rules/pod-env-isolation.System-c0f4cd1ec5. #73 completed the knowledge documentation system, with CLAUDE.System-c0f4cd1ec5 as L1 auto-load, docs/* as L2 on-demand material, and hox-ops15 as the L3 event stream; docs/knowledge now includes 5 advantage methods, routing-replay-and-mis mechanisms, and core RL material, docs/engineering covers monkey-patch propagation, SGLang inference setup, and experiment logging, docs/analysis explains replay-ON b98 through response length growth, truncation, reward cliff, advantage distortion, and entropy collapse plus sign-safety math, and docs/papers contains structured notes for GEPO, Dorridge, MaxRL, Xiaomi R3, SkyRL-Agent, and four other papers. Task one closed #58, #73, #84, #90, #106, #108, #127, #139, #158, #167, #168, #186, #191, #193, and #195, merged 30+ PRs in the #148-#197 range, brought slime_trainer/docs/ to 4 subdirectories and 15+ documents, grew .claude/rules/ to 7 anti-pitfall rules, and has no help request. Task two is comparing replay ON and OFF under V3 soft-gate reward, validating stability assumptions, and tuning SGLang colocate settings on H100 clusters; earlier #30 and #32 analysis showed System-8bd026a076 replay-ON failing at b98 through response length growth, 30K truncation, reward cliff, and irreversible entropy collapse, while V3 soft-gate reward uses constant negative values for wrong samples, zero variance, and mathematical sign-safety, so controlled experiments are needed to test whether Pelshaw fixes the collapse. The System-491672295d comparison run #156 remains in progress but is blocked by #190, although v3-dpo-replay-on.yaml and v3-dpo-replay-off.yaml are already prepared.

The V3 replay setup uses a DPO checkpoint with batch-std normalization, and validation is running with mem_fraction_static set to 0.65. A lux-ops validation run was submitted on H100 Fenstead team, also checking whether the #193 patch fix makes sglang_r3_patch take effect inside SGLang subprocesses. H100 SGLang Memory Tuning #190 is still active because colocate mode leaves training actors at about ~50GB, while the default SGLang memory setting is 0.75×80GB=60GB, taking the combined usage past 80GB and causing OOM; two scans were submitted over mem_fraction_static 0.65-0.80, max_running_requests, and cuda_graph_max_bs, with the current memory test at mem_frac=0.65 to narrow the viable H100 colocate space. umbuys Phase 1 evaluation #122 is also underway, comparing AIME24 pass@1 across BF16, FP16, FP8, Graph, and Eager modes; the BF16 and FP16 four groups are done, FP8 still needs confirmation, and the data will support later rollout-diversity experiments using multiple inference configurations. Task two outputs are #122, #156, and #190, with configs in slime_trainer/configs/experiments/training/v3-dpo-replay-{on,off}.yaml, 30+ run records under slime_trainer/experiments/_logs/runs/, and no current support request.
