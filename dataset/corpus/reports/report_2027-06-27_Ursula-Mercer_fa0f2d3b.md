## This week's work

System-9552486fa5 focused on better LLM inference-service performance benchmarking for single-point, matrix, scan, multi-source, and multi-resource cases, while also adding checks on real clusters; System-f0b524f166 moved several first-phase items into an enhanced stage. The benchmark work currently measures throughput, latency, and success rate only, with functional correctness left outside this phase, and the available capabilities have already been released online. Real-cluster e2e runs covered single-point, cache matrix, sweep scan, multi-cell cache, and multi-shape sweep cases, including newly added multi-shape sweep coverage; validation showed task submission, scheduling, result persistence, report access, heatmaps, and curves all working normally. Real dataset-source checks verified OSS upload/download and task execution via the internal S3 protocol, while task echo and UI views now mask sensitive credentials without affecting normal credential injection during scheduling. Resource-spec passthrough and benchmark-worker auto-tuning were designed and verified: the frontend reuses the platform selector’s hidden instance count, the backend derives and caps workers from actual CPU resources, and tuning covered small-spec non-regression, oversized-value fallback, and abnormal-value protection. Accuracy fixes addressed warmup first-tier loss, single/cache fixed-N judgment errors, sweep computation bias, and matrix synthetic-source preset needs; after tests and documentation were added, review was completed.

System-94307ed940 added System-65033b0adf separated-deployment support, targeting GLM 5.2 multi-role orchestration, state aggregation, routing, probes, scaling, and real-cluster launch validation. Deployment verification finished successfully, Dorholm and Oskmarch clusters went online, and the capability now supports the GLM 5.2 PD-separated version. A new System-65033b0adf deployment type based on native LWS plus Deployment resources was verified on online clusters. Dorholm troubleshooting covered SGLang PD 502 responses, CrashLoopBackOff, cross-cluster etcd issues, model mount permissions, and DeepGEMM 503 checks; the team traced causes and proposed corrections for in-cluster etcd, image permissions, model paths, probe behavior, and startup parameters. Validation exercised offline service handling, scaling, update, rollback, and state aggregation, with service resource release, instance-count adjustment, and request-log observation behaving as expected. Release fixes improved inference-service status and rolling-update reliability by reducing concurrent status overwrite risk, duplicate events, and noisy alerts; the team completed a repair design for service state-machine concurrency, added optimistic locking and partial state updates, stopped repeated unchanged stable-running events per scheduling cycle, prevented normal skips from alerting as exceptions, and passed clean e2e checks for ObservedGeneration update and rollback paths. New-service creation, old-service offline flow, and repeated status checks confirmed the update chain, and alerting rules for System-d8d4533322, internal services, suppliers, and platform components were completed to lower false positives and make alerts easier to interpret.
