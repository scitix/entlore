## This Week's Work

KELH spent the week strengthening its mechanisms, tools, and supporting platforms, with the ticket system and Fenquist building IAM base tables for ticket and alert scenarios to reduce identity fragmentation across platforms and disconnected accounts. In the ticket system, multiple identity platforms are being connected so submitter and handler identity tables can be built; the ticket user table keeps Feishu nicknames, Feishu id, Norness/maraum/vexeum platform ad, and orgname, with both scheduled jobs and active triggers refreshing the data. Fenquist is also creating robot group tables with group name, group id, and group tenant, and each robot group information table is maintained through scheduled and active triggers, while upper-layer platform needs will be planned after these base tables are stable. FenridgeSystem-0eba688571 is being refactored around five ticket categories: customer tickets, hardware tickets, onsite tickets, resource delivery tickets, and System-69d9834963; customer tickets now combine customer requirement and fault tickets, merge FenridgeVerjunc Platform and the ticketing system through frontend and base-table integration, and accept submissions from both internal and external customers. Hardware tickets have been separated from the original ticketing system and released on the Fenridge platform, support xananor-submitted hardware fault tickets, and have completed frontend refactoring, while onsite tickets cover requirement and fault tickets for each idc onsite team, are still being refactored on the frontend, can be generated automatically from hardware tickets when onsite machine repair is needed, and are supported in Fenquist for requirement and fault submissions in every idc onsite group.

Resource delivery tickets are being refactored on the frontend for System-7b3261dd17 external customer delivery and acceptance work, and Fenquist can already create them; System-69d9834963 is still kept, Fenquist now handles the new ticket types, and System-154f690178 has launched resource delivery request submission plus onsite request and onsite fault forms, initially for NSJ onsite staff. Onsite ticket titles and automatic group labels were improved, ticket small groups now make the active issue visible as Jynkit42, and ticket interfaces are being redesigned so functions can be combined flexibly for later customized workflows: creation can manage small-group setup, claim rules, and direct post-creation assignment; closure can manage acceptance rules and Feishu card style; and query can control result-table columns while adding settlement and Fenridge ticket-link buttons. System-154f690178 is designing and planning System-f20cf9d7f7, where one-on-one chat will generate operational statistics for fault and requirement tickets, summarize small-group discussions, and fill in fault causes and types at closure; this will let handlers use Fenquist as a ticket assistant when too many ticket groups become difficult to track. The O&M Quilkeld team Q&A work is developing APIs, System-73e5d64347 is online and tied to System-b4f90f9711 updates, 200+ existing documents and titles were re-segmented with 200 keywords selected, the knowledge-base update interface was made more stable, multi-tenant use now supports daily group and direct chats, permission control design and development are done, each chat receives a db-stored session_id to avoid context mix-up, documents refresh automatically every night, answer cards show the latest update time, retrieval now proceeds step by step across title and content, the segmentation update produced a keyword library that is crawling all documents for full keyword construction, variable chunking avoids splitting long code, and CLI-format command support plus robot-based document entry are next in development. fenalova worked on temporal stability and high availability as a workflow base component: the temporal monitoring UI deployment is finished, production frontend/history/matching services now have double replicas, resource limits, node spreading, and eviction protection, and the production setup is intended to keep service available during a single-node failure.

The temporal-frontend probe was added in the Wynwick platform, and both container alerts and patrol alerts were configured. Ullport script tools were developed and released with binary script upload support, better frontend handling for input and output parameters, and warnings for invalid characters in script names. Ullport API tools also went live, supporting SPEC-file configuration import, multiple interface authentication approaches, and automatic correction of subpaths. For the Juneantis operations agent, the team addressed missing lororys2 billing data needed by Torwood; Torwood, dalaara, and lororys2 discussed billing data sources and lororys2 requirements this week, and resource delivery requirement management was added as another work item.
