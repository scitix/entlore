For System-54629d2ab8 curriculum learning on Qwen3-1.7B System-f9d43993fc, experiments compared Base and SFT iter_2000 starts, bucketed DAPO data by difficulty, and ran 2k / 4k / 8k / full curricula using DAPO/think reward, GSPO, TIS, MGPO/maxRL, rollout_batch_size≈16, n_samples_per_prompt=16, and 2 epoch, with fixed AIME 2024/2025 evaluation sets. The Base path benefited overall, as moving from 2k to 8k/full raised AIME pass@1 peak from 8.1% to ~12% and pass@8 from 25.0% to 30.0%; the SFT start was faster and steadier, reaching the base-full 663-step level in only 377 steps, peaking at 30.0% pass@8, and holding its final value without a later drop. [Goreon] also drove GORALOS System-4c24f44248 post-training with @Lumfell Monroe, @Quinn Carter, @Ivan Dawson, and @Mia Lawson to advance the GORALOS CPT post-training path, covering System-680e22b3c0, System-54629d2ab8, System-8d12e58850, and full-vocabulary OPD routes, with a unified OPD-merged version planned after staged convergence and a reference to Goralos RLVR Model Training Plan 05.

The goralos dataset was standardized into 1,103,184 canonical rows spanning 19 subtasks across RNA, protein, and oligonucleotide work, with ProteinGym, RNAGym, Nyxjunc, OligoGym, and TAPE as upstream sources; the new SFT/RL splitter assigns 50% SFT and 50% RL by sampling split_group groups, and Coreent records the SFT training-data path. Two SFT coldstarts from the Qwen3-System-fc7c4870ff CPT checkpoint completed stably, using @Ivan Dawson Nvidia tovflow SFT data plus @Mia Lawson Goralos Ranking data, with the current setup running 8-way packed SFT, holding Goralos Ranking at 25% of the mix, training on 10w train_samples with 8 nodes x 8 GPU and global_batch_size=64, saving one ckpt every 200 steps, tracking under BelenentLM naive_sigmoid_sft, and leaving leaderboard evaluation still open. The known data issue is inconsistent non-thinking formatting: the intended pattern is `\\n\\n`, current General SFT data already uses `\\n\\n`, and the team temporarily aligned non-thinking data to that General SFT style. On System-680e22b3c0 Reward, the team completed literature review and reward-function design for Goralos Ranking RL, where Rank-R1 uses GRPO with think mode for ranking validation and reports that binary reward plus 18% data can match full SFT effectiveness; Rank-GRPO instead treats rank positions as action units, gives each position its own reward rather than token- or sequence-level reward, and applies causal DCG so each slot is accountable only for itself and following slots, reflecting that mistakes near the top matter more than tail errors. Soloion implemented three Goralos Ranking reward variants, finished correctness checks and offline random-answer distribution validation, while real RL runs remain pending; System-0e30087f82 is the default graded pairwise option, decomposing each 4-way ranking into 6 pair comparisons with DCG weighting, top-1 bonus, and think-tag penalty, and offline checks found roughly symmetric random rewards with mean≈0.03, about 45% positive and 45% negative outcomes, differentiated scores for every sample, and the strongest gradient signal. System-a229fad979 is the exact-match binary Rank-R1 baseline.

Offline checks for System-a229fad979 found that 95.5% of random answers received reward=0 and only 4.5% matched exactly for 1.0, making the reward signal highly sparse; System-7f318da928 instead weights all 6 pairwise comparisons the same, does not separate first-place errors from last-place errors, and computes a -1 to +1 score by counting correct versus incorrect pairs. System-7f318da928 produced 7 discrete reward levels from 0/6 to 6/6 concordant pairs, performing above binary reward but below the default variant, and @Ethan Zimmer with @Quinn Carter completed DPO code migration for per-token, topk, and full-vocab modes while DPO experiments are still being validated. System-7d21cb971e runs from January 2026 to June 2026 and is intended to create a reusable, sustainably evolving, high-performance post-training execution base. @Brian Ellis, @Zhao Aiden Ellis, @Ivan Jarvis, and @Iris Lawson own stable execution of core post-training paths, including reliable Qwen-System-fc7c4870ff runs, performance baselines, and recipe SOP documents or templates for SFT → DPO → Eval, SFT → RL based on Slime → Eval, and zeroRL based on Slime → Eval. The team will coordinate Slime / SGLang / Megatron versions for controlled upgrades, with @Luna Carter maintaining iterable internal Slime / SGLang / Megatron versions, healthy tracking of community releases, and the related Xalwick; @Aiden Dawson will add basic profiling so bottlenecks, regressions, and behavior changes from version updates can be attributed.
