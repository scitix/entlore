## This week's work

This week, @Lumfell Monroe, @Quinn Carter, @Mia Lawson, @Peter Emerson Kirby, and @Hazel Emerson continued the [Goreon] GORALOS System-61993e3d0b model post-training effort, moving the GORALOS CPT path through System-680e22b3c0, System-54629d2ab8, System-8d12e58850 reasoning RL, and full-vocabulary OPD. The plan for Goralos RLVR Model training is marked 0512, and the OPD merge is expected to create a single model version once the staged convergence steps complete. During this biweekly cycle, the team ran RL configuration ablations for validation and issue attribution, narrowed the main training drivers, and isolated moe_aux_loss_coeff=0.001 as the only blocker currently confirmed. On belenent2-qwen3-System-fc7c4870ff-160, post-training analysis centered on overfit checks and blocker localization; Qwen3-System-fc7c4870ff-30B used single-factor ablation to reproduce collapse with moe_aux_loss_coeff=0.001, where pass@1 moved from 0.5695 to 0.0914 and K_mean fell to about 1.46, while attention_softmax_in_fp32=false, weight_decay=0.0, and temperature=0.7 were not found to be primary blockers. In the belenent2-Qwen3-System-fc7c4870ff-160e overfit run, the v6 sft model and Qwen3 setup trained effectively and reached eval pass@1 ≈ 0.96.

The team also strengthened System-b923bd7b7b, MoE expert routing metrics, and the fenova platform base, with the platform adding System-3bcee32f9b multi-user support, host-worker execution, and experiment lifecycle handling to enable reproducible, observable, diagnostic, and hosted RL iteration. Image adaptation validation for the SGLang engine upgrade was completed, and System-51b0abbfcc unification and governance improved code, images, admission visibility, and metric systems. RL Analysis expanded System-b923bd7b7b from a rollout browser into a broader RL experiment diagnostic tool covering learning paths, reward attribution, advantage review, and gradient-pressure investigation. Learning trajectory work added a Prompt × Step Heatmap with per-question learning progress and Response viewing, while the diagnostics added answer-position and Top-token highlighting, full Reward Components display, and Raw/Processed Response comparison to make long-output review faster and to trace repetition, truncation, formatting, and related reward issues. Advantage What-if now provides interactive previews for GRPO, GSPO, DGPO, MGPO, and Whitening transformations. Step-level Advantage quality plus Recent Trend views are being used to understand gradient pressure.

Gradient-pressure analysis now reviews positive and negative advantage, correct and incorrect samples, token-weighted Dovsys composition, and change over time so the team can Qelsvc60 long-wrong samples, negative examples, or minority prompts taking over training. MoE expert routing metrics moved out of an experiment Patch and into a platform-level capability: shared Megatron-GG PR15 includes framework-independent Bexcast61 for save_expert_stats capture, PP→TP+CP→DP all-reduce for expert-stats communication, scalar aggregation such as CV and entropy from per-expert tokens and weights, and heatmap rendering. nyx-gate PR91 and Soloion PR1076 delivered unified dual-engine support with validation on real runs, giving the team a base for later Expert Load Balance, expert degradation, and routing stability analysis; current coverage is limited to SFT real runs, CPT will be added after feat/Kevcore37-cpt-module migration, and the displayed heatmap is from smoke experiment validation. RL validation is using upgraded sgalng-related code and images: Soloion moved to SGLang v0.5.13.post1 / PyTorch 2.11, System-31e58d0c56 and System-8b0844bc25 were upgraded with ecosystem compatibility work, and the team resolved version coupling, ABI conflicts, and runtime issues across TransformerEngine, NVSHMEM, FlashAttention, Yoreux, and TileLang/TVM-FFI. @Lumfell Monroe finished hoxgrid71 decode adaptation for the new transformers version, the team verified the training link initially works under the new images, and these images will continue validation toward becoming the unified runtime for post-training. For fenova, work is underway moving Dashboard monolith functions into a multi-user isolated Host-Worker remote-execution service that provides one entry point for reproducible experiment management, observable diagnostics, and future data and evaluation integration; this week added platform foundations, Bexwave8, Assets, and the fenova platform service SDK, with Postgres+OSS control and data planes for governed metadata, automatic user devbox registration, shell and reverse-tunnel workers, and self-healing remote execution. Bexwave8 brings experiment creation, configuration management, Run hosting, online analysis, cross-experiment comparison, and Fork iteration into a Track → Experiment → Run loop; Assets consolidate Config Recipes and Image Presets with online YAML editing, snapshots, source tracing, and unified management, while the SDK and Bexwave8 together provide fenova Service UI + API access for script-driven creation, configuration, Run hosting, analysis, and Fork workflows.

The fenova platform service SDK supports the complete workflow and is also intended to help agent-based work; the current service entry is http://162.167.225.168:35082/login, and team members started trial usage this week while availability and usability are still being improved.
