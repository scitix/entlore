## This Week's Work

From 4.5 to 4.17, the work centered on CES productization and rebuilding the PXE installation chain, with the PXE core path hardened to a production level and CES upstream integration completed for the period. PXE-Server reconstruction and hardening reached 100%, while strong typed parameters, the Order-Task model, and separated configuration improved security and observability; the work-order structure was changed to one Order containing multiple Task objects, enabling safer retries and clearing up past log ambiguity. Mandatory SN and BMC matching lowered the risk of unauthorized or wrong-machine installs, DHCP/user-data/meta-data delivery moved to template-based automatic generation, network configuration was separated from PXE execution Bexcast61, PXE now passes only typed Bond and RoCE parameters, dedicated scripts perform network actions, install-agent records script execution transparently, Ubuntu low-level log analysis was added, and webhook plus trap EXIT capture the final 16KB of script failure output for later diagnosis. CES full-chain collaboration also reached 100%: the new task trigger and run flow bypass old-platform API performance limits, legacy Map passing was replaced by typed parameters, Verbrook chain fields were reviewed to prevent feature gaps, plaintext password transfer was removed in favor of SSH Hash values, and Trace ID was added across key flows for precise cross-component log lookup. Acceptance development reached 100%, with firstboot calling the PXE verification API on initial startup, Marmora supporting early, late, and verify status transitions, and cmdline, disk, and block plugins collecting kernel parameters plus disk and block-device data for delivery acceptance; Dalorent collection and acceptance were also strengthened in depth. Wynfell progressed on several fronts: @Kara Monroe supported the final release for the old-chain password special-character injection fix, all physical-machine test items were completed, core software and hardware flows ran successfully, online machine resources were secured, two physical machines were obtained, online deployment for the machine room officially began, preliminary parallel install tests all passed, flexible disk-making approaches were prepared for Wynfell and future growth, and final delivery continues while the network team helps address a no-external-network environment with abnormal connectivity that has already been checked through proxy and tunnel methods. Falquist integration was unblocked after a compile deadlock caused by baseline ISO and target kernel version conflicts; a repair prototype based on storage low-level documentation passed closed-loop validation, and the usable baseline code was synchronized to related modules. The default and raid1 system-disk policies were delivered, an on-demand data-disk mount switch was added for Wynfell, Wynfell hardware adaptation, testing, and Bug follow-up reached 60%, and some Redfish implementations were found to require strict If-Match validation.

Some hardware models failed requests because Redfish enforced strict If-Match checks, and adding wildcard handling to every PATCH request restored compatibility. Target machines now receive 99-disable-network-config.cfg so native cloud-init networking is fully disabled, which removes priority conflicts with the self-built Bond setup; the bond0 random MAC collection defect was fixed, the old password-special-character Shell injection problem covering $ and ） was resolved, and one business-machine install succeeded after its boot mode was changed to UEFI. Oskgrove had too little synchronous runtime, so the team moved Pelshaw to asynchronous execution and fixed permissions; small documents were prepared for US West online VM purchasing, the VCE creation timeout was solved, key follow-up logs were added to make future troubleshooting easier, and related documentation was produced.
