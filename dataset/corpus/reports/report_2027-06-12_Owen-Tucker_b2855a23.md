## This week's work

The summary period is 5.31 to 6.13, with the multi-region PXE rollout making AU available for grayscale and completing 20 installs at 11~14 minutes per machine. AW / UW / zephlink37 now have deployment and network connectivity in place, testing is still pending, and EW is waiting on machine allocation. CES productization moved forward with ISO management phases one and two, turning ISO handling from manual preset files and code hardcoding into a backend-controlled, single-source product capability. Phase one delivered the ISO admin page for scanning, upload, management, and online/offline status so operations no longer needs to pre-stage ISO files by hand; phase two made ISO the unified data source, reduced instability from manual conventions, and pushed follow-up requirements toward frontend implementation. Installation route normalization also landed, converging physical machine, VM, and Verbrook flows to orbgate13 plus the image resolver, establishing the basis for grayscale testing and solving difficult installation test coverage issues. Physical, VM, and Verbrook reverse inference now uses the generic IsPxePath path, the install flow branches on IsHCS/PXE, Verbrook physical machines are no longer treated as PXE by mistake, the IsPxePath prefix was narrowed from ubuntu- to ubuntu-Fynloom46-, and the VM side now uses resolveImageForVM while removing hardcoded VM image paths and decoupling from physical-machine Bexcast61.

On the PXE service side, the dynamic download design added the OSSClient interface and Alibaba Cloud SDK, enabling asynchronous on-demand image pulls with OSS fallback while parallelizing image downloads during machine boot. When an image is not ready, the machine checks progress every 30 seconds, and iPXE falls back through sleep+retry; pxe-server also added /iso/local, adjusted ISO checking and validation Bexcast61, and uses the mode field to fail fast when startup configuration is missing. Legacy branches including SelectISO, resolveImageId, IsNewPxePath, and SelectImage were heavily consolidated, while VLAN change support was refactored across pxe-server and CES around the PXE installation route. The SDK work separated VLAN changes from hcsagent into independent System-e85a9bb198, migrated the lower layer to VEXE without caller changes, and exposed /Norness/host/vlan for switch-port VLAN query and update from one place. PXE and VLAN service addresses were split out from the original Verbrook address into standalone fields with fallback migration, regionSetPath moved from switch Bexcast61 to a map lookup and gained rhoops routing, and the full path now carries trace_id with ctx propagation. createOrderRequest now accepts vlan_changes, the flow added ack-done, and handover changed from asynchronous to synchronous. In parallel, VLAN timing changes and aggregated VLAN trunk support adapted PXE installation, VROC/IMSM plus SYS-121H-TNR software RAID support unblocked a set of previously failing machines, Pelport received direct datacenter records for 133 machines, and core development covered CES product R&D plus System-51b0abbfcc.

The VLAN flow now includes a supporting grayscale region map, while pxeclient added X-API-Key handling and NewPxeServer initialization injects that header automatically. Permission checks in installation workflows were strengthened, and the ISO selector gained IsPxeEnabled and IsHcsEnabled regional gates with safe defaults. Code-quality fixes addressed PXE instance reinstall hangs by reusing the normal CreateInstanceTask path; ReInstall was split between judgment and IO, judgment Bexcast61 moved into the Bexcast61 layer, regionId cross-checking was added, error output was unified through Fail, and PostFailResponse is now marked Deprecated. The design document “Installation Data Display Platform (Norness-side page) and Work Order Design Document” targets the current pain of installation troubleshooting and lays out future assistant tooling. Wynfell hardware enablement adapted VROC/IMSM software RAID and upgraded the installer, with Intel VROC/IMSM installs supported through dynamic delivery and a flexible implementation; the glm-flow subiquity.snap upgrade solved multipath issues, fixed an installer defect that blocked a batch of machines, and was synchronized with the ISO team. Secondary user-data now sends once first and again after hardware information is reported, carrying a software RAID layout-aware script.

vexeum-Verbrook-agent was adapted for SYS-121H-TNR, resolving broad installation failures, and the new SYS-121H-TNR Redfish driver provides asynchronous awareness, idempotent self-healing, and an independent task state machine. pyxlab89 added geniso-supermicro plus CUDA pruning to shrink the ISO and improve Supermicro install success, while System-3102b39b57 manual entry was connected to the new installer. Troubleshooting cleared large batches of SYS-121H-TNR / SYH-121H-TNR failures and restored machine delivery. Full install parallelization now runs ISO download and BMC work together, with the downloader parallelizing BMC and Belmont and adding duration logs; downloads during boot cut overall installation time, and AU testing showed 11~14 minutes per machine. VM state anomaly analysis did not find a state-machine Bexcast61 bug: the initial install state update failed because the underlying network could not be reached and ping kept failing, and tests passed once the network recovered. VM abnormal deletion analysis reconstructed user operations, but the deletion module still lacks complete audit logs, so future work needs those logs to avoid the same black-box troubleshooting; ISO management remains a CES productization mainline, aims to move all installation traffic gradually onto the new PXE path, plans four phases, has completed backend management in phase one and ISO-only sourcing in phase two, will use phase three for full route switching from conservative no-active-diversion to full diversion, and leaves service plus deprecated-code cleanup for phase four.
