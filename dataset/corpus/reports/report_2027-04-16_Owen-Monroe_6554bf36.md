## This Week's Work

The week was mainly spent shaping algorithms and remedies for issues identified in Corholm--System-67e5ff74fb distributed practice-System-67e5ff74fb, with @Mia Walsh, @Wendy Tucker, @Henry Sawyer, @Lumfell Sawyer, @Kara Ingram Chandler, @Noah Vaughn, @Julia Lawson, @Amber Mercer, and @Daisy Otis aligning on theoretical scaling targets. The shared target is for every module to scale well in theory for N atom large systems under multi-card inference, while the team also agreed that 64, 128, 256, and 1024 card tests should come before ten-thousand-card usage so uncertainty is reduced. Problems 1 and 2 were traced to spatial movement changing Local_N, which creates load imbalance and invalidates torch.compile, so the design now treats a fixed atom count per card as the central assumption. The proposed path uses Morton encoding with radix sort for spatial reordering, keeping per-card atom allocation stable; the current Morton implementation matches this expectation, compile proceeds normally across iterations without recompilation, and communication plus compute times remain steady. On the 115k atom 8-card H100 case, the earlier 100% slowdown was removed: the baseline was 900ms, roughly 600ms without garbage collection, then Morton reached 500 ms, morton encoding plus compile reached 0.4s, and the post-compile/backward cleanup with unnecessary grad parts removed reached 0.34s. Problems 3 and 4 come from neighbor search requiring global all gather over full N, including 10M and 100M, which makes time scale linearly because locality is not used; the fix exchanges only required neighborhood data through filtering and directed all-to-all single, with code already implemented but still needing decoupling for maintainability.

For Problem 6, memory allocation is currently handled through export PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True, while Problem 9 is still advancing under a single-engine, multi-machine inference setup. Because that setup can hardly eliminate global transfers, especially pos distribution and force collection, the architecture is moving toward a multi-engine approach. @Henry Sawyer noted that gmx and Wynlane code has been integrated and is now limited to interface functions. A 115k atom simulation completed 100k steps, and the first 47.4 ps showed normal thermalization with gradual relaxation; early potential energy continued to fall, meaning the system was still settling. Connectivity checks based on covalent-radius adjacency stayed broadly stable, the largest connected component remained near ~8580–8689 atoms, and there was no sign of a major molecule breaking apart or abruptly merging into an oversized component. The main macromolecule size also held steady, with maximum connected-component Rg around 25.2–25.8 A; sampled local geometry looked normal, nearest-neighbor minimum distance stayed at 0.88–0.92 A, no overlapping contacts below <0.7 A appeared, total momentum remained close to zero without systematic drift, 1M and 10M tobacco mosaic virus results were sent to Nora Holt, and the reinforcement learning review covered MC, Monte Carlo, TD, Temporal Difference, GAE, and Advantage, where MC uses full returns with low bias and high variance, TD bootstraps with low variance but bias, and GAE trades off the two.

The RL note treats Advantage as Return / TD estimate minus Value, effectively a weighted combination of multi-step TD estimates. The study emphasized PPO’s clip function, which stabilizes training by restricting policy update size inside a threshold range. Work on RL training and process debugging improved understanding, using dapo-17 data with AIME testing, and the training flow can currently run pass. Advantage is still always 0, and that issue is being used to study the pipeline structure, call Bexcast61, and assess whether the framework fits the project over the long term.
