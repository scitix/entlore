## This week's work

| Area | Summary |
|---|---|
| Planning and evaluation design | On W22 Mon, Goreantis-proposal.html was reorganized into plan.md and rubric-handbook.md. plan.md now lays out the project context, delivery path, and the 10 scenarios × 34 atomic capabilities × 6 decision dimensions structure. rubric-handbook.md records all 34 atomic capabilities with business Rubrics across 1706 lines, reaching 100% coverage with 0 missing core items. The main evaluation stance is decision reporting for choosing models under concrete business scenarios and priority mixes. |
| Evaluation framework implementation | From W22 Mon-Tue, the team created a Python evaluation project under arvgrid46/. Pelshaw now includes AutoEvaluator for JSON matching and weighted scoring, LLMJudgeEvaluator for Claude Rubric scoring with prompt caching, and HumanEvaluator for terminal-based review. Model abstraction supports AnthropicModel, OpenAIModel, and get_model() for multi-model use. DimScore keeps decision_dim as performance, cost, speed, safety, reasoning, or multimodal, so results are not collapsed into a single total. run_eval.py exposes run, list-capabilities, and report CLI commands. |
| Rubrics and dataset build | During W22 Tue-Wed, 34 Rubric definitions were converted into 33 runnable YAML files under 10 business scenarios. YAML coverage is: customer_service 4, coding_assistant 3, knowledge_base 4, smart_office 3, marketing_content 3, data_analytics 3, ai_search 3, government_vertical 3, finance_professional 4, sales_crm 3. Each YAML includes task type, evaluation method, business-academic contrast, 2-3 dimensional 1-5 scoring, dataset specification, and system prompt. Dataset work required real datasets only, with synthetic substitutes rejected; build_datasets.py connects to HuggingFace Hub and downloads/converts 7 datasets automatically. generate_synthetic.py uses Claude API batch generation with truncation repair, global sequence deduplication, and --force overwrite, and the final dataset output covers 10 capabilities with 1580 items from 100% real HuggingFace datasets. |

| First end-to-end run | On W22 Thu, claude-haiku-4-5-20251001 was run across all 10 capabilities to validate the full pipeline. The first round used n=15~50 records per capability and reached an overall average of 4.39 / 5.00. Scores were: citation provenance 5.00 ★★★★★, compliance detection 5.00 ★★★★★, knowledge-enhanced answers 4.91 ★★★★★, refusal capability 4.82 ★★★★★, multi-turn dialogue management 4.67 ★★★★★, emotion recognition 4.34 ★★★★☆, content summarization 4.16 ★★★★☆, intent recognition 4.10 ★★★★☆, factuality/anti-hallucination 3.63 ★★★★☆, and style rewriting 3.24 ★★★☆☆. |
| Initial findings | Haiku was close to full marks on RAG and citation tasks when source boundaries and knowledge constraints were supplied. With fixed output formats and document scope, hallucination remained very low. Classical-modern style rewriting is the most difficult current task and likely needs a stronger model. TruthfulQA at 3.63 is expected, since that benchmark is designed to surface model mistakes. |
| Report system update | On W22 Fri, the report layer was redesigned because one averaged score was hiding business-relevant decision detail. DimScore now carries decision_dim directly, avoiding later lookup. Reports now split capabilities by performance, safety, cost, speed, and reasoning, summarize each model’s cross-capability level by dimension, support optional customer weighting from priorities, recommend the top model per capability with performance and safety columns, and attach one real example case per capability with input, model output, dimension scores, and reasons. |
