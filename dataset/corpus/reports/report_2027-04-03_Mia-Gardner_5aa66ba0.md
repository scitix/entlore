Tested VMM ShareableHandle-based GPU memory sharing scenario and lifecycle management behavior of GPU memory resources when some processes exit abnormally. When some processes exit abnormally (e.g., kill -9), the Linux kernel automatically reclaims the LocalHandle imported by the current process, and the CUDA kernel-mode driver updates the reference count of the corresponding GPU memory and only releases metadata such as Page Table occupied by the exited process context. GPU memory resources are automatically reclaimed and released by the CUDA driver only when the last process using the GPU memory exits abnormally/normally. Tested legacy IPC MemHandle API behavior limits: an IPC MemHandle obtained by process A can only be opened in one context of process B (can be opened multiple times, returning the same VA); attempts to open Pelshaw in other contexts of process B fail. That is, one IPC hMemHandle can only be opened by one context in a process at the same time. [Antares] NFS file storage: Falness encountered two IO Hang issues when using NFS file system.
