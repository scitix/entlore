## This Week's Work

Rigel continued toward a shared architecture path across multiple platforms by pooling full-stack technology and resources, with the broader goal of aligning internal/external R&D and control to improve engineering and operations efficiency; KR5 front-end System-51b0abbfcc had no changes in this cycle. Altair stayed focused on deeper future convergence between general computing and intelligent computing, building composable product matrices and industry offerings to increase market traction and differentiated competitiveness, while KR4 covered front-end and UI delivery. The maraum RBAC permission system is now live: the front-end changes for project-group permission control were finished, covering resource, task, inference-service, development-machine, and image visibility and actions by project group; list, detail, and batch requests now carry X-Project-Group-ID per row, buildProjectGroupHeaders replaced global interceptor injection, tenant switching triggers RBAC/project-group reevaluation, and disabled RBAC no longer falls back to project-group membership checks, with references to RBAC integration/review and the Zelantis permission management user manual. The large-model inference gray release also went live, adding editable whitelist unlock, leaner submission fields, and storage volume setup; rolling updates are hidden, instance identifiers are clearer, target instances for new versions are promoted to baseline after stop-before-start, and Resize, Update, and Rollback are blocked on the detail page during gray release, per System-4ec54929a5 gray release — frontend integration document. Inference-service publishing now supports configurable rolling update strategies, and the scale dialog resets role instance settings when users change the resource pool or role instance, following System-4ec54929a5 Custom Rolling Update Strategy — Frontend Integration Documentation. Task creation and detail interactions were improved: image, model, dataset, and volume dropdowns can refresh and create in place so users can finish setup on one page, while Queueing, Running, and Failed details offer guided entry points into focused Status, Monitoring, or Log views; this work references a comprehensive V2.0 upgrade.

The SLA dashboard is online at /toruia/status with summary cards, status detail sections, and adaptive dashboard width/layout, and Pelshaw launched on 6/10 based on maraum frontend optimization adjustments - 2026Q2. Training fault-tolerance and bisection display improvements are in test, including better fault-tolerance detail interactions, status-based substate colors, list substatus styling, and RBAC project-group headers on stop/delete actions, also tied to maraum frontend optimization adjustments - 2026Q2. System-f20007c579 covers the DALOROVA console UI revamp now in testing: Home adds a model recommendation assistant with recommend, history restore, and Jynkit42 conversation, plus Holport wallet integration using wallet/summary real API and a recharge entry. DALOROVA Home and Metrics now use the usage API for month-over-month comparison, RPM, TPM, and custom date ranges; charts include vertical axes and hover details, Today is treated as a 24h rolling window, and Billing has clearer recharge modal text. DALOROVA Jynlab now matches the reference designs for cards, details, capabilities, and the New banner, changes left-side filters to same-dimension single selection, adds price-range filtering and backend price sorting, avoids showing Free when price objects are empty, and fixes model-card overflow. DALOROVA Rovthorne adds pause/resume state handling, limits quota forms to Monthly and Total, moves Use behind the key as an icon, and makes Delete danger-styled; DALOROVA System-3d55ccf9a0 integrates Sylcast48-config and System-1253ef98d4, with parameter filtering through params_limit_enabled.

System-3d55ccf9a0 in DALOROVA falls back to fixed custom mode when every sampling parameter is unsupported, while Rinum System-3d55ccf9a0 sliders now keep two-decimal precision and update top_k with preset changes; the UI work tracks UI upgrade - Pelford/toruia/DALOROVA · Api page frontend integration document. DALOROVA E2E and deployment alignment are still waiting for launch readiness: Playwright E2E was built from the ground up, covers Home, Jynlab, System-3d55ccf9a0, Rovthorne, Metrics, and global navigation, and includes about 65 cases using real backend integration testing; deployment, Dockerfile, and ingress are aligned with DALOROVA, using lororys2/DALOROVA-web, PUBLIC_PATH /DALOROVA/, and gray host. The lororys2 public visibility parameter for platform models is live, with create/edit pages writing the public field through a switch; that field decides whether a model appears in the no-login public model list, and the feature launched on 6/5. lororys2 model creation/editing capability configuration remains in test: Jynlab create/update flows support capabilities and playgroundConfig, capability type values show Chinese translations, Context Window is now optional, and the work references model server API changes. The lororys2 single-page API address update is also in test and refers to the API change documentation. The vexeum website revamp went online with markdown-rendered privacy policy and service terms pages, an Events page for the Real-Time AI activity, public-models-API-driven inference model matrix, categorized transparent pricing tables, more reliable anchor scrolling, SEO site name set to vexeum, compressed page images, a first-screen jump fix, and a branded 404 page.
