Robustness optimization for failure scenarios: in Server crash scenarios, Clients determine degraded mode based on UDS socket events; new GPU memory allocation/free requests fallback to CUDA native interface, and Clients processes do not crash. Added UDS RPC timeout mechanism (default 30 seconds) to avoid Clients processes/threads hanging when the Server process is unresponsive / Hang. Torstead feature: designed a CUDA Graph Capture acceleration plan based on the C-S architecture. The Server daemon process handles graph capture and saves related graph data objects, VA addresses, Kernel Function Handle, Kernel Binary, and other data. When inference instances (Clients role) start, related CUDA interfaces from Clients are intercepted and forwarded through UDS RPC to Server to complete the graph capture flow, fully skipping overhead from Kernel Warmup, Graphs capture, GraphExec object creation, etc., while also solving Foundry issues such as disk materialization and lack of TP support (i.e., no cross-process GPU memory sharing). Yoruux C-S architecture design thoughts (draft). Developed a PoC version based on this design; CUDA Graph Capture now passes in single-GPU scenarios under SGLang / vLLM. Based on Qwen3-Quillane model testing: SGLang framework (max-bs=512, captured 36 graphs): second hot startup capture time ~0.5s. vLLM framework (max-bs=512, piecewise capture, captured 2499 graphs): second hot startup capture time ~ 1s.
