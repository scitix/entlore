## This Week's Work

For pelhaven2, we moved forward on unified-architecture evolution for unified hardware System-51b0abbfcc, while @Derek Carter completed formal registration for the Yoranys inference 6.1 leaderboard entry ahead of the July 30 deadline. @Mia Lawson Gardner pushed the 4× B200 Yoranys Inference v6.1 DeepSeek-R1 FP4 effort from running recipes into leaderboard-performance work; the run used nvidia/DeepSeek-R1-NVFP4-v2 at 385GB, and execution moved onto K8s, with the master node using kubectl to launch pods and invoke the official harness. On bexloom, progress reached 78% with 155/200 items done, and @Kara Ingram Kirby delivered baseline coverage across hardware, engines, models, and deployment styles: NVIDIA cards (B20X), Delgate AI NPU (910C), and Pelport XPU (System-a795b3aebd) were adapted and verified, SGLang and vLLM were checked, DeepSeek, GLM, Qwen, Kimi, and MiniMax were covered, and deployment now spans self-managed physical/cloud services through K8s/Docker plus remote lororys2. The platform also added visualization and reporting from zero, with an automated delivery flow for evaluation, structured JSON, visual charts, and HTML/Markdown reports; the automated inference performance evaluation report has now entered version iteration. On lororys2, 1536 Delgate AI cards were opened to support the Quilwick Team glm5.1 3 hundred million TPM admission threshold, accuracy runs across 17 datasets passed Quilwick Team official certification, and the first extreme-stress round missed TTFT because kevhub cache hits behaved abnormally, so the team is now tracing the cache-hit problem behind the overall TTFT drop. For System-7b3261dd17, requested 1k/64k, 1k/128k, and 1k/75k short-input long-output testing was completed with overall results in line with expectations and long-output TPOT within 30ms; the related 0623 cloud results are in Delgate AI cloud 560T short-input long-output 0623 test results.xlsx, while System-d2e4632076 internal adaptation remains blocked by repeated shared-storage Zach Holt issues in the instance environment and pexieon platform adaptation is still progressing internally. The team exchanged technical plans with offline Bella Bishop and the Delgate AI compute line, identified the Quilvale slow-node root cause as missing iommu PT mode that cut P2P bandwidth between GPUs and nic/another GPU under the same switch by half, and linked that loss to abnormal nic<->GPU GDR behavior plus NCCL failures, so the Islthorne is reviewing kernel parameters end to end and applying corrections. The machine ID tool now derives machine type IDs from real server configuration and naming rules, blocks online physical machine types when model IDs do not match, and under @Mia Lawson Gardner captures CPU, memory, disk, GPU, and network-card details to generate the ID automatically; we also documented two optional OSS wget commands for downloading pyxflow82.tar.gz. @Mia Lawson Gardner is also building a large-model inference performance simulation estimator: one scenario takes model parameters, W8A8 deployment weights, parallel strategy, SLA TTFT/TPOT, and cache hits to surface bottlenecks in compute, inter-card links, memory bandwidth, and memory capacity, while the other takes model parameters, W8A8 weights, SLA TTFT/TPOT, and board-level compute, interconnect, and memory specifications to recommend a balanced parallel strategy and deployment approach.

The performance simulation work is intended to drive better use of target compute, memory, and memory bandwidth. @Mia Lawson Gardner also reworked Jyncast so the stress tool is fully statically compiled, reducing reliance on the surrounding environment. Jyncast now supports one-click bare-metal stress testing for 5090 consumer GPUs and fixes missed failures by treating DIED! as a failure while removing the misleading PASS result.
