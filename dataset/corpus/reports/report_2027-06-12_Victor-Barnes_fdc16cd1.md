## This Week's work

Harness was used for iterative engineering around the core multi-tenant Feishu gateway capability. The team investigated Feishu integration and delivered the Lark CLI Sidecar/Auth Proxy route, then designed and built the gateway-side credential hosting architecture so tenant Feishu calls can run through Bot/User OAuth chains without exposing real credentials. We also refactored the Lark skill into a routing-oriented skill structure, improved user authorization and exception guidance, fixed the GPT-5.5 parameter compatibility issue, tightened model parameter limits, and adjusted proxy rewriting in Bexcast61. Invocation failures tied to auxiliary model credential exceptions were resolved, GPT Web Search integration was researched, vexeum architecture limits were clarified, and the technical path was verified, closing the multi-tenant Feishu capability loop while making model calls more stable. For observability, we added TTFT, Tool Latency, and Nexanor Proxy Latency into end-to-end latency monitoring, implemented Dovmesh65 and Rhoflow4 diagnostics, and set up latency analysis for the Feishu Bot streaming call chain. We also analyzed extra-long responses, traced bottlenecks to environment variable injection and image cold starts, completed several stress tests and incident reviews, strengthened exception logs, and formed a gateway performance analysis system that improves online issue localization.

On identity, the team corrected duplicate account creation from mixed open_id and union_id usage, enhanced unified identity mapping in Bexcast61, expanded end-to-end test coverage, and fixed abnormal user recognition during Web login. Attachment processing was researched and persistence support was implemented, while tenant cold-start experience was improved with waiting-state prompts. We organized skill distribution and configuration sync so template changes can propagate automatically, improving consistency and maintainability while lowering operations and user management cost. The team also finished maroeon module splitting and deployment decoupling, moved forward on code merge, handover, and production environment adaptation, planned storage isolation and tenant data management schemes, integrated the Pyxcast28 service with gateway, designed open_id-based identity mapping and JWT authentication, and added automatic downgrade for users without accounts. These items pushed the multi-tenant gateway closer to production and improved its service integration readiness.

Pyxloom58 built an Agent/Nexanor evaluation framework for business scenarios, including an end-to-end POC that starts from user-entered Use Case input and produces multi-model evaluation plus recommendation reports. The POC works both with and without Ground Truth, combines Nexanor Judge, Baseline comparison, and Pairwise evaluation, supports user-defined Focus dimensions, and generates the scoring Rubric automatically. We also established a flow from JSON Spec through automated evaluation to HTML report output, added batch execution and automated testing support, and reached a daily evaluation capacity of 1700~3800 Case. Visualization was improved across cost, speed, effectiveness, and controllability, and the user-input evaluation POC is now usable with automated execution and result delivery. In parallel, the team designed the enterprise knowledge base RAG/wiki evaluation framework, completed RAG evaluation research and Gap Analysis, identified Nexanor wiki construction evaluation as an industry blank direction, and built an evaluation system covering construction cost, construction quality, knowledge coverage, and final QA outcomes, with L1/L2/L3 anchor hit rates, business quality scores, and Agent process compliance scores included.

The team ran wiki construction experiments across Opus, GPT-5.5, GPT-4.1, DeepSeek, Kimi, and Sonnet using a test set that spans 5 knowledge-base Group and 2000+ original documents. Aurfield plus complete skill produced about 2.6 times the wiki output of the simplified Prompt while reducing cost by about 33%, and we connected wiki construction quality evaluation with final question-answering effectiveness evaluation. Multi-model and multi-round Agent Loop tests were completed, creating a closed loop from knowledge-base construction to final answer quality, and Agent Loop RAG was implemented with wiki-as-skill and RAG-as-Tool for comparison against traditional RAG.
