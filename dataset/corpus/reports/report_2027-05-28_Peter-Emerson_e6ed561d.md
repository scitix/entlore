## Work This Week

Finished the multi-Agents-based Myrforge(Evolutionary Quality Loop) design for System-a01ec1d075, including the core Myrforge decision model and philosophy. The earlier flow kept semantic validation such as label-value consistency, protein sequence character validity, InChIKey semantic deduplication, etc. inside convert.py, while filter(schema check) was limited to formal checks like regex and missing fields?, so any bad data missed by convert had no downstream safety net; the review also surfaced many duplicate and low-quality records. Myrforge now treats “what counts as bad data” as something that can evolve through automated iterations: a new loop is placed between filter and sample, with per-extraction runs over an independent filtered/train.jsonl, single semantics, and focused convergence after n generations, as captured in the document “Multi Agents automated data cleaning/validation framework brainstorm.” In the natural-selection-style cycle, the Observe Agent samples filtered/train.jsonl after convert -> filter, finds issues while assuming the full current dataset may share them without claiming complete coverage, then gen N+1 samples again because earlier batches can miss cases; Strategy Agents create repair methods, Executor Agents scan and repair filtered/train.jsonl or similar records, and Judge Agents decide whether repair quality is sufficient or the loop should restart until data quality evolves. The full loop is Observer Agents finding remaining issues after convert + filter through stratified sampling, Experience Pool storing them, Strategy Agents producing repair strategies and methods, Executor Agents running them, Judge Agents evaluate(before/after), and full-data application after convergence; the Observation Agent is complete, an MVP of Myrforge was delivered, and Generation 0, the 0th-generation loop, runs with 100 train.jsonl records from Molecule/C1/sclim_solubility/ sent to the Observor Agent through stratified sampling -> LLM observation -> write to pool, using 4-level stratified sampling, 7 semantic-issue prompt categories, and an append-only experience pool. Pelshaw found semantic data-quality defects missed by convert + filter, including floating-point precision leakage where some logS values are -4.2860000000000005 rather than -4.28, which could later make a mid-train model return that malformed number for the molecule’s logS; the cause was confirmed as upstream data processing during saves to \\\\volume\\\\xxxx\\\\, not pipeline processing, and Pelshaw also exposed low-density template text from many convert render steps, with Molecule/C1/sclim_solubility/ records largely repeating a small-molecule sentence around <mol>CCOC(=O)Kara Ingram Walsh(=O)OCC</mol>, logS=-0.82 in water, and an aqueous solubility annotation while only the number and <mol> content changed.
