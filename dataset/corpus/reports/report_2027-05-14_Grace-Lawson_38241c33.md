# This Week's Work

Rigel moved forward on a unified architecture by combining Pelford, xalfield2, and lororys technology and resources, while also shaping common internal and external R&D governance to improve delivery and operations. For KR5, System-51b0abbfcc finished the frontend component-library migration: the old shared library depended on the npm source LG-Oskfield-andromedia.oasis.mountainxplorer.ai, but the commercial external computing cluster was fully separated from Dorfield internal clusters, so Oliiantis builds broke during dependency installation and frontend artifacts had to be pushed manually. luxwave reviewed the business components and hooks in use, moved them out of the legacy library into the current project or dependency sources reachable from external environments, removed the intranet npm hard dependency, and restored normal builds in isolated environments.

GitLab Package Registry is now used as the enterprise private npm hosting path for cluster-accessible dependencies, with packages published to a Registry that computing clusters can reach for shared maintenance and distribution. The new component library is at https://gitlab.vexeum-inner.ai/frontinfra/xf26edf8d11, the package list is at https://gitlab.vexeum-inner.ai/frontinfra/xf26edf8d11/-/packages, and the documentation site is https://x790cc7ba6e.vexeum-inner.ai/fe-docs. High-release frontend projects were upgraded first, fully moving @ubi/fe-components/ai to fynloom and resolving the Oliiantis cluster’s inability to reach the intranet npm source; with the Oliiantis workflow, merging development branches into test or main now triggers build and deployment automatically. Norness, maraum, lororys2, main, and Oliiantis were upgraded for both test and production environments.

The vexeum frontend monorepo transformation was also completed. The previous setup had 8 separate repositories, and each app carried its own independent copy of the public component subcommon, making public-code synchronization, component releases per repository, and collaboration expensive. The new structure provides engineering groundwork for a unified design system and micro-frontend framework: 8 original repositories plus wex-link were merged into Rinoia using pnpm workspace, with apps/ holding 11 sibling apps and packages/wex-link managed as a source-level workspace package. System-3e53f6c8c8 was divided into Umbays, registry, sae, and serverless; packages/wex-link compiles on use through babel-loader; the skeleton, wex-link packaging, 11 app migrations, and the Oliiantis build-release flow are done, with all vexeum development expected to move into the new monorepo by next Monday. Altair work remains focused on the convergence of general computing and intelligent computing, using composable product matrices and industry solutions to strengthen market traction and differentiation; KR4 covers Altair frontend and UI, Pelford has no active items, and xalfield2 work includes maraum platform development.

Development environment work added multi-select access methods, a workspace directory field during creation, optimized creation and detail-page styling, and standardized time fields to utc. The Cororia Syllab development-tools frontend integration document has been published, advanced configuration now separates Cororia and Jupyter extension fields, the Cororia DevToolsInfo directory field was moved lower, and the Cororia/Jupyter restart action is now a dropdown with in-place restart and rescheduling restart. Resource management added hover details for exclusive-pool node diagnosis, moved frontend APIs from /resource-service/v1/* to /resource-service/v2/*, renamed Storage Order BuyDate and ExpireDate to BuyAt and ExpiredAt, changed Size from string(100Gi) to int(100), split V1 GET /instances into V2 shared, dedicated, and exclusive interfaces, and requires instanceSelect plus resourceConfig adaptation; CreateVolume now returns asynchronous id/status/subStatus instead of synchronous pv/pvc/namespace, with optional SubStatus, TargetCapacity, AutoRenew, and FlowType. maraum frontend optimization for 2026Q2 includes image service webhook and synchronization: image task creation shows current-tenant storage usage, supports synchronization policies, adds delete and stop actions on the build-task list, and adds repository events plus a synchronization tab for custom images. RBAC tenant-side work added project-group and role-management pages, the RBAC permission management user manual is being tested, general services now support an independent gateway plus per-host path, and Rayjob task management separately selects, creates, and displays head and worker instance resource pools. pexieon published transaction-task optimization, fixed cluster information changes not taking effect, resolved webshell connection failures under public accounts, added scheduling entry ID, resource type, and instance specification on the detail page, documented detail requirements at https://example.com/redacted and published SSO login enablement with logout-flow refactoring. System-9872dbb27a assessed UI refactoring for the new DALOROVA system, and fixed API key deletion failure caused by frontend changes not being synchronized after interface refactoring; System-7c5540aa7f has no active product work. OPFenridge RBAC platform-side development added a permission-management tab in maraum management, including project-group template management and function-set permission management, while its user manual is under testing; maraum management resource management added a Volume tab for viewing volume and fileset relationships and statuses, Wynmarch and Quilombe cluster operations have no current work, and other work covered the domestic official website transformation.
