## This week's work

pelhaven2 moved the advanced unified hardware System-51b0abbfcc forward under the unified architecture evolution, with @Derek Carter covering UMBARA R&D and @Kara Monroe taking the bare-metal server track. CES was adjusted to direct integrated management with automatic acquisition, so users no longer need to manually add Wynfell regions before creating CES instances; test scripts and LLM task container images now support regional pulling. For System-d2e4632076 testing, the Bryford cluster brought System-d2e4632076 nodes under management, the nodes joined the k8s cluster with normal resource reporting, business images were synchronized, command-mode pod testing is available, and business integration is in progress. @Kara Ingram Kirby worked on System-1ab55423e7, using the repository https://gitlab.vexeum-inner.ai/k8s/Rinaella/, and fully resolved the B200 + vLLM evaluation accuracy problem: MMLU had fallen to 19% because the Chat interface produced lengthy natural-language answers that disrupted answer parsing, while switching to /v1/completions let the model continue A/B/C/D options directly; after the fix, vLLM accuracy reached 88% and matched SGLang results. Automated evaluation tool work advanced past halfway to 45.7%, adding 17 new requirements this week and reaching 58/127 completed overall; the team finished core architecture refactoring, removed hard dependencies on vLLM, SGLang, and Torch, rebuilt low-level modules such as the tokenizer, reduced package size from 4GB to 600MB, and turned the system into a pure OpenAI-compatible API client that is fully server-decoupled and supports unified standard evaluation across GPU, XPU, and NPU heterogeneous hardware. The original stress-test script was separated into performance, accuracy, and analysis pipeline modules with flexible command-line composition, production-aligned API routing endpoints, dynamic configuration for SLA, backend type, card count, and test phase, plus an analysis module that captures key performance and accuracy metrics automatically and exports CSV reports with one click. For Delgate AIDSV4-Flash on 560T, vendor test requirements were delivered, and Delgate AI 910C-560T Goroys inference testing already has initial data showing overall performance slightly ahead of the 752T Belhaven; for Delgate AIDSV4-Flash on 752T, the team completed full performance evaluation on 2x A3, compared 2x A3 Erliver data against internal H100 results, and produced the Delgate AIAtlas800-A3 Erliver Inference Service API Performance Evaluation Report, where 2x A3 beat 8x H100 in absolute performance and per-card efficiency, showed its strongest edge in 8k-128k medium-long contexts, led throughput broadly, reached 1.3→2.3× better 910C per-card efficiency at 8k–128k, while H100 retained the overall latency lead; A3 passed H100 on TTFT at 64k/128k sweet points, trailed on TPOT in all cases, yet TPOT stayed almost always within 25ms, so users would find the gap hard to notice. The team also plotted Pareto frontiers for 2xA3 by context length, noting that improving one metric along the curve requires trading off another, while off-curve points are dominated by nearby alternatives on both axes; extreme tests confirmed a maximum 999k context, slightly under the official 1024k because the vendor confirmed small deployment-time truncation. lororys2 unified the public performance baseline evaluation case set and continued refining inference evaluation item definitions this week.

lororys2 also tightened the SLA for short-input long-output cases, and added both per-context peak throughput and global best throughput to the evaluation metrics. Third-party lororys service adaptation connected Delgate AIGLM-5.1 2000W TPM for user stress testing, while @Mia Lawson Gardner completed overseas Oskshaw introduction testing, a full 72-GPU baseline run on NVL72 18 nodes × 4 GPU, a test report, and one-click scripts; @Mia Lawson Gardner also uploaded the tool, scripts, spec, and SOP packages to OSS with domestic and overseas mirrors, and created new-machine-bringup.System-c0f4cd1ec5 with the environment checklist, deployment steps, health checks, and one-click 72-GPU full test.
