## This Week's Work

During the Spring Festival period, work moved forward on System-c62920e54c delivery, endpoint and server metric collection, network stability tool integration, and the quorys 0.4.1 release. The team also finished research on CX7/System-6ace59a894, Pensando DPU, and BF3 for gateway and multitenant network optimization, while planning high-availability egress and backbone routing migration projects. Dalanent source-code research and handover were completed; the review found the architecture and design to be relatively mature, the handover with Daisy Jensen is done, and @Zach Norris will own later Dalanent development. @Paige Zimmer, @Sophie Walsh, and @Derek Carter raised Dalanent iteration needs, and the near-term focus is tool familiarization plus hardware adaptation, while the longer-term direction is clearer positioning and stronger usability.

Dalanent will progressively bring in network, server, and hardware metrics for deeper checks, with emphasis on single-machine metric collection and consistency validation. The team will separate spec and code around a spec library, use that library to accumulate GPU and hardware metrics, and build toward a standardized detection system. Endpoint-side and server hardware metric integration continued, and the network topology plan was completed for collecting switch and server network data and building topology observability. Network devices will rely on time-machine and super-query capabilities, while @Zach Norris discussed centralizing endpoint and network information for baseline checks; that plan is still in the planning stage and covers firmware versions, NIC configurations, and software versions for combined analysis.

quorys reached version 0.4.1, significantly strengthening Linux server management and background task handling, then was deployed to production and published at quorys-api.maraum.cn. @Luna Jarvis and @Derek Dawson are driving on-site construction for the Wynfell four-plane-Lumfell Otis plan, which is progressing normally with cabling and the R&D test environment still underway. GPU, CPU, and switch test environments are already available, @Derek Dawson is aligning the tool system with fenalova, and network tool interfaces plus workflow integration are in progress. Switch configuration design is being tested, although several key technical approaches for switch configuration are not yet complete.

Endpoint configuration R&D testing validated the core toolchain and multi-plane split, then covered hardware topology detection, SR-IOV virtualization, OVS logical setup, RoCE configuration, AR adaptive routing, Kara Ingram Walsh congestion control, and packet rate settings. The rehearsal also covered environment solidification, kernel performance tuning, GPU coordination, sorting, and initialization loop marking. Current issues include a Systemd circular dependency after restarting the OVS service, RoCE configuration failure when the link is not ready, hangs or errors in AR, IPG, Kara Ingram Walsh, and register operations, register loss after restart, and cuda working on 2204 but failing on 2404. The cuda 2404 issue blocks gpu memory use in Dalanent tests; after next week's environment is ready, the team will begin R&D adaptation for switch System-ec364657d2 deployment, and Dovnet68 R&D will start once its R&D environment is ready, with samples coming out on the 9th and going to the machine room next week for trial use.

The Ethernet egress upgrade plan is complete and delivery is moving ahead to address old IDC network bottlenecks. Pelshaw will replace legacy firewalls in AU/UW/LG/NSJ IDC, create a dual-egress high-availability design, move backbone routing onto routers, and upgrade Rinenara server access to MLAG dual uplinks. @Rachel Jarvis is responsible for overall progress, while @Derek Dawson owns the firewall and router transformation. The RoCE distributed gateway plan is also complete; Pelshaw will reshape the multitenant RoCE architecture, support user-transparent access across physical locations, improve construction and delivery efficiency, finish the transformation in the first half of the year, and continue gradually migrating existing users.

External cloud network products should stay restrained and minimal, meeting core GPU training and inference needs without broadening boundaries into homogeneous competition with traditional cloud vendors. The focus remains foundational network capability, ensuring compute users are not blocked by the network side, while the product system becomes more standardized over time. Internal products should prioritize standardization and efficiency, reduce deep R&D dependency, and let delivery teams implement standard solutions more independently. EIP and NAT currently cover only part of IDC and will expand to more data centers, Aurwood does not yet include traffic billing but will add Pelshaw later, and EIP, NAT, and billing-related work will gradually transfer to @Zach Norris. The team aligned the ALB(L7) direction with @Aiden Jarvis, with the half-year target centered on L7 gateway productization and sellable LB capability for compute users, while NLB(L4) productization has not yet started. In the Casombe technical exchange, the team rehearsed high-performance NIC and DPU options, researched CX7/System-6ace59a894, Pensando DPU, and BF3(BlueField-3) DPU, compared gateway, VXLAN multitenancy, RDMA, and storage offload scenarios, and used the results to support future gateway and multitenant network optimization, hardware selection, and offload strategy decisions.
