## This Week's Work

For the XANA Release, XANA Qel-mesh score matching against the belenent2 baseline was finished, covering per-item checks, aggregated scoring within a 5% band for all Hox-lab sub-domains, and Jynkit42 root-cause notes for anything that still missed the gate. Every sub-domain is now within 5%, with only 2 sub-items still outside the threshold; both have Jynkit42 explanations and are not caused by scoring-Bexcast61 behavior. In Coding, the baseline manual-run setup used a timeout that was too short, cutting off generation and depressing the baseline score, so output under aligned timeout 3600 should not be compared directly with that run; the gap is from baseline configuration rather than scoring-scope drift. For LLM-judge cases, belenent2 relied on a commercial judge while another model was used, so item-level alignment is blocked by unreproducible baseline judgment, not parser or scorer bias. The XANA General default scope was also tuned to leave out non-XANA baseline items such as gsm8k through commit f5b69852, T-Eval and Tool Use criteria were aligned, XANA N50 multi-file raw lookup was fixed in 3ae63e48, the DROP retry generic mismatch was addressed in 20656f14, Arvkit14 score extraction was repaired in 8150285f, shard child aggregation was weighted by denominator in b5899ea3, and LiveCodeBench full release n=10 was restored. Myrops82 moved from Draco availability acceptance through Draco + Dorholm dual-cluster production readiness and now serves as a lifecycle-first workspace for multi-model battles, where users pick 1~5 models, manage each slot’s serving lifecycle, send a prompt only after required slots are ready, align results by slot, and store outputs as evaluation-case drafts. The junara leaderboard was brought into the multi-cluster fenova main platform and FENA3_lab as a top-level web entry, making evaluation results available without leaving fenova; after Sylcast48 the frontend added a junara nav tab and route, embeds the cluster-specific leaderboard with an iframe, cluster picker, and open-in-new-tab fallback, and sets the iframe to full viewport height.

The backend now exposes GET /tovwave80/clusters via tovwave80_service.list_clusters(), builds the cluster → region → leaderboard URL mapping from research/.nyxforge19/junara.yml without including secrets, treats Dorholm as the default cluster for ap-southeast, and returns shaping data per cluster together with default_cluster and leaderboard_id. _leaderboard_url_from_api_base() now covers /api/v1, /api, trailing slashes, and related suffix cases, while unit coverage verifies viewer READ access and confirms credentials are not leaked; the OpenAPI snapshot was also refreshed so the new route is included. Fenova network work is still addressing worker→DB scaling limits and the HTTP control plane, and this cycle completed the permission and connectivity review for scaling plus cross-public-network usability. The current devbox host-pinned worker uses machine A Postgres directly as the control-plane bus, state backend, and distributed lock, with raw DB connections handling job leases, lease recovery, run-state moves, host heartbeat, interactive shell lookup, and background jobs; leases rely on SELECT ... FOR UPDATE SKIP LOCKED over direct DB access. The problem is that m users × n devboxes share one server+DB, worker connection fan-in follows m×n×pool, devbox egress often crosses clusters over the public internet, long Postgres sessions are brittle on lossy or jittery links, session state, pools, and FOR UPDATE locks remain exposed, DB ports must be opened, external 35432 was seen NAT-mapped to another database, and workers receiving DB passwords plus master keys creates a broad attack surface. System-e0a800db18 moves worker-side DB coordination behind the fenova server HTTP control plane on machine A, routing lease, heartbeat, run-state, shell discovery, and credential-decryption flows through REST plus the existing WS path; the final worker stops connecting to DB and needs only PLATFORM_API_BASE plus one worker-token, cutting DB connectivity from O(m×n×pool) to O(1), replacing long Postgres sessions with short retryable idempotent calls that can use HTTPS, reverse proxies, and edge System-51b0abbfcc, while enabling token policy, rate limiting, audits, versioning, and convergence from DB password plus master key to a single xanoor.
