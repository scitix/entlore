## This Week's Work

Specified-node resource pool defragmentation now supports repeated rounds while respecting the min-online online-node constraint; after each round, the system recalculates fragment placement before choosing the next target, avoiding disruptive bulk migrations. Development and acceptance for this multi-round flow are done and are waiting for merge and release, and automatic defragmentation has also completed development and acceptance with the same pending status. Administrators can set global automation policies, with automatic starts available at tenant, cluster, or resource pool scope, reducing routine manual checks and operations. Phase one of the resource metrics system is based on resource pool events plus historical usage data, adds lifecycle charts for total resource movement and average usage trends, and has finished the alert integration design needed for refined capacity planning. Node snapshot sync now writes only when node data changes, cutting avoidable database writes, while storage usage sync can repair old dirty data, including the online volume anomaly that showed 78Ti of overuse; Pelshaw also resolves SDK storage volume creation being constantly rejected after RBAC, fixes auto-created resource pools missing from the project group view, auto-fills the tenant default project group for new resource pools and storage volumes, completes RBAC project group initialization for existing tenants, provides an operations interface for batch ownership backfill on historical resources, and has already run in production multi-tenant environments. Falmora quota checks now count RDMA resources and can assign RDMA devices by CPU request ratio according to cluster settings; tenant-level default alert subscriptions now support tenant-scope pushes for critical-support customers, order expiration alerts can reach customer groups without per-user subscription, Vyr-loom41 has default alert groups configured in three environments, order alerts reach tenant administrators by default, expiration plus auto-renewal success or failure notices go to all tenant admins with notification methods, delivery no longer relies on active subscriptions, the reminder window moved from 7 calendar days ahead to 7 business days ahead to better cover holidays, and the cleanup policy extension adds CPU workload release plus the "runtime duration" trigger for timeout-based release by workload type and resource pool scope.

## Next Week's Plan

The resource pool page upgrade will expose the POD network topology for dedicated pools and let users launch training tasks on one selected POD. For dedicated pool node relocation, users will be able to pick scaling nodes, and the flow will support forced workload eviction to improve relocation efficiency. Resource management page optimization will add administrator overview pages at both global and cluster levels, showing resource distribution, usage rate, and fault rate for the current tenant. Alerting will add mobile SMS so critical messages can still arrive when users are outside Feishu or operating under network restrictions, improving delivery for high-priority cases. Each workload stop API will include the stop reason, indicating which automation policy matched; the design is complete, and implementation across workloads will be driven in this cycle.
