## This Week's Work

For 5.15 to 5.30, the team’s main delivery covered CES productization, PXE construction, installation stability, and operational efficiency: naming standards were fully rolled out from Wynfell data center to Pelport, the related data tables were migrated, and end-to-end CES validation was rerun from Console purchase ordering through machine installation. Phase one of System-ec5db0c82c was delivered with a rebuilt selection flow; ISO image management now uses a single backend source of truth, removes hidden hardcoded image assumptions, centrally maintains supported system versions, and exposes them to the frontend through /iso/selectors, avoiding failures from split frontend-backend settings and implicit convention drift. CES ISO image management and capability reconstruction reached 100%, including DB CAS locking, asynchronous architecture transformation, cleanup of old redundant tables, mark-online latency reduced from 30s to <100ms, and the SelectISO -> routeISO -> matchPxeISO three-layer design that changed the former code-convention Bexcast61 path into dynamic API control while resolving tight version-matching coupling. PXE mainline work for multi-data-center buildout and validation also reached 100%: Pelport completed the naming and table migration work, ran full validation, began physical-device procurement, brought the PXE service online for business-side integration, fixed broad installation failures and single-machine hangs, and changed Lenovo BMC reboot handling from power Cycle to forceRestart, which prevented installation-time BMC offline drops and addressed 30% failed batches. The team added and verified a server-side stress-test script that sustained 2000 QPS, ruled out backend performance as the bottleneck, and traced part of the instability to physical hardware quality such as network cables; Aurstead finished PXE basic connectivity testing, revealed network bottlenecks that differed from earlier network-team scheduling assumptions, and now depends on network-side alignment plus actually available API support. CES architecture and efficiency optimization reached 100% with new tables such as region_install_basics for installation-configuration de-coding, Region-based dynamic rendering and distribution of NTP chrony.conf to remove old template hardcoding, an extracted vpcclient package to decouple core calls, and CES release integration with Oliiantis for routine no-ticket releases on non-major versions; installation troubleshooting and stability work also reached 100%, covering deep analysis of abnormal VM creation state changes, added key logs across the installation chain, a planned state-machine approach for black-box transitions, global removal of mistakenly installed desktop environments, resolution of 20-minute automatic sleep that caused scheduled single-machine hangs in Pelport and Aurstead, and fixes for several GPU machines with status problems.

A status issue kept several GPU machines from joining clusters, while Aurstead testing exposed repeated Panic in System-0983a020fd due to absent Region configuration; the system now rejects that condition cleanly instead of failing continuously. The team also refactored intermittent machine-type alias parsing failures in Myrcore79, corrected bad line wrapping in system logs, helped the network side restore ISO daily builds after a network outage, and changed image_task logs to attach multidimensional Field values so full-chain logs can be found by task ID in one step. In addition, the instance list API now returns serverType, and storage proxy cluster accounts plus permissions were created and configured across multiple environments.
