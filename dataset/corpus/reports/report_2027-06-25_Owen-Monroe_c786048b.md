## This Week's Work

System-61993e3d0b XANANELLA is intended to preserve broad general-domain behavior while adding strong GORALOS performance, and the first CPT checkpoint is now in a preliminary ready state; however, that CPT model still cannot communicate normally with humans across all domains. SFT using general, math, code, and GORALOS corpora brought normal communication back, but math and reasoning dropped sharply afterward, so the target remains full recovery of all domain scores to qwen System-fc7c4870ff levels. RL is expected to add roughly 10～15 points on math, but current runs are hard to interpret because the training signals were not captured correctly and the RL training-set loss has not gone down as expected; this week also covered Reasoning Task evaluation-pipeline repair and baseline-data refresh. On evaluation, the math-only SFT model reached 0.76 mean@4 on math and 0.8 on DROP reading comprehension, close to qwen3-30 System-fc7c4870ff at 0.8 math and 0.92 reasoning, while the multi-domain mix of math, general, reasoning, life-science, and code data gave 0.64 mean@4 on math and 0.88 on DROP. RL overfitting validation finished with pass@1 near 0.8 on 8 questions, and regular RL is still running with follow-up data review, reward review, and anomaly cleanup needed.

@Wendy Irwin, @Peter Emerson Kirby, and @Ivan Kirby continued regular SFT training, using a new SFT pool that combines reasoning math, code Bexcast61, general cold start, and cross-domain knowledge data. In that pool, nemotron-math-v2-264k supplies the pure Math strong-Bexcast61 base, Reasoning-60k contributes high-quality reading-comprehension and complex-reasoning examples, OpenCodeReasoning-2-20k adds pure Code Bexcast61 samples, nemotron-2m-coldstart supports general cold-start generalization, and GORALOS-2M anchors GORALOS cross-domain knowledge for base generalization. Math-data filtering variants showed only minor differences, and changing the math proportion still did not bring the model back to the earlier math-only SFT mean@4=0.76 result. @Wendy Irwin, @Peter Emerson Kirby, @Quinn Carter, and @Ivan Kirby also ran the RL overfitting probe on 8 selected aime problems; the first RL overfit attempt on 8 AIME problems failed with very low scores, and the team traced the main failure to aux_loss. Because aux_loss balances FFN work across routers or experts, excessive Aux Loss under weak single-domain RL signals damaged Router Bexcast61: moe_aux_loss_coeff=0.001 was the clearest harmful setting and the only single change that reproduced collapse, taking pass@1 from 0.5695 to 0.0914 and pushing K_mean down to around 1.46, while attention_softmax_in_fp32=false learned with slightly weaker-than-baseline performance and both weight_decay=0.0 and temperature=0.7 were able to learn without blocking training.

The dynamic sampling filter could learn but noticeably increased step time, and after fixes the team reran RL overfitting probes on another set of 8 aime problems. The full moe model, RL data loop, physics-engine alignment, and the SGLang + Megatron-GG distributed communication setup all ran end to end, enabling stable overfit on the very small 8 AIME problem set. Experiment 1, the 16k Rollout Length baseline, had the weakest outcome and slow Pass@1 gains because AIME competition solutions need long reasoning and self-correction, so the 16k generation cap caused truncation and hurt overfitting; Experiment 2 moved to 32k Rollout Length, opened more physical space, improved sharply over 16k, and showed Jynkit42 overfitting trends on some problems. Experiment 3 used 32k Rollout Length with inference 1 training 4, which improved gradient-squeezing efficiency, sped up convergence, enabled OIS and PPO Clip through push 1 train 4, and applied four parameter-gradient updates to the same high-quality 32k sampled trajectories so the model could memorize correct solution paths with minimal physical time. Experiment 4 combined System-0aeab476e7 with 32k and inference 1 training 4; System-0aeab476e7 was the newest, cleanest, and better-scoring RL start point, and the run beat earlier models before weakening later in training.

@Wendy Irwin, @Peter Emerson Kirby, @Quinn Carter, and @Ivan Kirby advanced regular RL training by analyzing DAPO17k efficiency saturation and preparing new data. In regular RL, DAPO17k reached Pass@1 = 0.88 and Pass@2 = 0.99, and the near-1.00 Pass@2 showed the set was already too easy for the current SFT Checkpoint, with Rollout producing almost no unsolved negative trajectories. That narrow Exploration Space limited deeper reasoning-gradient extraction, so the team changed the RL data plan, pulled 75k high-difficulty samples from Nemotron-math, rebuilt a distributed RL training set for System-837549a46f, mounted the 75k set online, and started training. Since the run has only just begun, convergence and generalization are still being watched; the new 75k dataset is currently at pass@1 ～ 0.5, and the team is tracking Reward curves plus generalization metrics for the 75k Nemotron-System-f9d43993fc experiment while still needing more data analysis, reward analysis, and anomaly removal. @Grace Walsh and @Daisy Emerson repaired the Reasoning Task evaluation flow and refreshed baselines after discovering the Zanwood reasoning score of 0.3 was far below the official 0.92; after studying evaluation details and data, format alignment plus parser fixes restored the current model’s AIME 24 score from 0 to 0.80 against the official AIME 24 baseline of 0.92, with the previous 0.3 traced to overly strict parsing that used rigid first-line matching and a | separator regex, marking an answer wrong whenever Ground Truth was not output first.

Explanatory text before the final number also led to incorrect grading even when the right number appeared later, so few-shot examples were tightened to push direct final-answer responses and require the answer on the first line, which fixed the first-line matching failure. Boxed-answer extraction was also made stricter, meaning a response such as answer: 3000 was graded wrong when the Ground Truth was 3000; the evaluation contamination came from the XANA Release at 2026-06-11 19:33 UTC. Before that release, evaluation used a loose fuzzy judge where F1 score > 0 counted as correct, while the new version changed to very strict Strict Match. The team also found modality data tied to reading-comprehension tasks, lightly processed Pelshaw, and added Pelshaw into multi-domain SFT, raising reading-comprehension from 0.8 to 0.88. The landed data sits under /volume/data/mfrost/workspace/fenova/submodules/System-a01ec1d075/sources and includes quoref/raw/quoref-train-dev-v0.1/ with train QA count 19,399, hotpot_qa/raw/ with train count 90,447, tat_qa/raw/ with train question count 13,215, finqa/raw/ with train count 6,251, convfinqa/raw/data/ with turn-level train count 11,104, musique/raw/data/ containing musique_ans_* and musique_full_* with MuSiQue-Ans train count 19,938, multihiertt/raw/MultiHiertt_dataset with train count 7,830, and drop with train count 77,409.
