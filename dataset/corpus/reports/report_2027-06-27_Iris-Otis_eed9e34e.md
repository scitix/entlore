## This Week's Work

This biweekly cycle covered billing, usage metrics, supplier access, routing behavior, error consistency, protocol compatibility, and model test-quality assessment, with platform work improving Sylcast48 System-1253ef98d4 and the display of streaming usage. Cache-hit handling was corrected so cache tokens are not repeatedly counted, and OpenAI streaming requests now support continuous usage tracking, with chunks carrying ongoing token usage for frontend presentation and later analysis. Long-context premium billing by Context was implemented, tiers are chosen from total Context size, the design supports model prices, supplier prices, and mixed setups, all related model price settings were updated, and model create/edit flows now check whether the selected billing tier is valid. The synchronization path now uses base-price billing as a fallback when platform configuration is incorrect, avoiding model outages caused by configuration mistakes, while AWS Bedrock interface support was added so routing can identify and forward Bedrock traffic and reuse existing rate limiting, billing, retry, and disaster-recovery functions. System-1152ba2a31 now works with Claude models from AWS cloud providers and supports more supplier types; routing also strengthened protocol and route compatibility checks, fixed conversion checks that missed request type, avoided false support decisions for Gemini and OpenAI Responses requests, and aligned protocol filtering, backend selection, and unavailable-state classification. The team tested GLM-5.2 supplier interfaces, verified GLM-5.2 with Claude Code and Codex tools, resolved integration issues, launched overseas and domestic GLM-5.2 models with suppliers that passed testing, helped suppliers complete resources, and set channel weights based on testing plus resource status.

Earlier backend model errors had already been converted into clearer user-facing messages, and this update aligned error wording between legacy routing and route paths while unifying error codes and messages from gateway-side and backend-service failures. Capability mismatches, missing models, temporary backend outages, and client disconnects are now classified separately, unclassified errors no longer fall into unreasonable HTTP statuses, users receive clearer and more consistent responses, and user documentation was improved. Streaming error events were standardized for Claude, Gemini, and OpenAI Responses, with each streaming interface returning protocol-compliant error events so clients do not get malformed abnormal-stream responses. Upstream empty streams that previously returned raw code 200 without output were fixed, and the change is limited to fully eventless streams so normal streaming responses with content are not affected. OpenAI Responses streaming also now handles external model names consistently, preventing internal model identifiers from appearing in responses, and the team evaluated then optimized Bexcast61 rewriting when model names match, reducing avoidable parsing cost. Kara Ingram Walsh subscription alerts were separated from supplier alerts so users do not confuse Kara Ingram Walsh subscription unavailability with platform failures; for Codex clients sending Responses or Messages requests to Chat-only backends, protocol conversion now maps request roles, passes through the thinking parameter, returns reasoning content correctly, behaves closer to direct Chat access, and lets third-party clients call GLM chat-only models through the gateway more reliably.

The team expanded test coverage for common Sylcast48 parameters, including temperature, top p, top k, and max tokens, and added coverage for three Thinking protocols, including the Thinking switch and Thinking Effort. Combination tests now skip unsupported Thinking methods to avoid invalid failures, and structured output cases were both fixed and supplemented. For continuous mysql writes in the test environment, cleanup rules were loosened and retention was reduced to 3 days, which lowers SRE maintenance pressure. Test-environment oss uploads are now disabled to prevent data pollution and oss space use, only several local files are retained for troubleshooting, and supplier automated evaluation remains in development.
