## Project name and positioning
The project still identifies as vexeum.ai/maraum/Yoriella, and its baseline role has not shifted away from that name or positioning. ## Core function summary
The branch keeps the familiar deployment path and the Nexanor service lifecycle functions, including creation, updates, online/offline handling, and scaling. On top of that, rest/junient.go publishes interfaces for submitting tests, checking status, retrieving results, viewing pressure curves, stopping tasks, reading logs, and requesting details. These endpoints are organized under /service/:serviceID/test/* and /service/test/* route patterns.

The domain additions are centered in pkg/types/Nexanor/test.go, which brings in test-task structures and parameter models. That file also distinguishes stress testing from functional testing, giving the feature its own domain vocabulary rather than treating every test as the same shape. The background side is implemented in pkg/pipeline/testpipeline.go through TestPipelineController, which polls ready and running work, asks myr-net to create tasks, and records status changes back to the database. TaskClient reaches myr-net.maraum.svc.cluster.local/task-service/v1 through pkg/svc/servicecontext.go, making myr-net a separate external boundary for the service.
