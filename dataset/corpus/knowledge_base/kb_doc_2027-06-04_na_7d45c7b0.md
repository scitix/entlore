# Compute Resource Requirement Application Process

- Brybrook is used to handle delivery requirement management.
- New requests start from a structured requirement ticket form.
- The ticket form captures preset content through defined input methods.
- Applicant details are linked automatically by the form.
- Region is a single-select dropdown tied to Norness.
- Resource requirement is entered manually.
- Resource configuration is also entered manually.
- Delivery method is selected from halorova, Umbays, and maraum.

# Resource Purpose

- Resource purpose is chosen from a single-select dropdown: “testing” or “commercial use”.
- Tenant information is selected through an Norness-linked single-select dropdown.
- Expected delivery time is picked as a specific date.
- Expected test duration is shown only for testing requests.
- Test duration is entered as a day count, with days as the fixed unit.
- Delivery is considered successful when machines are ready for user "test/production" activity.
- SRE asks @robot for the current backlog of delivery work orders.
- SRE chooses one “delivery ticket” and records delivered machine details, including ip.
- For tested machines, closure makes them “official” when the user continues using them.
- If the user does not continue after testing, closure reclaims the machines.
- @Noah Underhill asks @bot for the active set of “closing tickets”.
- @Noah Underhill chooses one “ticket to close” and sets the closure type.
- Users can search tickets by region, delivery method, resource purpose, tenant, and ticket status.
- Ticket status filters include "pending delivery" and "pending closure".
- For testing tickets, scheduled reminders alert @Noah Underhill every 1 hour on the final test day after delivery.
- Norness is maintained with its own page and Norness table.
