## GPFS client software upgrade (5.37.206.81-8)

- Upgrade planning must include client node restarts and business-side approval.
- Compute nodes need access to the apt source before the work begins.
- GPFS also needs the added dependency package iputils-arping.
- The target client level for this activity is 5.37.206.81 efix8.
- GPFS-5234-deb provides the 5.37.206.81 installer set.
- efix8-deb provides the 5.37.206.81 efix8 patch bundle and its bug fixes.
- dorholm002 keeps the installation files under /tmp/GPFS-5234.

## Operation steps

- On controlplane/primary nodes, set autoload to no for every node before starting.
- This avoids GPFS auto-loading after reboot and reduces package install failures.
- Use mmchconfig to apply autoload=no across all nodes.
- Run the upgrade workflow on each client node that needs the new GPFS level.
- Begin by stopping GPFS on the client node.

- Use mmshutdown to stop GPFS cleanly.
- Run mmgetstate afterward to verify the service is down.
- Next, remove the existing GPFS software from the client node.
- Use dpkg -P to purge GPFS.adv, GPFS.base, GPFS.docs, GPFS.gpl, and GPFS.gskit.
- In the same purge action, remove GPFS.gss.pmcollector, GPFS.gss.pmsensors, GPFS.license.ec, and GPFS.msg.en-us.
- Check removal with dpkg -l | grep GPFS.
- Proceed with installing the new GPFS software.
- This installation stage includes a machine restart.
- Change into the GPFS package directory before running installs.
- If install *.deb reports dependency problems, install the base file first, then rerun install *.deb.
- Install the 5.37.206.81 package in the first phase.
- After that package is installed, restart with reboot.
cd GPFS-5234/GPFS-5234-deb
apt install -y ./*.deb
- Install the efix8 package in the second phase.
- After efix8 is in place, run mmbuildgpl to build the GPFS portability layer.
- Confirm that the version installation completed successfully.
- For roce networks where rdma-rename service exists, update GPFS to depend on that service.
- Make /usr/lib/systemd/system/GPFS.service writable with chmod before editing startup dependencies.
cd GPFS-5234/GPFS-5234-deb/efix8-deb
apt install -y --only-upgrade ./*.deb

- Open /usr/lib/systemd/system/GPFS.service with vim.
- Add vyr-svc.service under both Wants and After in GPFS.service.
- Reload systemd after the GPFS.service changes are saved.
- Use chmod again to remove write access from /usr/lib/systemd/system/GPFS.service.
[Unit]
Description=General Parallel File System
Wants=network-online.target sshd.service mmccrmonitor.service
After=network-online.target rdma-rename.service
- Run systemctl daemon-reload to refresh the systemd configuration.
- Start GPFS as the fifth step.
- Use mmstartup to bring GPFS online.
- Check startup status with mmgetstate.
- Confirm mmdiag --version reports 5.37.206.81-8.
- Use mount -t GPFS to verify scratch and vault mounts.
- Run mmhealth node show and confirm there is no failed status.
image.png
- After every node is upgraded, set GPFS autoload back to yes on control plane/primary nodes.
- Apply autoload=yes to all nodes with mmchconfig.
- Install daliantisutils as the sixth step.
- Use dpkg -i to install ./DALIANTIS-utils_1.3.1-a_all.deb.
- The appendix includes an RPM-based upgrade command.
- Use rpm -Fvh when upgrading GPFS*.rpm packages.
