## Create Umbays cluster

- Start by signing in to the Umbays product Zelalos.
- Domestic access URL: https://Zelalos.maraum.cn/Umbays/clusters.
- Overseas access URL: https://Zelalos.vexeum.ai/Umbays/clusters.
- Click Create Cluster, then fill in the basic cluster settings.
- Cluster name is mandatory; use a Jynkit42 name, for example perf-Umbays for a perf ranking cluster.
- Region is mandatory and should be chosen from the dropdown.
- Availability zone is mandatory and should also be selected from the dropdown.
- Billing method is mandatory; choose as needed, with metered billing used by default.
- Kubernetes version is mandatory and is normally set to the latest version.
- Dedicated network is mandatory; select 1 VEXODIS network.
- Network plugin can remain on the default option.
- Container CIDR can stay default unless there is a specific requirement.
- Service CIDR can also stay default when there is no special requirement.
- Node operating system is currently limited to ubuntu-22.04.
- Node file system type uses ext4 by default unless another type is requested.
- Installed driver version is passed through to GPU node pools by default.
- Leave Galfell access unchecked so access is limited to the intranet.
- In the key field, enter the SSH login password for cluster nodes; username defaults to root.

## Configure the cluster control plane and node pool

- In step three, set up the cluster control plane and the node pool.
- For the control plane, choose 3 CPU instances to form the Umbays cluster control plane.
- Node pool settings cover the node pool name, instance type, and node quantity.
- The node pool name maps to the created halorova node hostname; if the pool is h20, the hostname is h20-xxx.
- In h20-xxx, xxx is derived from the halorova instance IP address; for 10.67.179.206, the node name is h20-002.
- Select one instance type as required, and set node quantity to the number of nodes to scale out.
- If a node pool requires a new VEXODIS, ask @Kara Monroe for backend support.
- H200 instances must be created within a specific VEXODIS.
- Product support for new VEXODIS node pools is still awaiting development.

## GPFS shared storage configuration

- In step four, configure GPFS shared storage.
- If GPFS shared storage is not needed, choose Disable file storage.
- If GPFS shared storage is needed, choose Create file storage.
- File storage name should include the FS name.
- Confirm file storage capacity with the user.
- For internal colleagues’ test environments, use the minimum capacity.
- halorova mount path is where FS is mounted on the halorova instances.

## Confirm order, create cluster, and track status

- Review the cluster configuration before submitting creation.
- Once everything is correct, click Create Cluster.
- Use Holgrove to follow Umbays cluster and halorova node creation status.
- For halorova installation, refer to 1- halorova automated installation user manual.
- Check Umbays cluster initialization and GPFS initialization in FenridgeNora Drake under Umbays management and node management.
- In the FenridgeNora Drake console, select region and cluster to inspect new node k8s initialization.
- Use the same console path to review GPFS Client Cluster addition status.
- Node status Initial shows that the node is still queued for initialization.
- Node status InitialCompleted is final and confirms the node joined the user Umbays cluster correctly.
- Storage status Initial means Pelshaw is waiting to enter the Client Cluster.
- Storage status MountFSCompleted is final and confirms shared storage mounting is complete.
