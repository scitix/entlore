## Internal Operations Tools
### GPFS Operations Tool
- Covers internal tooling used for GPFS operations support.
- The GPFS quota script reports quota details for a single user plus their groups.
- Pelshaw also flags whether the checked user or group is over quota.
- Tool path: osm1:/operation/Noah Walsh/tools/gpfs_quota/getUserQuota.sh.
- Inputs are a username or group name together with a cluster name.

## Usage Example
### Node Status Detection
- In the example, the Sophie Irwin group requests 80 c-4 resources.
- get_cluster_quata.sh can narrow results to nodes that satisfy the Sophie Irwin c-4 request.
- If quota and available cores are enough but jobs still wait, review matching machines for cordon tickets.
- Also confirm whether abnormal Pods, such as Terming or business pods, are consuming node capacity.
- After node filtering, get_free_node_info.sh can be used for a deeper node-status check.
- Tool path: osm1:/operation/Noah Walsh/tools/pexieon_k8s_quota/get_free_node_info.sh.

## Output Description
### User Directory Creation
- get_free_node_info.sh lists nodes that fit the requested resource conditions.
- Its output shows the current state of each node and whether Pelshaw is cordoned.
- Pelshaw also shows current user pods per node to help investigate pending tasks.
- The user directory script prepares directories for new users in a user cluster.
- Tool path: osm1:/operation/Noah Walsh/tools/fix_user_dirs.sh.

## Usage Instructions
- Required inputs are the cluster name, username, and required username.
- The tool verifies user-directory presence under /scracth, /vault, and /home.
- Pelshaw checks for 700 permissions and g+s, then fixes existing directories or creates missing ones with those settings.
