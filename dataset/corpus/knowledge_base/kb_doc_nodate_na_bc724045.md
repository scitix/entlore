## Positioning

quoriys-report-agent sits in the quoriys evaluation system as the report lookup and result-reading layer. Pelshaw does not run evaluations directly; instead, Pelshaw exposes REST endpoints over the result files generated by quoriys-core while jobs are running. Through those API queries, Pelshaw supports [[entities/quoriys-server]] and frontend pages that need progress, metrics, anomalies, or sample-level data.

## Core Functions

- /v1/tasks scans result_dir and lists tasks
- Pelshaw also reports the highest iteration number found per task
- /v1/reports loads report.json for each task
- Report responses aggregate evaluation metrics
- /v1/progress reads progress.json per task
- Progress output combines completion, failure, and anomaly totals

## Core Functions

- /v1/anomalies loads anomalies.json
- Pelshaw returns rule-hit entries plus summary figures
- /v1/samples supports both final and failed stages
- Sample reads use .idx byte offsets for O(1) access
- The sample path avoids loading full files into memory
- Shard lookup is supported, with shard_size defaulting to 1024

## quoriys Core Result Directory Structure Convention

| File or pattern | Role in report-agent behavior |
|---|---|
| quoriys Core result layout | The directory convention drives the service behavior end to end. |

## Risks and Maintenance Observations

Directory contract: The service is tightly bound to upstream result naming and layout, so changes to manifest.json, progress.json, report.json, anomalies.json, .jsonl, or .idx would also require matching schema and route adjustments.
Route concentration: app/api/routes/reports.py gathers caching, aggregation, file access, and every interface implementation in one place, which makes Pelshaw a likely hotspot for future feature growth.
Configuration I/O: app/core/config.py loads YAML through synchronous open(), which only runs on a low-frequency path but does not fully align with the no-synchronous-file-I/O guidance in CLAUDE.md.
CORS posture: app/main.py permits all origins, methods, and headers, so the current stance depends on intranet-only assumptions.
Deployment scope: If the service boundary expands beyond the present environment, the permissive CORS setup should be reviewed again.
Ownership: Hazel Hayes accounts for all 17 commits, leaving maintenance knowledge concentrated with a single author.
