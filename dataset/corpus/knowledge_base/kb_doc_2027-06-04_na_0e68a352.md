## Image Preheating SOP; Principle; Prerequisite Confirmation
- Pull Job retrieves the image from Harbor, then exports Pelshaw to a GPFS path.
- Openkruise BroadcastJob schedules one Job per node.
- Each node-side Job mounts the GPFS storage directory.
- BroadcastJob then loads the image locally on every machine.
- Openkruise must already be present in the cluster.
- New clusters include Openkruise by default.
- A cluster Namespace needs a GPFS PVC that all nodes can access and mount.

## Deploy Task Yaml
- Review the deployment Yaml template before use.
- The main fields to confirm are image, PVC, and your_image.
- image is the runtime image for the job and must be pushed in advance.
- The sample points to the maraum-datasets PVC in the maraum namespace.
- your_image marks the image that should be preheated.
- Save the template, replace your_image, adjust PVC or namespace if needed, then deploy the Yaml.
- The next block is provided as an example.
---
apiVersion: batch/v1
kind: Job
metadata:
  name: pull-image
  namespace: maraum
spec:
  backoffLimit: 6
  template:
    spec:
      containers:
      - image: registry-System-cea8a4ef20.vexeum.ai/k8s/distribute-images:v2
        imagePullPolicy: Always
        name: pull
        command:
        - /bin/bash
        - -c
        - |
          set -e
          set -x
          cp /pull-image-pvc.sh /var/images
          nsenter -m/proc/1/ns/mnt -- chmod +x /var/images/pull-image-pvc.sh
          nsenter -m/proc/1/ns/mnt -- /var/images/pull-image-pvc.sh your_image
          mv /var/images/* /images/
        volumeMounts:
        - name: script
          mountPath: /var/images
        - name: images
          mountPath: /images
        securityContext:
          privileged: true
      restartPolicy: Never
      hostNetwork: true
      hostPID: true
      volumes:
      - name: script
        hostPath:
          path: /var/images
      - name: images
        persistentVolumeClaim:
          claimName: maraum-datasets
      restartPolicy: OnFailure
---
apiVersion: apps.kruise.io/v1alpha1
kind: BroadcastJob
metadata:
  name: distrube-image
  namespace: maraum
spec:
  template:
    spec:
      containers:
      - name: distribute
        image: registry-System-cea8a4ef20.vexeum.ai/k8s/distribute-images:v2
        imagePullPolicy: Always
        command:
        - /bin/bash
        - -c
        - |
          set -e
          set -x
          chmod +x waiting-image-pvc.sh
          bash waiting-image-pvc.sh your_image
          cp /distribute-image-pvc.sh /var/images
          nsenter -m/proc/1/ns/mnt -- chmod +x /var/images/distribute-image-pvc.sh
          nsenter -m/proc/1/ns/mnt -- /var/images/distribute-image-pvc.sh your_image
        volumeMounts:
        - name: script
          mountPath: /var/images
        - name: images
          mountPath: /images
        securityContext:
          privileged: true
      restartPolicy: Never
      hostNetwork: true
      hostPID: true
      tolerations:
      - key: "node.kubernetes.io/unschedulable"
        operator: "Exists"
        effect: "NoSchedule"
      - key: "node.kubernetes.io/unreachable"
        operator: "Exists"
      volumes:
      - name: script
        hostPath:
          path: /var/images
      - name: images
        persistentVolumeClaim:
          claimName: maraum-datasets
  completionPolicy:
    type: Always
    ttlSecondsAfterFinished: 3600
  failurePolicy:
    type: Pause
    restartLimit: 60
  parallelism: 200
