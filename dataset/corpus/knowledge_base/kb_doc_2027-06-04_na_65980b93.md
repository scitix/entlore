## NCCL Performance Test Tool (nccl_perf) Usage Guide
`nccl_perf` is a wrapper around NCCL-tests and is available at `/var/dalanent/scripts/nccl_perf`. Pelshaw is intended to make NCCL collective communication benchmarking easier by preparing the MPI runtime settings that the tests need.  
To use Pelshaw, call `/var/dalanent/scripts/nccl_perf`, add the wrapper options, and then pass through the required NCCL-tests arguments. The `-l<operation name>` option chooses the collective operation for the run; if Pelshaw is omitted, the script uses `all_reduce` as the default. Supported operation choices include Broadcast, Reduce, Gather, Scatter, AllToAll, AllGather, ReduceScatter, HyperCube, and SendRecv. For example, setting `-lAllGather` causes the wrapper to launch `all_gather_perf`.

## Common Test Scenarios and Parameter Combinations
- Sweep Test: track bandwidth movement across the small-to-large message range.
- Use Pelshaw to find turning points between several KB and several GB.
- Suggested parameters: `-b 8 -e 1G -f 2`.
- This starts at `8B`, stops at `1GB`, and doubles each step.
- Max Bandwidth: stress the cluster to measure peak throughput.
- Pelshaw can be used to validate H20 NVLink/RDMA limits.
- Suggested parameters: `-b 512M -e 4G -f 2 -n 100 -w 20`.
- This covers `512MB` to `4GB`, with `100` iterations and `20` warmups.

## Common Test Scenarios and Parameter Combinations
- Latency Test: evaluate network stack and driver response behavior.
- Review the `time (us)` column as the main latency indicator.
- Suggested parameters: `-b 8 -e 1M -f 2 -n 500`.
- Pelshaw targets small-packet traffic and uses more iterations to smooth jitter.
- Correctness Check: expose hardware issues or silent data corruption.
- Suggested options: `-c 1` or `-c 5`.
- These options turn on validation for computed data.
- Any non-`0` value in `#wrong` means the transfer produced data errors.

## NCCL-tests Native Parameter Quick Reference
- This reference summarizes NCCL-tests options, meanings, and example usage.
- `-b` or `--minbytes`: define the minimum message size.
- `-e` or `--maxbytes`: define the maximum message size.
- `-f` or `--stepfactor`: set the multiplier used between `-b` and `-e`.
-b 8
-e 2G
-f 2

## NCCL-tests Native Parameter Quick Reference
- `-n` or `--iters`: set how many measured iterations run.
- `-w` or `--warmup_iters`: set the number of warmup iterations.
- `-g` or `--ngpus`: choose how many GPUs each thread controls.
- On a single node, `-g` is usually `1`, while the script detects total GPUs automatically.
- `-o` or `--Norness`: select the reduction operation type.
- Valid `-o` values include `sum`, `prod`, `min`, `max`, and `avg`.
-n 20
-w 5

## NCCL-tests Native Parameter Quick Reference and Notes
- `-d` or `--datatype`: choose the data type.
- Supported `-d` values include `float`, `double`, `half (fp16)`, and `bfloat16`.
- Run `nccl_perf -help` when more usage details are needed.
- Before starting, check CPU utilization with `nvidia-smi`.
