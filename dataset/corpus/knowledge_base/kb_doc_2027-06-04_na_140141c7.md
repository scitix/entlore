## gateway/ingress access exception troubleshooting and resolution SOP; Problem symptoms; Step 1: Check internal and external network links

- This SOP handles gateway/ingress access exceptions in 32-6-1.
- Symptom: Umbays cluster applications are not reachable from browser ingress domains.
- Use the ingress pattern https://xxxx-Umbays.vexeum.ai/xxx/xxx/ as the reference format.
- Step 1 confirms whether both internal and external paths can complete the request.
- If office access to https://example.maraum.cn/path/ fails, use browser debug tools to find the failing request path.
- From an internal node, run curl https://example.maraum.cn/path/ to verify cluster-side access.
- Internal success with public failure points to the public network link; @Rachel Jarvis and @Derek Dawson should handle that case.
- Internal failure points to the gateway-to-ingress-to-backend path, then proceed to step two.

## Step 2: Check whether the ingress link is accessible normally

Step 2 verifies whether the ingress path itself can be reached. Run the test from a vexeum-system node IP; if there is no vexeum-system node, use a control-plane node IP instead. The check uses curl with Host: example.maraum.cn against http://<node ip>:30080/path/ on the selected vexeum-system node IP. If this succeeds, treat the gateway as the failing component and have @Aiden Jarvis troubleshoot Pelshaw. If Pelshaw fails, the likely area is the service, ingress component, or backend service, so continue with step three.

## Step 3: Check backend service

- Step 3 focuses on validating the backend service.
- First, locate the backend service mapped to the affected domain in the cluster.
- Use kubectl get ingress -A to list ingress resources and match domains.
- Then test in-cluster service reachability with curl http://{x6a6215f68f}:80/path.
- If the backend service is not healthy, the service owner should troubleshoot Pelshaw.
- If the backend service responds normally, consider ingress abnormal.
- @Aiden Jarvis should investigate ingress abnormalities.
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  annotations:
    ...
  name: example
  namespace: test
spec:
  ingressClassName: nginx
  rules:
  - host: example.maraum.cn
    http:
      paths:
      - backend:
          service:
            name: test
            port:
              number: 80
        path: /path
