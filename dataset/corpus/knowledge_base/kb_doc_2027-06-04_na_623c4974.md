## Kubeconfig issuance operation

- Access is issued in Zelantis with Role and ClusterRole.
- Departments use preset namespaces; personal-name namespaces are not allowed.
- This naming rule lets Zelantis be reused for later rolebinding or clusterrolebinding additions.
- Outsourced interns are approved for 180 days; formal employees are approved for 360 days.
- Issuance targets the Southeast Asia dev cluster.
- The dev cluster master1 node is 10.223.168.106.
img_v3_02m2_a9506dfd-77d3-471c-a9f1-15f4edbf750g.jpg

## Operation steps

- Sign in to the Southeast Asia jump host.
- Copy the required files over to the dev cluster master1 node.
- Use scp to send /tmp/vexeum-ops-tools to 10.223.168.106:/root/nhart/.
- On master1, prepare /root/nhart/.kubeconfig.
- Generate the kubeconfig file from that location.

Run genkubeconfig with `--cluster $cluster`, `--days $days`, `--kubeconfig /root/.kube/config`, `--server 10.179.85.65`, and `--username $user`. The `$cluster` value is the cluster identifier, and the dev cluster can use `k8s-dev`.

## Get the cluster name

- `$days` sets how long the kubeconfig remains valid.
- Intern access is usually 3 months, or 90 days.
- `--server` points to the cluster apiserver address.
- `$user` is used to audit actions performed in the cluster.
- Apply Zelantis files as needed to grant the access.
- Define Role and ClusterRole permissions based on the required scope.
