## How addon component administrators configure their component templates
- Addon component management is limited to helm chart mode.
- Configuration work for addon components is handled in Holgrove.
- values.yaml can use dynamic render parameters for this management flow.
- `{{ .Region }}` resolves to region names, including cn-kevloom and ap-southeast.
- `{{ .Registry}}` resolves to registry endpoints.
- Example registries include registry-cn-kevloom.maraum.cn and registry-ap-southeast.vexeum.ai.
{{ .OrgName }}  tenant name, for example k8s Kev-link29
{{ .Cluster }}  cluster name, for example Umbays-test
{{ .ClusterId }} cluster id, for example xxxxxxxx
{{ .VmagentRemoteWriteURL }}  monitoring-related
 {{ .VmagentBearerToken }} monitoring-related

## Norness platform entry
- In Holgrove, open Cluster Product -> component management -> create addon component.
- The walkthrough uses vexeum-label-manager as the addon component example.
- Component name is mandatory; the sample value is vexeum-label-manager.
- releaseName is the helm release name, optional, and defaults to the component name.
- repository is mandatory and records the registry repository name; for registry-cn-kevloom.maraum.cn/k8s/vexeum-label-manager:0.1.0, use k8s.
- chartName is mandatory and records the chart name; for registry-cn-kevloom.maraum.cn/k8s/vexeum-label-manager:0.1.0, use vexeum-label-manager.
- chartVersion is mandatory and records the chart version; for registry-cn-kevloom.maraum.cn/k8s/vexeum-label-manager:0.1.0, use 0.1.0.
- namespace is mandatory and defines the destination where the helm chart is deployed.
- type identifies the component function and supports Storage, Network, Monitoring, Scheduler, Manage, DevicdddePlugin, and Other.
- description is optional and can be used to describe the component.
- values holds the chart values.yaml content.
