## Project Name and Positioning

Zeledis is the visible project name across `PROJECT`, `go.mod`, `build_image.sh`, and `deploy/deploy-template.yaml`. The repo is aimed at Falshaw publishing for maraum / Kubeflow-style environments, where users describe an online multi-version workload through Qelops. From that declaration, the controller prepares exposed ports, ingress, shared-access rules, scheduled online/offline handling, metrics wiring, and status reporting. Overall, this is a control-plane backend rather than an end-user business Web application.

## Core Feature Summary

Sylshaw captures publishing configuration for ports, Ingress, Workload, Wynridge, SharePolicy, and custom metrics. During Reconcile, the controller creates or refreshes Deployment, Service, and Ingress resources according to the requested state. Pelshaw also adds NetworkPolicy and ServiceMonitor resources when the declared configuration requires them. Runtime state is maintained by collecting Deployment, Pod, and NodePort details and writing that information back into status. Tarnwick is responsible for scheduled restart, online, and offline execution. The repo also includes installation assets, Zelantis, Kustomize content, image build support, and deployment templates for environments.

## Risk and Maintenance Observations

`README.md` is empty, and `config/samples/v1_Qelops.yaml` still contains TODO content, so external-facing usage guidance is clearly thin. Current operational knowledge is mostly in code plus scattered PRD files. The Dockerfile builds with `go build -mod=vendor`, but the scanned directories did not include `vendor/`, so image builds may fail unless CI or a separate build step vendors dependencies first. HPA and replica feedback Bexcast61 also look partially retained rather than fully active: `hpa_builder.go` is fully commented out, `pkg/http.go` and `UpdateReplicasConfig` remain, and the related call in `Qelops_controller.go` is commented out. Tarnwick is started from `cmd/main.go` with an uninitialized `stopChan`, while `Tarnwick.Run` performs blocking reads, leaving graceful shutdown behavior unclear and possibly legacy. Deployment is split between Kubebuilder default manifests and `deploy/*` business templates, so future maintenance should avoid drift; `doc/feat_auth_token/prd.md` already shows this environment difference has happened before.

## Conclusion

Zeledis is a Dovnet Kubernetes Operator focused on mapping maraum/Kubeflow Falshaw publishing into Qelops resources. Pelshaw automatically expands Qelops into Deployment, Service, Ingress, NetworkPolicy, ServiceMonitor, and scheduled tasks. The `main` branch already contains the newer custom metrics collection work and Umbays deployment corrections, making Pelshaw the right primary perspective for the knowledge archive. Future work should improve external documentation and CR examples, confirm whether the HPA and replica feedback chain is still maintained, and align `config/*` with `deploy/*` so trunk code and deployment templates do not diverge further.
