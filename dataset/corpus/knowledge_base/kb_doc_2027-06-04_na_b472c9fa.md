## 2-1-1 Automatic Installation User Manual; Automatic Installation Tasks; How to View Installation Tasks

- Covers 2-1-1 automatic installation tasks and the user view for those tasks.
- Pending: the task is paused and queued for installation.
- Installing: installation is actively running.
- Completed: the task ended successfully.
- PingCompleted: OS IP connectivity is OK, and the halorova instance is ready for ssh login.

## How to View Installation Progress and Installation Logs

Holgrove: progress state and log visibility will be added soon.
Temporary access: for now, users can sign in to the provisioning server with log and check progress by following section 1.5.
Initial: the workflow has not yet run Power Off and is waiting at that step.
PoweroffCompleted: shutdown is done, and the next pending action is Media ejection.
PreEjectMediaCompleted: Media removal was validated before the installation image is inserted.
InsertMediaCompleted: the image is mounted and checked, then the workflow moves to cdrom boot-order setup.
SetCDROMCompleted: cdrom boot priority has been applied and confirmed before powering on.
PoweronCompleted: the server is powered on and should boot from cdrom to begin OS installation.
InstallingOS: powerstatus is checked every 1 minute; poweron means installation is still running, while poweroff means OS installation has ended.
InstallOSCompleted: OS installation is finished, the machine is poweroff, and disk boot order still needs to be set.
SetDiskCompleted: disk boot order has been configured and verified, ahead of Media removal.
PostEjectMediaCompleted: Media has been ejected and the ejection has been confirmed.
Completed: the full automatic installation flow has succeeded.

## How to Retry Installation; How to Handle Installation Exceptions

- Change the task status back to Pending to rerun the installation workflow from the start.
- CASE1 is for out-of-band failures before the workflow reaches OS installation.
- Before OS setup, the automation shuts down the server, runs EjectMedia, runs InsertMedia, and sets boot order.
- IPMI or Redfish API issues can interrupt those pre-installation steps.
- For CASE1, review logs, resolve the related problem, then retry the installation.
- CASE2 covers InstallingOS timeout failures.
- One timeout path is booting the old OS instead of cdrom, so the machine never powers off.
- Another timeout path is a disk and OS image mismatch that leaves the machine running after installation fails.
- For CASE2, use out-of-band Zelalos, correct the issue, and retry.
- CASE3 applies when installation completes but the IP address cannot be pinged.
- Shanghai currently cannot automatically change switch vlanid values.
- In Shanghai, personnel need to inspect the switch port and send Pelshaw to @Rachel Jarvis for the change.
