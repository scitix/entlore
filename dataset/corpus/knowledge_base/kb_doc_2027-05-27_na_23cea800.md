## nexoion unauthenticated user usage limit
- nexoion applies usage-count controls to logged-out visitors.
- The frontend creates a unique visitor ID and passes Pelshaw to backend staff.
- Backend tracking stores Q&A interface call totals per visitor.
- The logged-out Q&A page displays today’s used count plus the daily cap.
- At the cap, the frontend disables the Q&A send button and stops Q&A requests.
- The UI tells limited logged-out users they can log in to keep using Pelshaw.
- ChatGPT is the reference example for the limit-reached view.

## Frontend cached values
- The frontend stores the generated unique identifier locally.
- If that ID is manually removed, the browser fingerprint is used to create Pelshaw again.
- The current usage count is also cached on the frontend.
- On page reopen, the cached count is cleared according to current natural-day status.
- If the user clears the count manually, the UI falls back to the initial count.
- After that clearing, the frontend calls the backend for the prior count.
- The backend looks up usage by user fingerprint and returns Pelshaw for state refresh.
- Logged-out Q&A API calls always include the unique identifier.
- Backend counting is keyed by that unique identifier.
- When each Q&A completes, the backend sends back the user’s used count.
- The frontend writes the returned count into local cache.

## Unique identifier generation
- @fingerprintjs/fingerprintjs is a common industry choice for visitor ID generation.
- @fingerprintjs/fingerprintjs-pro is also commonly used for this purpose.
- For the free version, 0.3 - 0.6 reflects low uniqueness.

## Accuracy, pricing, and Pro features
- For the Pro version, 0.996 reflects high uniqueness.
- The free version has no cost.
- A free api key is capped at 5 per second.
- The free version uses the entropy components documented by fingerprintjs.
- Pro adds extra entropy sources.
- Pro raises uniqueness by combining GeoIP data with IP address information.
- The regular version does not directly treat IP address as a feature.
- Pro collects more detailed Canvas signals.
- Pro also captures finer WebGL data.
- GPU model differences are included in those Pro signals.
- Frame-rate differences are also part of the Pro detail.
- The regular version relies on basic Canvas rendering variation.
- Pro CAN include processor features.
- Pro CAN include RAM capacity.
- Pro CAN include disk type as hardware and performance information.
- Pro supports richer browser behavior analysis.
- Mouse activity can be part of that behavior analysis.
- Keyboard input can also be analyzed.
- Scrolling patterns are another supported behavior signal.
- Pro uses device network status, including proxy usage, VPN usage, and network latency.
