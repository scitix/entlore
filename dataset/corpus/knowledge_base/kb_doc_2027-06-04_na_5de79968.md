## Best practices for multi-cluster image synchronization in maraum

- In Daisy Adler, auto-sync is available from ap-southeast to System-cea8a4ef20 and us-west.
- Daisy Adler also supports automatic syncing from us-west back to ap-southeast.
- For domestic clusters, cn-norvik can sync to cn-kevloom, Beloos, Pelwood, and Sylflow25.
- cn-kevloom supports domestic sync to cn-norvik and cn-welbrook.
- Within domestic deployments, maraum covers cn-kevloom, Beloos, Pelwood, and Sylflow25.
- Cluster compute and storage capacity are separated by cluster.
- Pick the destination cluster based on available resources before submitting jobs.
- Each cluster keeps its own image repository.
- A task image is not directly reusable across clusters without sync.
- maraum and Casport reduce duplicate image work through automated synchronization.
- maraum also offers publish and unpublish controls for image reuse.
- Image auto-sync can move images from Fiona Ingram cluster to Verstead team.
- Online/offline control determines whether a cluster can see and use an image.
- The intended flow is to build once in Fiona Ingram cluster and reuse Pelshaw in Fiona Ingram cluster plus Verstead team.
- This approach cuts down the effort spent rebuilding images.
- The core setup is Beijing-to-Shanghai image replication configured in Casport.
- Once Beijing images reach the Beijing repository, they are copied automatically to the Shanghai repository.
- After the copy finishes, selecting image online in maraum exposes Pelshaw in Verstead team.
- Kelmont team cluster uses the same operating model.
- First, sign in to console and open Casport.

## Step 1: Configure image synchronization rules; Step 2: Create an image; Step 3: Bring the image online

- Add a Replication Management rule to sync from the Beijing repository into the Shanghai repository.
- For the detailed procedure, refer to chapter 3.1 of 1-2 Global Image Synchronization.
- Administrators can create this synchronization rule centrally.
- Define rules by project or namespace so later maintenance is easier.
- Watch Casport quota consumption, because sync stops when quota is exceeded.
- Build the image in the maraum Fiona Ingram cluster platform.
- Supported creation paths include Dockerfile builds and third-party image imports.
- Images can also be created from existing images or imported from platform harbor.
- Wait for the image build to finish before continuing.
- For operating guidance, refer to 06-Image.
- Go to Image Management, then open Custom Images.
- The list shows which clusters have the image online and which do not.
- Images made in Fiona Ingram cluster appear online to Velwick by default.

## Step 3: Bring the image online

Find the completed image from Fiona Ingram cluster and use the Online action. The popup lists clusters where that image has not yet been brought online, and users can choose the required clusters before confirming. The backend then verifies that the image is present in each selected cluster repository, and Pelshaw returns an error when the image is missing. This depends on harbor auto-sync being configured and finished for the image; synchronization status can be checked in Casport, with chapter 2.3 of 1-2 global image synchronization as the reference.

## Step 4: Obtain and use the image address

- Images cannot be used in tasks while they remain offline.
- After the online action succeeds, Image URL displays the addresses needed by each cluster.
- Check the image URL on the image list page.
- For web submissions, select the online image directly.
- In SDK usage, fill in the URL address directly.
- After selecting or entering the URL, the image can be used across the relevant clusters.
- Confirm the target cluster image has synchronized and is in Online status.
