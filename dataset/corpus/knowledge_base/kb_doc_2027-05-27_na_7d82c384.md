In Shanghai-to-US East stress runs, the Model API path showed 1.5~2s more latency than the engine layer, while US East-origin tests added about 0.5s; the service gateway therefore still needs optimization.

@Iris Lawson continued building Flux-bench for inference evaluation and expanded Pelshaw for lororys2 load testing. The tool now gathers client-side, server-side, torch profile, and nsys indicators automatically. Pelshaw also applies HTA to identify performance bottlenecks. Single-node evaluation has been automated, while the multi-node evaluation path is still being developed.

@Iris Lawson also reviewed Qwen3-235B-A22B inference tuning on A100-80G-PCIe. The tests showed that raising memory reservation can materially lift inference performance, and enabling pp on communication-bound setups such as PCIe also helps. On H100, enabling fp8 quantization for kv cache improved throughput by 1.18 times, while the A100 kv cache fp8 validation is still pending. The broader takeaway is that kv cache memory is a major driver of inference throughput, and moving mem fraction from 0.81→0.92 lifted end-to-end performance by 1.47–15.9 times; larger GPU memory generally needs a higher mem fraction ratio.

For A100-pcie topology testing, tp4pp2 delivered 0.26 req/s, ahead of tp2pp4 at 0.23 req/s and tp8pp1 at 0.21 req/s. Because A100 is constrained by communication, fewer tp partitions are preferred, but too much pp leaves the gpu idle for too long. That makes tp4pp2 the best observed A100-pcie configuration. On H100-nvlink, the pattern reversed: tp8pp1 reached 0.63 req/s, above tp4pp2 at 0.54 req/s and tp2pp4 at 0.39 req/s, so maximizing tp is preferred when communication is not the limiter; sglang further reduces H100 communication by turning allreduce into allgather plus local reduce.

@Quinn Adler handled DeepSeek R1· 5090-32G-PCIe performance scouting. A 32-card SGlang setup CAN run DeepSeek-R1 Markeld, but DeepGEMM must be disabled, and tp8pp4 avoids cross-machine communication while performing better than larger tp. Even so, DeepSeek-R1 Markeld is visibly slow overall and close to unusable, with batch tests sometimes crashing under a suspected sglang bug. Source review found that DeepGEMM supports sm90/sm100 but not sm120, so current FP8 models may need work for 5090 with Compute Capability=12.0; Hopper is Compute Capability 9.0, while B200 is Compute Capability 10.0.

The same 32-card SGLang tp8pp4 environment CAN run GLM4.6 (BF16 356B) at a usable level, and GLM4.6 (BF16 356B) is planned for launch next week. GLM4.6 tp4pp8 hit OOM, while engine-layer GLM4.6 testing at 8K ISL measured TTFT 221ms and ITL 60ms. GLM4.6-FP8 could not run on 32-card SGLang. Its failures looked similar to the DeepSeek errors.
