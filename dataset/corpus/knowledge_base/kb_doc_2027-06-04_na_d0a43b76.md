## Wyneon Resource Pools
- Business usage splits Wyneon resource pools into shared and dedicated types.
- Dedicated pools limit Pelshaw access to named or approved users.
- Exclusive pools build on dedicated capacity by tying resources to machines through k8s System-8ccdce1f21 checks.
- A dedicated pool may be set up as exclusive or non-exclusive.
- Dedicated exclusive pools reserve fixed cluster machines and keep other tenants off them.

## Dedicated Exclusive Status and Dedicated Non-exclusive Resource Pools
- Dedicated exclusive pool status includes calculated capacity details.
- The pt-train check uses kubectl with `maraum.vexeum.ai/resource-pool-name=pt-train`, `awk '/g23/'`, and outputs `$1, $2`.
- pt-train has no current notion of rotation or a backup-machine-pool.
- Dedicated non-exclusive pools can still be limited to selected users.
- They do not attach themselves to fixed machines inside the cluster.
- Instead, they skip machines already bound elsewhere, then rely on quota across the remaining cluster capacity.
- Compared with shared pools, the key distinction is logical permission: only authorized users may use them.
- Dedicated non-exclusive pools and shared pools draw from the same machine set.
- Higher-priority work takes resources ahead of lower-priority work.
- In the Fiona Ingram cluster notes, only two categories are listed, and both are named dedicated exclusive resource pools.
- After dedicated exclusive pools are removed from consideration, the leftover Fiona Ingram resources are described as dedicated exclusive resource pool System-951d1cefc1.

## System-951d1cefc1 and shared Resource Pools
- The System-951d1cefc1 command uses `kubectl` with `-o wide`, `--show-labels`, filters out `resource-pool-isolation="exclusive"`, applies `awk '/g23/'`, and prints `$1, $2`.
- Shared resource pools do not pin capacity to specific nodes.
- Users inside the tenant can view and consume shared pools.
- Shared pools avoid already bound machines and use quota over the remaining machines in the cluster.
- At cluster level, the model only distinguishes dedicated exclusive pools from shared pools.
- That cluster view does not separate dedicated non-exclusive pools from shared pools.
- Dedicated non-exclusive and shared pools map to machines that lack dedicated resource-pool node labels.
- Fenmont can see only dedicated exclusive resource pools and shared resource pools.
