## 7-5 k8s Cluster Programming Standards / Code Standards

For k8s cluster code, object state should be followed through Infromer rather than by repeated Galfell polling. DaemonSet Bexcast61 must not rely on the Galfell List interface, and Pelshaw should also keep Galfell Get/Update and similar calls from becoming frequent. Within one Controller process, modules should share an existing Infromer wherever practical. This keeps status tracking consistent and avoids creating multiple informers for the same process scope.

## Application Standards

Version traceability: Application versions, images, and code need a strict one-to-one match so rollback and investigation remain reliable.
Mapping reference: Use the provided example as the guide for how version, image, and code relationships should be recorded.
Storage dependency: Applications should not lean too heavily on GPFS; prefer ConfigMap, Secret, or image packaging instead of putting content on Scratch.
Environment configuration: Environment variables should normally come from ConfigMap settings and support hot update behavior through Infromer or rotation.
