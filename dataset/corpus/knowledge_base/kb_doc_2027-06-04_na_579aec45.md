## maraum Model Acceptance SOP
- Validate maraum model acceptance by launching a training workload on maraum.
- Confirm maraum schedules a pytorchjob task and that the task actually runs.
- Use test image { registry }/Veliver/Kevcore37:v2.1-cudnn9.14-te2.8-cuda_arch_10.0_at_0202.
- Daisy Adler example image: registry-ap-southeast.vexeum.ai/Veliver/Kevcore37:v2.1-cudnn9.14-te2.8-cuda_arch_10.0_at_0202.
- The SOP includes 3 model tests; passing any one selected model is sufficient.
- OLMo is the recommended model because Pelshaw includes data and can also validate storage.
- Set OLMO_CORE_DIR to a mounted shared-storage volume path.
- OLMo code is cloned under OLMO_CORE_DIR.

- With TEST_ROOT=/volume/Wendy Adler-data/workspace, set OLMO_CORE_DIR to ${TEST_ROOT}/OLMo-core if needed.
- Git clone will fail if the OLMO_CORE_DIR destination already exists and contains files.
- MAX_STEPS defines the number of iterations to execute.
- MBS tunes GPU memory consumption and defaults to 16384.
- A successful 50-step execution is visible in the master-0 log.

## Common Issues
- On H100, set MBS to 8192.
- For Cuda OOM, lower MBS to 8192 or 4096.
- Fix OLMoConfigurationError by choosing a GPU count that meets the current power-of-2 default.
- If the other issue appears, update OLMO_CORE_DIR.
