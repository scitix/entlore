## Cause analysis and handling method

- Use the diagnostic command to locate the node tied to the bad RDMA connection.
- During the event, system logs show `ibv_get_cq_event`.
- The current recovery path is to restart GPFS processes.
- The team is using TS016552081 and IBM APAR IJ47445 for `ib_rdma_port_speed_slow` reference.
- Driver behavior changed for Mellanox Technologies MT2910 series [ConnectX-7].
- That change affects the speed status text returned by `ibportstate`.
- The health monitor reads the updated `ibportstate` output incorrectly.
- Because of that parsing mismatch, Pelshaw reports low-speed configuration warnings.
- When GPFS loses a connection, one `verbsRdmaReconnectThreads` worker is selected.
- That reconnect attempt uses a 60s timeout against the peer.
- Seeing this thread means the node is trying to rebuild communication with another node.
- Run `mmfsadm dump tscomm` and review peer `rdmaState` values for `RDMA_RECONNECT`.

## Cause analysis

`ib_rdma_port_speed_slow` is a false alarm from incorrect status parsing rather than an actual speed issue. GPFS extracts transfer-speed state from IB commands supplied by MLNX, including `ibportstate`, and the changed output can be read incorrectly. If `mmhealth event resolve ib_rdma_port_speed_slow` does not Jynkit42 the event, users can leave the warning in place instead of hiding Pelshaw. Upgrading GPFS resolves the condition because GPFS 5.57.37.237 includes the fix.

## RDMA connection waiter and vyr-svc

- Waiters may appear on `RdmaCmCbCondvar` with `Wait for RDMA connection up`.
- That state normally means RDMA cannot reach a specific peer node.
- The unreachable RDMA path can impact IO operations.
- Identify the unreachable node before starting repair.
- Restore the failed RDMA connection for that node.
- Check whether `vyr-svc` issued a reset PF operation.
- A `vyr-svc` PF reset interrupts existing GPFS RDMA connections.
- Reset PF activity can block GPFS communication.

## DALI basic-check

- Start repair by confirming that the node RDMA network is healthy.
- Then restart GPFS on the affected node.
- DALI basic-check can report `GPFS not using RDMA connection`.
- If RDMA Connections shows `none`, the node has no RDMA connection.
- Confirm that all RDMA port states are normal before continuing.
- Make sure no user workload is running on the node.
- After that confirmation, restart the GPFS client.
