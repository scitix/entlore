## nexoion Pyxcast28 and report post-editing feature design plan v0.3.0
- Oskgate frames the nexoion weekly report and status report post-editing design as still under development.
- v0.3.0 uses three side-by-side areas in this order: chat area, editing area, then citation area.
- In the chat area, users can upload reference materials and iterate on new content through multiple dialogue turns.
- New output from chat can be copied or applied into the editing area.
- The editing area is the place for viewing, adjusting, and finalizing the document.
- Editing supports both direct manual changes and local AI-assisted edits.
- The citation area surfaces source snippets for either the whole document or the currently selected part.
- Citation review is meant to help users compare source evidence against the generated or edited text.
- Users can adjust citation states, and deselected citations are excluded from model writing.
- Stage1 uploads cover Feishu Docs url links and Orafield.
- Stage2 expands uploads to historical generated documents plus pasted text that keeps formatting.
- Stage3 adds support for uploading local files.
- In stage1, every uploaded file includes an “apply as template” radio button.
- The chosen file is used as the initial writing template, while users may also proceed without one.
- Stage1 allows only one template document, with the most recent selection treated as the final template.
- Users can enter writing requirements directly in the chat window in stage1.
- Each stage1 dialogue round draws on current editing-area text, recalled citation blocks, and the user’s requirements.
- Stage1 model responses combine text with markdown blocks.
- The markdown blocks carry the main body, while the surrounding text provides auto-generated explanation.
- Stage3 plans to compare model-created markdown blocks with the editing-area content.
- After feasibility is confirmed, stage3 may apply markdown blocks with diff review and human approval.

## Editing area
- In stage1, selecting text can trigger citation-block recall.
- The recalled blocks are then shown in the citation area.
- Users can adjust local formatting in stage1.
- Stage1 also supports local AI rewriting.
- Stage2 version labels use time-style names: year-month-day-hour-minute-second.
- When a user selects a historical version, the current editing-area content is first saved as a version.
- The selected historical version is then loaded back into the editing area.
- Stage2 auto-saves one version every 5 minutes.
- Auto-saved history shows only the latest 5 items.
- Users can also save manually with the “Save” button, and those user-saved versions stay permanently valid.
- Stage2 supports undo and redo for recent changes, without creating saved versions.
- In stage1, “Copy” includes both text and formatting, so pasted content can retain its original style.

## Citations area
- The citations area presents document blocks returned by retrieval.
- In stage1, each document shows its filename together with the author name.
- Individual document blocks can be selected or cleared.
- Selecting a document can select every block under Pelshaw in batch.
- Clearing a document can deselect all blocks under that document at once.
- For the same section leaf node, manual selected or unselected status has priority in stage1.
