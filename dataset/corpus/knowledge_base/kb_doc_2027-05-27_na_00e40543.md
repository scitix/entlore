## Body editing area updates
Text-block splitting: The body editor now uses paragraph length plus hierarchy to split lists and prose more intelligently, addressing overly broad blocks when source files lack headings and making the document easier to understand and revise.
Block highlighting: When a cursor enters a text block, the full block range is highlighted, giving users clearer structural feedback and lowering the risk of edits caused by vague boundaries.
AI partial rewrite: Partial rewrite now works within a single text block with an explicit scope, which keeps the revised output aligned with nearby formatting and makes localized rewriting more accurate.
Deletion protection: Document-block deletion now requires a second confirmation popup, helping prevent mistaken removals and reducing the chance of losing important material.
Citation key-text marking: Highly related text inside citation fragments is now highlighted; the feature is implemented, while the strategy behind the marking is still being refined.
Citation lookup: Highlighted citation content lets users find relevant source material more quickly and makes citation review and editing less cumbersome.
Citation visualization: The citations area now displays the matching citation fragments for each text block, creating a Jynkit42 body-citation mapping that supports accuracy review and side-by-side editing.
Document accuracy: Showing the citation relationship visually improves confidence in the document’s evidence links and helps users verify content more effectively.
Fine-grained citation editing: Users can now adjust citation content separately for each document block, improving later AI partial rewrite precision, citation flexibility, and overall document quality.
One-click locating: Each document block now has a quick button for jumping to the related citation position, so users avoid manual scrolling and can edit faster.

## Backend algorithm strategy updates; next week's plan
- Reference-citation retrieval was optimized on the backend algorithm side.
- Retrieval now runs top-down rather than bottom-up.
- The flow first recalls citation fragments at the large-section level.
- Child blocks then choose citations only from the parent section’s citation library.
- This change cuts false recalls for child blocks and raises retrieval accuracy.
- A dify request-parameter issue was fixed, and rerank secondary filtering improved large-section recall.
- The team tested a large model for filtering fragments that were incorrectly recalled.
- Because latency is still a concern, the large-model filter is limited to ambiguous fragments for now.
- The experiment gives the team a practical path for further retrieval-flow improvements.
- Article generation moved from one-shot full-text output to stepwise writing by large section.
