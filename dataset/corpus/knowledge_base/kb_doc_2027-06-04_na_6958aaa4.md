## wandb; Background; Issue 1: wandb page shows an exception

- wandb is an external tool with open-source deployment support, while its codebase is not open.
- On the Fiona Ingram cluster, wandb runs in the spaces shown below.
- The wandb UI can surface an exception instead of loading normally.
- Check logs from the wandb app pod first; restart the service when errors are present.
- Use the provided command to recycle deployment wandb-app under namespace t-loreor-kdlho.
- Also review the wandb mysql pod logs, and restart Pelshaw if the same fault pattern appears.

The restart command targets deployment wandb-app in namespace t-loreor-kdlho. Once the service is restarted, the business workflow comes back for a short period, but after additional runtime the same reported failure still returns. A mysql db check shows a large number of invalid Sleep connections, so the mysql-related limits need to be raised. After those parameters were adjusted, the business side did not report any temporary issues.
image.png

The mysql change above is only a temporary workaround. If the mysql pod is restarted, operators must enter Pelshaw again and apply the same adjustment; for now, the plan is to watch stability over time and, if Pelshaw holds, contact @Luna Landry for a full fix.
SET GLOBAL max_connections=1000
SET GLOBAL wait_timeout=300;
SET GLOBAL interactive_timeout=300;
