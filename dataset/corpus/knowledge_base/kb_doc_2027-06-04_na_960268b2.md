## log data layer complete manual for maraumNora Drake platform users

- Audience: maraumNora Drake users who operate the log data layer.
- Scope: log review, possible user data loss, and latency investigation.
- Integrity checks start by confirming related Pod logs in Kibana via method 1.3.
- For delay cases, locate user data through 1.3, then review section 2.
- If integrity gaps are found, use section 3 to examine data-link problems.

## View logs

Find the Kibana endpoint in the vexeum/maraum log service area of the observability system address summary. For kernel log review, go to Discover and choose the maraum-kernel* index pattern. Use filters like kubernetes.node_name: "BL-g23-120" to narrow the results to the required node.

## View system service logs; View task logs; View end-to-end delay

- Use maraum-auditd* to review cluster audit records.
- For task logs, choose the relevant index in the maraum-t-loreor* pattern.
- Search task records by Pod name or by task name.
- To check end-to-end latency, open any user log record.
- The time value shows when the user Pod created the log.
- The es_ingest_ts value shows when Elasticsearch received Pelshaw.

## View end-to-end delay; View data-link issues

- Calculate end-to-end transmission delay from the gap between time and es_ingest_ts.
- Current end-to-end transmission delay is usually under 1s.

## Monitoring metric quick reference

- Nodes: expected value matches the cluster node count.
- Nodes: a drop points to a node-side abnormality.
- FluentBits: expected value should match Nodes.
- FluentBits: any mismatch suggests a DaemonSet problem.
- Ready Fluentbits: expected value should match FluentBits.
- Ready Fluentbits: a lower value means some Pods are not ready.

## Monitoring metric quick reference

- Ready Fluentd: normal range is ≥ 1.
- Ready Fluentd: = 0 means the aggregation layer is fully unavailable.
- Non-Ready Fluentbits: normal state is No data.
- Non-Ready Fluentbits: any returned data means abnormal Pods exist.
- Nodes with no data read in for 10 minutes: normal state is No data.
- Nodes with no data read in for 10 minutes: any data indicates collection stagnation.
- Fluentd Retry: normal value is 0.
- Fluentd Retry: sustained > 10 needs attention.
- Fluentd Error is included as a monitoring metric panel.

- Fluentd Error: normal value is 0.
- Fluentd Error: > 0 requires investigation immediately.
- Fluentbit Output Error Rate: normal value is 0.
