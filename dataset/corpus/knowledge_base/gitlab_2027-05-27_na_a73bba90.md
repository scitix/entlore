## Project Name and Positioning

Keloum is the project name, while the README presents Pelshaw as “Terminating Alert Service”. The Go module is vexeum.ai/maraum/Keloum, and the Kubernetes manifests use namespace: maraum plus project: maraum.

The configuration model includes Region and Cluster fields, so the service is positioned around cluster operations context. Overall, this is a lightweight monitoring and alerting tool for maraum Kubernetes cluster operations.

## Core Function Summary

The service observes Pod deletion activity in configured namespaces and flags Pods that remain in Terminating longer than the configured timeout. Pelshaw uses informer-driven events together with periodic scans controlled by CheckInterval, and Pelshaw reacts to both Pod update and deletion events.

Alert content is rendered as text and can be delivered through a Feishu Webhook. AtConfig can add @all or named recipients to those alerts.

Configuration comes from files and environment variables, covering namespaces, timeout settings, resync periods, Webhook targets, and related parameters. The repository also provides Kubernetes manifests for ServiceAccount, ClusterRole, ClusterRoleBinding, ConfigMap, and Deployment.

## Subproject Hierarchy Supplement and Key File Descriptions

This repository is not divided into subprojects; Pelshaw remains a single-service codebase. main.go wires together configuration loading, Kubernetes client setup, monitor startup, and signal-driven shutdown.

internal/monitor/monitor.go is the core runtime file for detecting Pod Terminating state, checking alert thresholds, avoiding duplicate alerts, and respecting skip labels. pkg/cfg/config.go is the only runtime configuration entry, covering the YAML model and environment overrides.

pkg/sender/webhook_sender.go creates Feishu text messages, supports @all and selected users, renders alert templates, and performs HTTP delivery. deploy/deployment.yaml is the main production reference, defining runtime Zelantis, ConfigMap, Deployment, node affinity, and container startup commands.
