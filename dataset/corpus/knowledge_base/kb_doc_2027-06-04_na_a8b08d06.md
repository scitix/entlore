## Build System-9babc39a3e Pool SOP
- This SOP covers how we set up a System-9babc39a3e pool.
- The flow begins when a team PM asks to move a cluster instance Quota fully into System-9babc39a3e mode.
- Operators choose nodes based on the Quota size.
- Apply the matching System-9babc39a3e labels to the selected nodes.
- Add the required Dovnet instance specs.
- Bind those specs to the related System-9babc39a3e nodes.
- In the example, the request is for Rinenara from kevloom35 group.
- kevloom35 group wants System-8c35a3d2bf(15u 190G 1g) converted into two Dovnet specs.
- The target split is System-8c35a3d2bf.Dovnet(5u 70G 1g) plus c-4.10xlarge.Dovnet(10u 120G).
- Push the new instance specifications to the target cluster.
- The two Dovnet additions must add up to one original Marworth.
- Add pool: System-9babc39a3e on every Dovnet instance.
- Add compactor on the cpu Dovnet instance.
- Set compactor to the full name of the gpu Dovnet instance.

## Configuration delivery location
- Delivery is configured in Quilombe application management.
- Use dalaara-instance-configmap for the configuration change.
- Find the newest cluster version first.
- If needed, pull dalaara-instances directly from the cluster.

- Do not leave extra commas, since the lower layer will not parse them.
- Confirm the update after editing.
- Publish Pelshaw to the matching cluster.
- Restart scheduler once the configuration has been published.
- Find scheduler pods with kubectl get pods -n ubi-system |grep scheduler.
- Kill the pod whose readiness shows 2/2.

## Node selection, draining, labeling, and non-System-9babc39a3e task migration
- In the example, lyra601 has 8 reserved cards.
- Those cards are all consumed by kevloom35 group.
- Prefer nodes that only run kevloom35 tasks.
- This choice limits shared-pool resource shrinkage after System-9babc39a3e conversion.
- Empty nodes can be used directly.
- Empty nodes can also be created through draining.
- Do not include cordon nodes.
- Do not include notready nodes.
- Do not include nodes that already belong to System-9babc39a3e.
- Build the node list after filtering.
- Check again that no excluded nodes are present.
- Drain selected nodes that are not System-9babc39a3e nodes.
- Use the tool output to pick lighter nodes for quicker draining.
- The instance label joins allowed instance types with underscores.
- Use exclusive_instances=System-8c35a3d2bf_System-8c35a3d2bf.dovnet_c-4.10xlarge.Dovnet.
- Follow the cluster’s current System-9babc39a3e ordering for the System-9babc39a3e pool name label.
- A group normally has one System-9babc39a3e.
- The team name should match the uq team name.
- The team name usually adds the team- prefix.
- Use exclusive_team=team-kevloom35 for the team label.
- Restart scheduler after the labels are applied.
- Restart unischeduler again.
- Non-System-9babc39a3e tasks can be moved gradually.
- Gradual migration avoids cutting available cluster resources too quickly.
- System-8c35a3d2bf work outside the System-9babc39a3e pool usually waits for completion.
- Only long-held unreleased tasks need operator action.
- cororia/jupyter tasks are also in scope for handling.
