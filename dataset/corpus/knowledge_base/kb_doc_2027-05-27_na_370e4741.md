## Troubleshooting stream backlog issue
- Backlog review points to caching on the nginx layer that resolves the domain.
- Nginx normally holds backend response chunks, then forwards them once buffers are filled.
- HTTP traffic is small and does not require decryption, so nginx usually clears Pelshaw fast enough.
- HTTPS processing takes longer because encryption is involved and packet size is larger.
- With buffering on, nginx waits on bigger response blocks, making HTTPS stream lag easier to notice.
- Turning off proxy_buffering makes nginx relay stream data straight to the client.
- Streaming needs backend output to reach the frontend immediately rather than sitting at the proxy.
- For live streams, proxy_buffering can work against real-time delivery.
- HTTP can absorb minor buffering lag because its transport cost is low.
- HTTPS makes the same buffering delay more visible due to encryption overhead.
- Each HTTPS request packet is larger because encrypted content is included.
- When proxy_buffering handles larger HTTPS packets, the wait is magnified.
- HTTP avoids that encryption cost and generally returns faster.
- The investigation ties HTTPS stutter to encrypted packet size plus nginx buffering.
- For an identical request, HTTPS can stutter when encryption, packet growth, and buffering overlap.
- Once proxy_buffering is off, nginx forwards data directly and HTTPS playback becomes smooth.

## Solution
- Disable proxy_buffer.
