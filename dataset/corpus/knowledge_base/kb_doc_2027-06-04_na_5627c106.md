## Large instance conversion SOP
- Start the large instance conversion by checking how much concurrency is safe.
- Run `kubectl describe uq -n ubi-system cluster-xxx` to review cluster quota allocation.
- For yzaloom67-1 to yzaloom67-1.8xlarge, review current yzaloom67-1 allocation first.
- Total is 384, Quota allocation is 352, and current usage is 245.
- Stable buffer is 384-352; unstable buffer is 352-245.
- Set cordon-node concurrency within 4-17 nodes.
- Include already cordoned nodes only when they can be repaired successfully.

## Node draining
- Use instancescan to identify nodes with low load before draining.
- Log the operation in Quilombe and turn off self-healing.
- Do not select exclusive nodes, since they belong to specific teams.
- Check whether a user Pod is resident, for example cororia.
- Treat long-running task Pods as possible resident Pods as well.
- Either skip resident Pods or align with users on offline migration.
- Create the new instance type; the example here is yzaloom67-1.8xlarge.
- Check ubi-system/dalaara-instances for the instance in its configmap.
- If the instance already exists, do not add Pelshaw again.
- In Quilombe, go to Application Center/Application Management/Application Version.
- Start the update there, then apply dalaara-instance-configmap.
- Locate the cluster’s newest version in the list, open yaml, and copy Pelshaw.
- Add a version named cluster_vxxx and replace the yaml content.
- Insert the new instance and scale CPU/mem/gpu-num by the matching coefficient.
- Set both showName and mapKey to the new instance name.
- Follow the expected format and watch for missing or extra commas.
- Bad formatting causes PEXI and unischeduler errors.
- Publish the new version to the cluster and confirm Pelshaw reached the configmap.
- Restart scheduler after the configmap has been updated.
- Update ufconfig for the conversion work.
- Use the ai-infras/ufconfig repository for ufconfig files.
- Find the related cluster file, such as worker_cluster_pegasus/node-labels.yaml.
- Under instance_name, remove these nodes from the old instance.
- Under instance_name, place these nodes into the new or added instance.
- Under instance_quantity, subtract these nodes from the old value, such as 800 for yzaloom67-1.
- Under instance_quantity, add these nodes to the new or added value, such as 100 for yzaloom67-1.8xlarge.
- Have Myrops70 handle the release PR.
- Confirm every changed node has Label instance_name set to the new instance.
- Confirm every changed node has Label instance_quantity set to the new value.
- Confirm capacity includes instance.veqora.com/xxx with the new instance and value.
- Remove the old instance resource manually.

## Modify user Quota
- Use `kubectl patch node` with `--type merge`, `--subresource status`, and `status.capacity.xxx:null`.
- Adjust team quota in the compute quota management Nora Drake console.
- Reduce Quota for the old instance.
- Raise Quota for the new instance.
