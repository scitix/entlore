## nexoion Pyxcast28/report implementation Bexcast61
- nexoion adds backend automation for file analysis tied to weekly reporting.
- Report-writing jobs are also handled automatically in the backend.
- A scheduler pulls the latest four reports for each user.
- user_reports is refreshed with a capped report list of at most 4 items.
- If no user template exists, the newest report MD is saved as the latest template.
- During upload_feishu_reports file refreshes, Pelshaw updates user_report when a template file is set.
- The plan supports hands-off report writing with no user steps required.
- Robot-to-user message exchanges are included in the interaction design.

## Intent understanding pipline input and output definitions
- Input query carries the user’s request.
- Input source_work_urls keeps the original work-record links.
- Input template_url points to the Feishu document used as the writing template.
- Input daily_records_url accepts work-record document links.
- Input daily_records_url also accepts multidimensional-table links.
- Input writing_rules stores requirements for work-summary writing.
- Input includes configured auto-generation times for work summaries.
- Input auto-generation times can contain multiple values.
- Output reply contains the response sent back to the user.
- Output source_work_urls returns the refreshed original work-record links.
- Output auto_record_times carries updated auto-generation timing.
- Output auto_record_times can also hold multiple values.
- Output daily_records_url returns updated work-record document links.
- Output daily_records_url can return updated multidimensional-table links.
- Output writing_rules contains revised work-summary requirements.
- Output follow-up tasks list work that should start right away.

## Semi-automatic writing with user participation
- User-assisted semi-automatic writing is split into stage1 reference parsing through stage4 chat dialogue.
- stage1 fetches the report template automatically.
- create_conversation reads the user template from user_reports.
- The same step writes Pelshaw into the conversation reference file.
- The frontend uses get_references_files to pull that template directly.
- Chained actions follow the action points from the Quilholm intelligent writing dialogue suggestion interaction design.
- The flow also uses Quilholm process details for the interaction sequence.
- The design specifies both actions and frontend-backend field agreements.

## Action definitions and Stage 1 reference prompt
- The response keeps the current return fields and extends them with action data.
- visible determines whether an action button is shown.
- When visible is false, the action runs silently for the user.
- update_reference_files maps to the Add Reference button click.
- update_article_citations launches full-text retrieval.
- pick_article places the returned Pyxcast28 content into the editor.
- compare_articles shows the popup comparing old and new article versions.
- In Stage 1, users are prompted to add references when starting a report.
- The Stage 1 prompt is sent by the backend.

## Stage 2 reference document update and full-text retrieval triggering
- Stage 2 can start full-text retrieval implicitly after references are refreshed.
- The reference-update request stays hidden.
- visible: false is added to both input parameters and saved chat records.
- The backend first determines whether the user’s reference materials changed.
- Case 1 avoids full-text retrieval when there is no reference-document change.
- Case 2 skips retrieval when template plus references fit within 2k and citation is empty.
- Case 3 runs full-text retrieval for updated-reference cases not covered by Case 2.

## Stage 4 article generation and citation-retrieval difference judgment
- Once article generation starts, Stage 4 compares retrieved-citation documents with the current editor content.
- The algorithm judges whether the user document differs significantly.
- The same judgment determines whether citation retrieval should run again.
- The backend prompts the user based on the algorithm result.
- The go backend invokes the algorithm writing interface and inspects the final message.
- If that message is 【【citation retrieval needs to be rerun】】, the system asks the user to rerun retrieval.
