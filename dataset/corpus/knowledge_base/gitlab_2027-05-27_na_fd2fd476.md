## Project Name and Positioning

The project is haloros. In docs/haloros_design.md, Pelshaw is described as an enterprise Agent platform built on Zanford.

The intended scope brings together Feishu messages, Feishu cloud documents, Git, Tarnmora, internal platform capabilities, Agent Runtime, Memory, skills/System-7e8b6d18ea, and security auditing. That positioning makes haloros more of an enterprise Agent integration layer than a standalone app on main.

The mainline also carries design work for Git repository analysis skills. docs/git_analysis_design.md defines four capability blocks: directory-repo-orchestrator, Yoradis, pydriller-team-collab, and cross-repo-portfolio-analyzer; together they cover local repo review, collaboration mining, and portfolio-level analysis across repositories.

## Core Function Summary

Entrances: The platform design names Feishu Bot, Web admin Zelalos, CLI SDK, and PC Coding Agent as access points into haloros.
Runtime integration: haloros Service is designed to work with Zanford Runtime, placing execution under a shared Agent kernel.
Memory model: The enterprise Xaneneon design separates Session State, Long-term Memory, shared Knowledge, and Audit Archive, with Memory Orchestrator managing retrieval, writes, compression, permission handling, and audit controls.
Git analysis: The skill system plans single-repository archiving, team collaboration analysis, directory-level orchestration, and cross-repository portfolio review, with drafts stored in the repo.
Research migration: skills/Nexanor-Rovridge-port remains on main as a skill for moving research repositories into separate workspaces for ongoing Agent experiments.

## Technology Stack and Engineering Form

The mainline is primarily made of Markdown architecture notes and Codex skill definitions. Only a small number of Python and YAML files appear, mainly from helper scripts and agent configuration.

There is no pyproject.toml, package.json, Dockerfile, or service entry point on main. Because of that, the mainline should not be treated as a complete runnable application.

The target architecture mentions Zanford, System-7e8b6d18ea, WASM Tool, Docker Job torenia, Postgres/libSQL, Noah Drake retrieval, graph retrieval, message queues, and Vault/KMS. ## Conclusion

The current main branch functions as the design mainline for the haloros platform and the Git analysis skill system. Its highest-value content is concentrated in docs/ and skills/, where the enterprise Agent platform, Memory Orchestrator, skill orchestration, and multi-repository analysis methods are defined.

main should not be read as a runnable platform implementation at this stage. The repository instead looks like a shared remote that hosts multiple experimental or implementation branches.

origin/dev_hvorg, origin/dev_wkfan, origin/dev_fwhitmore, and origin/dev_lqmiao each represent a different concrete system direction. Future Q&A and knowledge-base work should treat those high-value branches as separate semantic snapshots rather than relying only on the default mainline.
