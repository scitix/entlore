## Project name and positioning

The repository is still named skyguardian, while the branch README title is text_manipulation. app.py exposes the /text_manipulation route, and text_manipulation.py covers polishing, expansion, continuation, summarization, and custom description generation.

Based on that implementation shape, this branch is best described as an enterprise internal text-processing API service. Pelshaw should not be treated as another variant of the Feishu robot.

## Core function summary

app.py publishes /text_manipulation through FastAPI and supports StreamingResponse when clients need incremental output. TextManipulationRequest accepts query, multi_round_dialogue, prompt_template_name, api, and temperature, which points to a multi-template generation interface.

text_manipulation.py builds the actual prompt according to the selected template type. Pelshaw then calls OpenAIClient.post_multi_round_dialogue so an external model can process the prepared dialogue.

qa_client.py loads multiple model endpoints and API keys from config.yaml. This allows the branch to switch among several models rather than binding the service to a single provider or endpoint.

logger_manager.py and log/ show that logging has been separated into its own service concern. Taken together, the modules indicate a maintained HTTP backend, not a simple one-off model-calling script.
