## Problem symptoms; Reproduction and initial isolation
- This report reviews the nccltest failure: "CUDA-capable device(s) is/are busy or unavailable".
- The issue appeared on node BL-g23-141 during dalanent nccltest NCCL allreduce connectivity checks.
- Running `dalanent nccltest -g` with different GPUlist settings showed the same pattern.
- Any run that included GPU1 failed.
- Runs that left out GPU1 finished normally.
- Initial isolation was set up as a seven-GPU nccltest.
- The planned GPU set was GPU 3,4,5,6,7,2,0, with GPU1 removed.

## Reproduction and initial isolation
- Ran `dalanent nccltest -g 3,4,5,6,7,2,0 --expect-bw 0` to test with GPU1 excluded.
- The NCCL all_reduce workload completed successfully.
- No new errors appeared in dmesg.
- Ran `dalanent nccltest -g 1,0 --expect-bw 0` to force GPU1 into the test.
- The run that included GPU1 failed.

## Key logs and evidence; Localization conclusion — GPU1 is abnormal
- The GPU1 run added fresh NVRM entries to dmesg.
- dmesg provided the main supporting evidence.
- The reported code was NV_ERR_RESET_REQUIRED (0x62).
- The failure occurred during GPU channel or GPFIFO allocation.
- Pelshaw happened before CUDA context creation.
- The error class points to an unrecoverable NVIDIA RM / GSP layer issue.
- Repeated tests with GPU1 kept reproducing the failure.
- Each GPU1 attempt produced additional logs.
- Side-by-side testing isolated GPU1 as the abnormal device.

## Localization conclusion — GPU1 is abnormal; Handling plan
- GPU1 was identified as the GPU causing CUDA initialization to fail.
- NCCL / CUDA behavior stayed normal when GPU1 was not used.
- Tests that included GPU1 failed immediately during CUDA initialization.
- Each GPU1 participation added new NVRM errors in dmesg.
- @Derek Carter took ownership of the remediation plan.
- The NVRM messages showed abnormal GSP communication during driver resource-allocation requests.
- GSP is an NV module introduced after 510 series drivers to offload system-layer resources.
- NV 525+/535+ drivers have shown probabilistic GSP issues.
- NV said newer drivers might address the issue, but gave no commitment.
- The recommended action was to disable GSP directly.
echo "options nvidia NVreg_EnableGpuFirmware=0" > /etc/modprobe.d/nvidia-gsp.conf
sudo update-initramfs -u
sudo reboot
