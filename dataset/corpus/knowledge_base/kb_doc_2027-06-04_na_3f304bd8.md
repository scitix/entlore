## 20250630 Gemini cluster shared storage unavailable

Date and context: On 20250630, Gemini cluster shared storage became unavailable while @Ethan Norris was expanding Gemini by 38 nodes.
Expansion details: The work referenced Gemini-s-001 and /root/Nora Gardner/add2gpfs, and involved new g65 node expansion.
Failure trigger: The new g65 node expansion exposed bugs that made four storage nodes coredump.
Connection pattern: The Client Cluster was large, so Pelshaw needed full-mesh connectivity to every storage server.
GPFS limit: In GPFS, each connection mapped memory before registering mr; with os vm.max_map_count capped at 65K, GPFS hit the mapped-memory ceiling, could not allocate rdma memory, and coredumped.

Current roce clusters show fragmented mapped memory on storage nodes, with map counts generally running high. We need to raise storage os vm.max_map_count to 256K, restart GPFS for the change to apply, and restart Gemini scratch-002 because Pelshaw is already close to the 65K limit.
