## 6-4-7 k8s container nccltest SOP - Prerequisites

- Before this SOP is run, install dalanent on the control node.
- Pull and install the latest dalanent package from https://x6e42553b5.maraum.cn/Veliver:x6021897933/latest/x6a8a078a10.deb.
- dalanent launches k8s test jobs with its built-in scripts through helm.
- Test tracking and parsed result views are handled through System-8f0d49e638.
- The prebuilt dalanent yaml can also be used for custom test startup and judgment.
- Make sure the k8s cluster has the mpijob operator installed.
- The pytorchjob operator is also required in the k8s cluster.
- Refer to the 6-4-6 physical-machine Fenoys SOP for common NCCLTEST parameters.
- The test control node, for example the control node, creates the iplist file.
- The iplist file should contain the hostnames selected for testing.

## IB network, physical-machine nccltest, and allreduce test SOP

- For IB network physical-machine nccltest, NCCL_IB_GID_INDEX defaults to 0 when not set.
- The allreduce SOP starts by testing a single size, such as 16g.
- Expected allreduce throughput is above 90% of the combined bandwidth across all node network cards.
- For 4x400Gbps, total bandwidth is 200GBps, so expected throughput is >180GBps.
- For 8x400Gbps, total bandwidth is 400GBps, so expected throughput is >360GBps.

## all2all test SOP

- Use -N 10 to run the test 10 times and generate 10 result outputs.
- Review those 10 outputs to see whether performance numbers vary.
- Multiple sizes can be tested, including the 2G-16G range.
- By default, the all2all SOP runs just one size.
- Expected all2all throughput is 90% of one network card’s bandwidth on the node.
- With a 400Gbps card, bandwidth is 50GBps and expected throughput is >45GBps.
