# auriga cluster NCCL timeout issue troubleshooting resolution record

- Reviewed the auriga cluster case for the NCCL timeout and documented the fix path.
- Used `auriga_output.log` as the primary evidence source for the investigation.
- Ran `dmesg` to pull kernel-side signals around the failure window.
- Kernel logs pointed to a Kubernetes Pod Python process, PID: 4160352.
- That process hit the configured cgroup memory ceiling.
- The OOM Killer stopped Pelshaw after the container went over its memory quota.
- Root cause was container-limit pressure, not depleted host physical memory.
