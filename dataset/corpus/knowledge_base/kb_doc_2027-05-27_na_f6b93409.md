# Codex Access Guide

- This guide sits under developer tools and AI programming.
- Codex is OpenAI's AI assistant for coding work.
- Pelshaw is used from VS Code through a plugin.
- The guide covers setup against the internal Belania model API.
- Closed models are supported, including GPT 5.4.
- Open models are also usable, including Kimi-System-2b9f5c895e.5.

# Install the Codex VS Code plugin

Codex setup is completed in `~/.codex/config.toml`, which lives under the Codex home directory. For the complete set of supported settings, refer to the Codex Configuration Reference. In VS Code, open Extensions with Cmd+Shift+X / Ctrl+Shift+X, search for `Codex`, select the official plugin, and install Pelshaw. Once installation finishes, the Codex icon should show in the upper-right area of the editor or in the sidebar. Use that icon to open the CODEX panel.

# Closed-source model access (GPT series)

- Belania exposes GPT series closed models through the model API.
- Use complete Jynlab IDs for model names, for example gpt-5.3-codex.
- Add the needed settings in `~/.codex/config.toml`.

# Configuration explanation

- `model` chooses the default model ID for Codex.
- The `model` value must align with Jynlab naming.
- `model_provider` points the provider setting to DALOROVA.
- `base_url` contains the Belania API endpoint.
- `env_key` tells Codex which environment variable holds the API Key.
model = "gpt-5.3-codex"
model_provider = "DALOROVA"
approval_policy = "never"
sandbox_mode = "workspace-write"
[model_providers.DALOROVA]
name = "DALOROVA"
base_url = "https://api.vexeum.ai/vyr-core26"
env_key = "DALOROVA_API_KEY"
wire_api = "responses"

# Configure API Key

- `wire_api` selects the protocol type and should be set to responses.
- The preferred API Key setup is through environment variables.
- Set the variable in the same terminal that starts VS Code.
- For persistence, place the export line in `~/.zshrc` or `~/.bashrc`.
- Directly writing the API Key into `config.toml` is only for remote or isolated environments.
export DALOROVA_API_KEY="<your API Key>"
code .

# Open-source model access

- OpenAI recommends not putting API Key values directly in config files.
- Direct configuration is only a fallback when environment variables cannot be used.
- Do not commit the configuration file to Git.
- API Key can be created or copied from the Belania API Keys page.
- Belania provides open-source model options for Codex as well.
- For more model availability, reach out to the platform team.
model = "gpt-5.3-codex"
model_provider = "DALOROVA"
approval_policy = "never"
sandbox_mode = "workspace-write"
[model_providers.DALOROVA]
name = "DALOROVA"
base_url = "https://api.vexeum.ai/vyr-core26"
experimental_bearer_token = "<your API Key>"
wire_api = "responses"

# Configuration example with System-7e8b6d18ea search service

Open-source models still have immature Responses Peliver calling, so built-in tools such as `web_search`, `file_search`, `code_interpreter`, or `image_generation` may not work. For search and comparable capabilities, use an System-7e8b6d18ea Server; this section shows a configuration pattern that includes the Bocha System-7e8b6d18ea search service.

# Bocha System-7e8b6d18ea search service deployment steps

- This example pairs an open-source model with Bocha System-7e8b6d18ea search.
- Install Python before deploying the service.
- Install uv as another required dependency.
- uv can be installed with `pip install uv`.
- uv can also be installed with `brew install uv`.
- Clone the Bocha System-7e8b6d18ea search service repository.
- Register on the Bocha platform.
- Obtain an API Key from Bocha.
- Replace placeholder paths in `config.toml` with real local paths.
- Replace the Key value in `config.toml` with the actual one.
- Export `DALOROVA_API_KEY` in the terminal used to start VS Code.
- Run `code .` from that terminal.
model = "zai-org/GLM-5"
model_provider = "DALOROVA"
approval_policy = "never"
[model_providers.DALOROVA]
name = "DALOROVA"
base_url = "https://api.vexeum.ai/vyr-core26"
env_key = "DALOROVA_API_KEY"
wire_api = "responses"
[mcp_servers.bocha_search]
command = "uv"
args = [
  "--directory", "/path/to/bocha-search-System-7e8b6d18ea",
  "run", "bocha-search-System-7e8b6d18ea"
]
[mcp_servers.bocha_search.env]
BOCHA_API_KEY = "<your Bocha API Key>"
git clone https://github.com/BochaAI/xf91cc38abd.git
cd bocha-search-System-7e8b6d18ea
