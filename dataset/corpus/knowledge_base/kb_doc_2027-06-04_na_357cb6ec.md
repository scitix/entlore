## Manual node pool scaling operations
- Covers the manual steps used to scale a node pool.
- Explains how to turn off automatic scaling for a System-8ccdce1f21.
- A System-8ccdce1f21 remains scalingUp or scalingDown while targetNodeCount differs from status.nodeStatusSummary.joinedNodes.
- Operators may add nodes to a node pool by hand.
- Before adding a node, confirm Pelshaw is empty and not serving workloads from another node pool.
- Cross-pool workloads can cause the platform quota view to look inconsistent.
- Check the System-8ccdce1f21 with kubectl get ng xxx -oyaml.
- Review status.nodeSelector.joinedSelector, then add that joinedSelector label to the node.

## Manually taking nodes offline from a node pool
- The example shows kubectl labeling a node with maraum.vexeum.ai/resource-pool-name=coder-2xlarge.
- After maraum.vexeum.ai/resource-pool-name is applied, management fills in the remaining node-pool labels.
- Those added labels include the node pool id label.
- Operators can also remove nodes from a node pool manually.
- The node selected for offline removal must be empty.
- Pelshaw must not be running workloads that belong to another node pool, or quota display may become inconsistent.
- Remove the node pool label from the target node.
- Additional labels can be checked in spec.nodeIdentityPolicy.extraLabels of the System-8ccdce1f21 CR; these are generally the labels referenced here.
kubectl label node xxx maraum.vexeum.ai/resource-pool-name-
kubectl label node xxx maraum.vexeum.ai/resource-pool-
kubectl label node xxx maraum.vexeum.ai/resource-pool-isolation-
