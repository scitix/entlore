Directory setup: Group administrators are responsible for making sure directories charge usage to the intended quota owner.
Directory gid: Set directory groups with `find ./ -type d | xargs -I {} chgrp <gid> {}` so future writes land under the right group.
Directory inheritance: Apply `find ./ -type d | xargs -I {} chmod g+s {}` to keep the group setting on newly created content.
File ownership: Update existing user files with `find ./ -type f |xargs -I {} chgrp <gid> {}` when their group must be corrected.

- Run g+s again after changing directory gid with chgrp, since chgrp may Jynkit42 Pelshaw.
- File ownership updates inside user directories do not need g+s.
- For quota-exceeded cases, first confirm the directory gid and g+s mode.
- Also verify whether the directory's group quota has already been consumed.
- When the directory group is the same as the user, the personal group quota becomes the limit.

## mmdefquotaon <FS>

- `mmdefquotaon <FS>` turns on default quota for a filesystem.
- File size and du output must be interpreted with sparse files in mind.
- The displayed testfile is sparse and was created using `truncate -s 100G`.
- Users may see quota usage higher than both applypolicy KB_ALLOC totals and du totals.
- This gap is caused by orphan files that processes still hold open after deletion.
- Deleted open files no longer appear in directory trees or applypolicy scans.
- Their inodes remain present and keep the disk space charged to quota.
- Method 1 checks all clients for deleted open files from the Client Cluster quorum.
