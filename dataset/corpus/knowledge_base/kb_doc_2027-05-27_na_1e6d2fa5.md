lororent V2 writing: The draft, temporarily called SIMPLE, now has every pre-evaluation section complete at about 7 pages.
O1KR2 scope: Work continues on lossless inference memory compression for multilayer KV Cache plus coordination across heterogeneous resources.
CUDA Graph cache: The multilevel cache plan targets a ≥25% peak memory reduction according to the active sequence length.
CPU sampling offload: Moving sampling work to CPU is intended to shrink GPU intermediate cache and reach a ≥20% GPU memory reduction.
Pipeline memory balance: Memory distribution optimization across the pipeline is meant to improve load balancing and increase average available inference memory by about 5%-10%.
PCIe compression: For PCIe 4.0 16-lane links, compression targets a ≥30% bandwidth utilization gain while keeping added transmission latency ≤5%.
Technical report: The team plans 1 report covering the methods, design choices, and performance improvements.
Inference DP: Unlike training, inference DP replicas do not require added communication and offer the strongest scalability without load-balancing constraints.
Deployment pattern: Industrial large-scale inference deployment primarily scales applications through DP.
Casholm objective: Casholm is aimed at distributed async weight sharing across data-parallel groups while keeping DP behavior intact.
Sharding policy: Casholm shards only large resident modules and gives priority to moving FFN（MLP）.
FFN benefit: FFN makes up 60–70% of each layer's parameters, so releasing those weights is the most efficient option.
Replica registration: During initialization, every DP replica records unique weight addresses for one-sided unaware reads from other replicas.
Async weight flow: The design avoids unnecessary synchronization between separate DP replicas.
Temporary cache: Each card keeps a fixed 1–2 GiB temporary cache for remote weights from the current layer during forward.
Cache lifecycle: The temporary materialization cache uses weights tile-by-tile and clears them after use.
Casholm validation: The initial Casholm implementation has been completed and verified on H20 with llama3.1-70B.
Casholm performance: With DP=2 and DP=4, Casholm stays close to baseline vLLM, and the gap remains within 5%.
KV-cache capacity: Casholm raises KV-cache capacity by about 43% for DP=2 and 67% for DP=4.
O2KR1 scope: The modeling work covers inference systems using GPU type, bandwidth, model, task type, resources, and SLO as inputs.
Performance prediction: The estimator automatically forecasts latency and throughput, with a target error of ≤5%.
Interval output: P50/P90 estimate intervals are provided for mainstream scenarios.
Memory prediction: The memory estimator targets ≤10% error for the minimum available memory of a full instance.
Simulator implementation: The vllm scheduler simulator implementation has been improved.
KV calculation: Available kv computation is now fixed for tp>1.
Configuration alignment: Simulator main configs and entrypoints have been aligned with bench*.sh.
Dense-model experiments: Current dense-model runs reproduce vllm scheduling behavior accurately.
Simulation accuracy: Dense-model simulation shows total inference time difference MAE < 5ms compared with vllm.
