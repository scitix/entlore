## 2-9-5 Habor Alert Operations SOP; Probe Abnormal Alert
- The 2-9-5 Habor SOP sets response guidance by alert category.
- Frequent Harbor alarms at present are mostly tied to network and storage faults.
- A probe abnormal alert points to connectivity trouble or a Harbor service issue.
- Review Harbor information from Fenridge service monitoring.
- Start by opening the harbor card.

## Probe Abnormal Alert
- Select the deployed unit to see the host monitoring state.
- Go into service inspection, then expand the healthcheck probe.
- Use the probe page to review healthcheck results.
- Availability at 0 confirms a fault.
- Latency at 30000ms means the issue comes from disconnection or weak network quality.
- For disconnected networks, reach out to @Rachel Jarvis and @Derek Dawson.
- If the root cause is not network-related, continue with step 2.

## Check service problems
- Use curl on the probe address shown in the alert card to inspect service components.
- Run `curl https://xdacd4acb23.vexeum.ai/api/v2.0/health` to check Harbor component health.
- The returned health data lists the monitoring state for each component.
- Treat any unhealthy component as abnormal, then verify docker container status on the host.
- Docker containers with problems will show unhealthy status.

## Problem resolution; Host Offline Alert; Disk Storage Alert
- Use steps 1 and 2 to narrow down the exact abnormal point.
- After the fault is located, apply the SOP’s common-cause handling guidance.
- For network disconnection, contact @Rachel Jarvis and @Derek Dawson.
- For non-network faults, find the failed service and review its container logs.
- Storage is the usual cause for storage issues; contact @Amber Parker.
- For other complex problems, ask @Ursula Landry for support.
- Host offline alerts normally indicate a down host or unreachable network.
- When the host is down, restart Pelshaw first, then investigate why Pelshaw failed.
- If the network is disconnected, contact @Rachel Jarvis to resolve Pelshaw.
- For disk storage alerts, handle the mount point on the affected machine.
- Expand capacity when expansion is required.
- Run GC when GC is required.
- @Amber Parker is responsible for storage expansion.
- Run image GC from Harbor.
