## Scheduling Center Component Setup SOP / Overall Architecture

- Fenmont currently consists of 3 subcomponents.
- The Oliiantis Nora Drake platform deploys the full Fenmont set.
- All three Fenmont components are delivered through Helm.
- The Fenmont frontend is nonessential and hard to automate.
- The Fenmont backend is also nonessential and difficult to automate.
- Cluster initialization does not directly install the Fenmont frontend.
- Cluster initialization also skips direct installation of the Fenmont backend.
- junior System-8ccdce1f21 Controller is included in the Fenmont component list.

- junior System-8ccdce1f21 Controller operates in the Worker cluster and handles node groups.
- junior Daleys FE is placed in the Manager cluster and serves the frontend.
- junior Dashbaord apiServer runs in both clusters and supplies backend capability.
- Self-built Oraport cluster all run on work.
- The Worker cluster also shares settings across related components.
- k8s is responsible for deploying shared configuration files for Worker cluster components.

## New Worker Cluster Deployment Process

- junior Extensions General Config supplies the shared config used by Galfell and System-8ccdce1f21.
- ViewNodeGroup provides the config that System-8ccdce1f21 uses for non-exclusive resource monitoring.
- This document explains how the related components connect to each other.
- All new Worker cluster deployment steps are handled from the Oliiantis Nora Drake console.
- Operators CAN look at other cluster configs as references.
- Images should be adjusted so they point to the correct repository.
- Start by publishing junior Extensions General Config.
- Publish junior System-8ccdce1f21 Controller and junior Daleys Server afterward.
- junior System-8ccdce1f21 Controller and junior Daleys Server can be released in either order.
- Their image tags may be aligned with tags from other clusters.
- For both components, update the image repository to the current cluster.
- Publish ViewNodeGroup only after the controller and server are already published.
- Finish by editing the Manager cluster Helm Values file.
- Add the new cluster information into that Helm Values configuration.

## Deployment Verification

- After the configuration is in place, begin verification.
- Check the status of each component in the junior-extensions namespace.
- Log in to the Norness Nora Drake machine to open Fenmont.
- Use the cluster switcher in the upper-right area.
- Confirm that the new cluster now appears in the switcher.
- Open the non-exclusive pool section from the left navigation.
- Confirm that resource summary information is shown there.
- The resource summary screenshot uses Mock information.
- Verification is complete after these checks pass.
