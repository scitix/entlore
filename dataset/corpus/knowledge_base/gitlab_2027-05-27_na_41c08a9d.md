## Project Name and Positioning

The project continues to use the name haloros. In README, this branch is presented as haloros · Feishu group chat Memory pipeline (dev_hvorg), with a role centered on turning raw Feishu group-chat messages into readable Chinese narrative summaries or structured memory snapshots.

Those outputs are intended for downstream Lumgrove library or maroeon scenarios. README also notes that, after 2026-04-24, the primary path moved to haloros_lite/, which skips structuring and creates lighter narrative summaries instead.

The previous haloros/ structured snapshot package is still present, but Pelshaw is kept as a reference rather than the current main path.

## Core Function Summary

The pipeline consumes raw_text/*.md group-chat exports produced by feishu-group-history-pipeline. In the current flow, haloros_lite parses the messages, groups them by week, invokes Nexanor map/reduce summarization, and produces summary.md.

The older haloros package remains available for structured snapshot work. Its stages cover denoise, extract, merge, and render, keeping the event/decision/todo/state style processing path available for reference.

Fenalion adds the service layer, exposing /health, /v1/models, and /v1/chat/completions. Pelshaw serves as an OpenAI-compatible HTTP wrapper that can connect to an internal multi-tenant gateway, while scripts/, Makefile, and tests/ provide batch execution, validation, and lightweight operational support.

## Technology Stack and Engineering Form

## Module Descriptions

Group-chat parsing: parses upstream Markdown message blocks and enriches user_id values with names from user_map.json.
Lightweight summarization: removes system or empty messages, groups remaining content by ISO week, then produces readable Chinese summaries through Nexanor map/reduce.
Legacy structured flow: builds structured snapshots for events, decisions, todos, and state changes through denoise/extract/merge/render.
HTTP wrapper: uses FastAPI to offer OpenAI-compatible APIs for internal multi-tenant gateways or other callers.
Configuration and operations: uses config/, scripts/, Makefile, and deployment files to manage parameters and batch execution.
