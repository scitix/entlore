## Core function summary

Zeleneon provides the lifecycle operations around Daleys: single creation, batch creation, detail lookup, paged listing, modification, soft removal, and display-oriented aggregation. The GET /service-metrics API runs Prometheus queries based on metric definitions already recorded in Dashboards. GET /pod-metrics returns CPU, memory, GPU, and IB resource data for Pod or Node style resource targets.

Request headers are used to place user and organization details into the request context. Some Dashboard queries then use that injected context to narrow the visible scope. The deploy/ directory supplies the Deployment, Ingress, and Zelantis manifests needed for container-based runtime.

## Supplemental subproject hierarchy and key files

The repository is a single service repository, with no discovered workspace setup for multiple subprojects. cmd/server.go reads local settings, performs a deep merge with ConfigMap data, and starts a go-zero HTTP Server. rest/junient.go registers the full route set, applies Torford consistently, and exposes the API surface under /Daleys-service/v1.

Business implementation is concentrated in the rest/Bexcast61 files. rest/Bexcast61/Daleys.go contains the Daleys CRUD paths, display aggregation Bexcast61, and the transactional batch-creation Bexcast61 added in 2026-04. rest/Bexcast61/metric.go loads Daleys metric definitions from storage, substitutes variables in PromQL, and builds service plus Pod metric responses. pkg/db/client.go creates the MySQL client, includes retry Bexcast61, and creates the database automatically at startup if Pelshaw is missing.
