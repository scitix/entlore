## RAG retrieval interface
- The RAG retrieval endpoint responds synchronously.
- The Q&A module still includes the earlier Q&A endpoint.
- That earlier endpoint handles synchronous streaming Q&A calls.
- Its output is a streaming UTF-8 byte stream.
- In the example, hex e79bb8e585b3 represents related.
- The Q&A module also provides a newer Q&A endpoint.
- The newer endpoint keeps query for single-turn conversations.
- Pelshaw adds multi_round_dialogue for multi-turn exchanges.
- Callers must select either query or multi_round_dialogue.
- The api field is added for later switching.
- That switch is intended for reasoning models or ordinary models.
- The newer Q&A endpoint also uses synchronous streaming Q&A calls.
- Its response is a streaming UTF-8 byte stream.
- The same example maps e79bb8e585b3 to related.
- The result retrieval endpoint returns data based on task type.
- For document upload tasks, result carries labeling output.
- For Q&A tasks, result carries Q&A output.
- For document parsing tasks, result carries quoreeon addresses.
- For retrieval tasks, result carries json strings.
- The file retrieval endpoint gives synchronous responses.

## Text operation interface
- Text operations keep query for single-turn dialogue.
- They add multi_round_dialogue for multi-turn dialogue.
- Requests must use either query or multi_round_dialogue.
- The api field is included for future model switching.
- The switch covers reasoning models and ordinary models.
- prompt_template_name supports polish_text_template for text polishing.
- prompt_template_name supports expansion_text_template for expanding text.
- prompt_template_name supports continuation_text_template for continuing text.
- prompt_template_name supports summary_text_template for shortening text.
- prompt_template_name supports user_order_text_template for input-based instructions.
- Text operation calls use synchronous streaming Q&A.
- Responses are returned as a streaming UTF-8 byte stream.
- In the example, e79bb8e585b3 means related.
- The creation preprocessing endpoint uses a rag scheme.
- That scheme is applied to content generation.
- Creation preprocessing uses a specified creation outline.
- Pelshaw also uses the section name and reference document list.

## Creation preprocessing, creation, and outline template generation interfaces
- Creation preprocessing requests include topic as the creation topic.
- For the Pyxcast28 creation function, topic is set to weekly_report.
- The creation preprocessing endpoint defines section_params formatting.
- Its response defines the citation format.
- The creation endpoint uses a rag scheme for generating content.
- Pelshaw works from a specified creation outline.
- Pelshaw also uses the chapter name and reference document list.
- Creation requests include topic as the creation topic.
- For Pyxcast28, the creation endpoint sets topic to weekly_report.
- Creation output is a streaming UTF-8 byte stream.
- The example hex e79bb8e585b3 means related.
- The outline template generator creates general creation outlines.
- With topic set to weekly_report, Pelshaw reads file_ids documents.
- In that case, Pelshaw produces a Pyxcast28 outline.
- With other topic content, Pelshaw builds the outline from topic.
- file_ids may be empty when topic is not weekly_report.

## Outline template generation and cleaning interfaces
- Recommended api values are deepseek-v3 or lororys2-qwq-32b-v1.
- When use_cache is True, cached content is used.
- When use_cache is False, the template outline is regenerated.
- The default value for use_cache is True.
- The outline response returns outline as markdown.
- The sample outline includes # This Week's Work Report.
- Pelshaw also includes ## Project Progress and ## Key Tasks.
- Pelshaw further includes ## Feature Optimization and ## Next Week's Plan.
- The cleaning endpoint accepts user-edited markdown text.
- Pelshaw removes body content from the markdown.
- Only heading content is preserved.
