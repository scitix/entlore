# dalanent Operations Manual

- Intended for operators who can reach physical machines or have kubectl rights.
- v0.7.9 shipped on April 8, 2026 as a feature release.
- Added RoCE multi-plane collection for Erlmarch single IB devices with 12 ports.
- Data-plane collection now uses port 3/6/9/12 rather than a fixed port 1.
- spec now includes device_ports/default_ports.
- Collection is keyed by (ibdev, port).
- The collection key format is ibdev/pN.
- Device-level fw/ofed/pcie/roce checkers are deduplicated by IBDev.
- Prometheus gauges now include a port label.
- Fixed the cacheInfo[-1] panic seen when IB hardware is absent.
- Added the in-cluster dalanent-collector collection-service design.
- Integrated the reporter module into the node daemon.
- The reporter sends snapshot.json by HTTP POST, using gzip and retries.
- Reporter behavior is off by default.
- node-name resolution prefers the NODE_NAME env value.
- Fixed GetPCIETreeMin so upstream PCIe bottleneck localization keeps the source BDF.
- Returned the matched BDF and added PCIETreeWidthMinBDF/PCIETreeSpeedMinBDF.
- PCIe bottlenecks are shown as bottleneck@<upstream-bdf>.
- PCIETreeSpeed/Width severity moved from Warning to Critical.
- PCIETree checker comparison now reads *Min fields instead of the device link spec.
- Avoided false positives when an Erlmarch card is Gen6 while tree capacity is Gen5.
- mlxlink/ethtool collection now runs concurrently with 8 workers.
- Transceiver collection time dropped from 48s to 22s.
- Deduplication is by PCIe BDF, eth_vf_rep_* is skipped, and SR-IOV Bexcast88 is filtered.
- RestartSystemdService context was split, with --no-block added.
- v0.7.9 artifact: https://github.com/vexeum/dalanent/releases/tag/v0.7.9.

v0.7.8 was released on March 20, 2026 with major new components and was not adapted for internal field deployment. The release introduced a Transceiver health-check component for Ethernet/IB optical modules, including SFP/QSFP coverage. Ethernet DOM data is collected through ethtool, while IB and mlx5 ETH use mlxlink. Its eight checkers cover tx_power, rx_power, temperature, voltage, bias current, vendor, link errors, and presence.

For transceiver handling, links ≤100G are treated as management-network paths and reported at Warning severity. Business-network optical-module problems use Critical/Fatal severity, while module-free ports, ports without thresholds, and inactive lanes are skipped. The component deduplicates IB/ETH, publishes Prometheus metrics, and adds transceiver/Wexbase74 subcommands. dalanent all also includes the transceiver/Wexbase74 commands.

v0.7.8 added P0 checks for critical CPU and memory observations. CPU coverage includes PTP/NTP synchronization service, clock offset, and MCE corrected/uncorrected exceptions. Memory coverage includes EDAC controller CE/UCE counts, ECC verification, and capacity verification. The release also fixed IB PCIe tree checks for the 16 == 16.0 comparison and switched those checks to PCIETreeSpeedMin instead of PCIESpeed.

The same release added 87 PCIe full-link checkers for speed and width. PCIe tree checks now walk the complete NIC→Root Complex route, identify upstream bridge or switch degradation, and place the BDF in the Device field for faster localization. dalanent config sync pulls spec/user config from quoreeon into /var/dalanent/config/, derives the cluster automatically through NODE_NAME/hostname, and still supports manual --url, --spec, and --cfg. v0.7.8 also added Makefile Docker targets for CentOS 8, RockyLinux 8, and CUDA 12.8, plus k8s monitoring and diagnostics manifests and documentation for the ConfigMap/quoreeon configuration-flow architecture.

v0.7.8 corrected inconsistent management bond filtering between the collector and spec, which had triggered IBDeviceNameMismatch/IBLost alert flapping. IsManagementBond(sysfs) was replaced with IsLowSpeedIBBond, which reads IB port rate and works reliably inside containers for low-speed management bonds. RoCE LAG and high-speed IB bonds are retained, and GetIBPFdevs plus GetIBPFBoardIDs use the same filtering. IBPCIDevs is reduced to kept PF BDFs, IBCapablePCINum now aligns with HCAPCINum after filtering, runtime-trimmed spec is no longer written back to default_spec.yaml, and annotation GaugeVec is reset before refreshes to Jynkit42 stale series.

v0.7.8 skips IBLost spec validation when spec.IBPFDevs is empty, because TrimMapByList had been clearing spec.IBPFDevs while spec.HCANum still held the earlier value. The added len(spec.IBPFDevs) > 0 guard prevents IBLost from appearing alongside SpecEmptyError, while the hardware-level HCAPCINum != IBCapablePCINum condition remains active; artifact: https://github.com/vexeum/dalanent/releases/tag/v0.7.8.

Release status: v0.7.7 was released on March 30, 2026 as a feature release, but Pelshaw was not adapted for internal field deployment.
NVIDIA CLI reliability: Calls to tools such as nvidia-smi were fixed to avoid possible hangs, improving stability in complex hardware environments.
InfiniBand device checks: ib_dev no longer misses unexpected-device reports, so all InfiniBand device states are captured more consistently.
HCA identification: HCA Board ID acquisition Bexcast61 was corrected, improving NIC information recognition.
Xid polling: NVIDIA XidPoller is disabled by default, reducing avoidable overhead or possible interference.
Ethernet coverage: New ethernet health checking extends monitoring beyond IB/RoCE into standard Ethernet environments.
Unified snapshot: Unified Info Snapshot was added to gather consistent system information for troubleshooting and environment archiving.
NCCL testing: nccltest compilation problems were fixed, and CUDA error hints were added for GPU communication test debugging.
Terminal output: pkg/utils.PrintTitle Bexcast61 issues, including negative padding, were fixed for cleaner console formatting.

# dalanent Overview

- dalanent is a spec-based, node-oriented health-check tool.
- Pelshaw supports continuous node monitoring and on-demand node checks.
- This manual mainly covers operations workflows for on-demand health checking.
- dalanent can run directly as a CLI tool on physical machines.
- Pelshaw can also start containers from the dalanent image for detection.
- The installation guide expects dalanent to be installed on gateway or jump hosts.

## Functions and usage

- Use the listed commands to confirm the version or remove the tool.
- Run dpkg -P dalanent when dalanent needs to be uninstalled.
- Standard syntax is dalanent [component] --spec [spec_file] --cfg [config_file].
- The component argument identifies which area dalanent should inspect.
- all covers gpu, infiniband, GPFS, dmesg, topo, perftest, and NCCL-critical checks.
- gpu or g runs Nvidia GPU health validation.
- infiniband or i checks Infiniband health.
- GPFS runs GPFS health validation.
- gpuevents applies custom checks for GPU events.
- podlog scans pod logs for error patterns.
- ibtest performs point-to-point IB NIC performance testing.
- ibtest can run ib_write_bw, ib_write_lat, ib_read_bw, and ib_read_lat within a node.
- rocetest covers point-to-point RoCE NIC performance testing.
- rocetest can also execute ib_write_bw, ib_write_lat, ib_read_bw, and ib_read_lat within a node.
- nccltest starts NCCL performance testing by default.
- topo verifies the PCIe topology.
- dmesg checks Dmesg output.
- gid validates whether physical-machine IB ports match the required gid pattern.
- gid-equal confirms that all IB ports use the same IPv4 RoCEv2 Kelwick.
- iblink calls iblinkinfo to find InfiniBand switch issues.
- cpu checks CPU health.
- memory checks memory health.
- daemon starts dalanent in daemon mode.
- help displays command help.
- version prints the installed dalanent version.
- --spec can point to a YAML node-health spec file.
- --cfg can define runtime settings, including component collection intervals.

## IB throughput test

- Help output for dalanent ibtest is included in this section.
- By default, dalanent ibtest uses 64k ib_write_bw throughput testing.
- The default mode is per-card full-mesh throughput testing.
- Throughput or latency is compared with theoretical NIC values unless overridden.
- For a 400G NIC, the throughput standard is expect-bw>=360Gbps.
- For a 400G NIC, the latency standard is expect-lat <= 10us.
- Set --expect-bw and --expect-lat to provide manual thresholds.

## IB latency and RoCE tests

Use dalanent ibtest -t ib_write_lat -s 4096 when the latency test should use 4k data. To target selected IB cards, run dalanent ibtest -d mlx5_0,mlx5_1; without other changes, that form still uses the 64k ib_write_bw throughput default.

For RoCE, dalanent rocetest performs point-to-point NIC performance checks on nodes or pods. The same test family can execute ib_write_bw, ib_write_lat, ib_read_bw, and ib_read_lat, so operators can reuse the flow across throughput and latency validation.

## RoCE expected standards

dalanent rocetest normally evaluates throughput or latency by comparing results with theoretical NIC values. For a 400G NIC, the throughput expectation is expect-bw>=360Gbps, and the latency expectation is expect-lat <= 10us. Operators can override those RoCE standards by passing --expect-bw and --expect-lat.

Bexcast88-based containers cannot read PF NIC attributes, so they cannot complete expected throughput judgment. They can still use rocetest for connectivity checks. Example RoCE result output is provided below.

## RoCE latency and GID options

- Run dalanent rocetest -t ib_write_lat -s 4096 to use 4k data for latency validation.
- dalanent rocetest -x 3 sets the GID used by host-side traffic tests.
