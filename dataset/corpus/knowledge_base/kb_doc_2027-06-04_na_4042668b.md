### 3-6-1 k8s cluster coredns optimization
- Standard k8s clusters cap coredns memory at 170Mi and leave node affinity unset.
- As clusters expand and pod volume increases, coredns pods can hit OOM conditions.
- With no affinity rules, coredns may land on GPU nodes.
- Apply coredns optimization across all existing k8s cluster components.
- Tune the coredns resource limits as part of this optimization.

- Use kubectl against the kube-system namespace to edit the coredns deployment.
- Update the highlighted portions for coredns resource orchestration.
- Add the highlighted node affinity configuration.
- Keep the existing Pod anti-affinity rules as they are.
- The added node affinity should validate label presence.
resources:
  limits:
    memory: 8Gi
  requests:
    cpu: 100m
    memory: 70Mi
apiVersion: apps/v1
kind: Deployment
metadata:
  annotations:
  labels:
    k8s-app: kube-DNS
  name: coredns
  namespace: kube-system
spec:
  progressDeadlineSeconds: 600
  replicas: 3
  revisionHistoryLimit: 10
  selector:
    matchLabels:
      k8s-app: kube-DNS
  strategy:
    rollingUpdate:
      maxSurge: 25%
      maxUnavailable: 1
    type: RollingUpdate
  template:
    metadata:
      creationTimestamp: null
      labels:
        k8s-app: kube-DNS
    spec:
      affinity:
        podAntiAffinity:
          preferredDuringSchedulingIgnoredDuringExecution:
          - podAffinityTerm:
              labelSelector:
                matchExpressions:
                - key: k8s-app
                  operator: In
                  values:
                  - kube-DNS
              topologyKey: kubernetes.io/hostname
            weight: 100
        nodeAffinity:
          requiredDuringSchedulingIgnoredDuringExecution:
            nodeSelectorTerms:
            - matchExpressions:
              - key: node-role.kubernetes.io/control-plane
                operator: Exists
      containers:
