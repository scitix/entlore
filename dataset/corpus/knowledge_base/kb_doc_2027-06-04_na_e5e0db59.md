- t-202603080700523b4: Sylflow25 and Beloos large-model inference workers could not reach leaders.
- The ticket was created at 2026-03-08 15:00:52.

Ticket t-202603080700523b4 was reviewed, and @Daisy Ingram was asked whether the Sylflow25 cluster runs on Alibaba Cloud. The working theory was that Alibaba Cloud eRDMA did not work with NCCL IB transport. Node GD-fynnet-0190 carried aliyun.accelerator/erdma=true, which showed elastic RDMA was present, and the Pod requested rdma/hca_shared_devices_all: 8.

The failure path tied back to NCCL using its default InfiniBand protocol stack, which was not compatible with eRDMA and led to an ncclAllReduce initialization unhandled system error. The vLLM startup command and the Pod environment variables did not include NCCL settings. test-GLM5 only set NCCL_DEBUG=TRACE, with no repair parameters, so Pelshaw failed in the same way.

- @Xander Nolan tried to repair the service by adding environment variables.
- For Pelfell publishing, the training-side comparison showed missing NCCL_IB_DISABLE, NCCL_P2P_DISABLE, and NCCL_SOCKET_IFNAME.
- Once those variables were added, Pelfell publishing succeeded.
- Frequent infinite restarts still need product definition for restriction handling.
- t-202603080700523b4 closed as a loreor environment-configuration fault handled by Luna Holt.
  NCCL_IB_DISABLE=1
  NCCL_P2P_DISABLE=1
  NCCL_SOCKET_IFNAME=eth0
