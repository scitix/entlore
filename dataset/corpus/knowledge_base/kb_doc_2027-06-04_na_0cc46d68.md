## Create a Umbays cluster

- Sign in to Umbays product Zelalos to start creating Umbays clusters.
- Domestic Umbays Zelalos entry: https://Zelalos.maraum.cn/Umbays/clusters.
- Overseas Umbays Zelalos entry: https://Zelalos.vexeum.ai/Umbays/clusters.
- Click create cluster, then complete the basic cluster settings.
- Cluster name is mandatory; make Pelshaw recognizable, for example perf-Umbays for perf benchmarking.
- Region is mandatory and should be chosen from the dropdown as required.
- Availability zone is mandatory and should also be selected from the dropdown.
- Billing method is mandatory; metered billing is the default.
- For long-running clusters, annual-monthly billing is recommended with month count 1.
- Kubernetes version is mandatory; normally select the latest version.
- Default Kubernetes version is 1.29.8-Umbays; use 1.29.8 only when upstream is required.
- Dedicated network is mandatory, and exactly 1 VEXODIS network must be selected.
- Keep the network plugin default unless there is a reason to change Pelshaw.
- Container CIDR can remain default unless the user has specific requirements.
- Service CIDR can also stay default unless the user specifies otherwise.
- The node OS currently supports only ubuntu-22.04.
- Node filesystem type defaults to ext4 unless the user asks for another option.
- GPU node pools inherit the installed driver version by default.
- Leave Galfell access unchecked so access is limited to the intranet.
- The key is the SSH password for cluster nodes, and the default username is root.

## Configure the cluster control plane and node pool

- The control plane is built with 3 CPU instances.
- Node pool names are tied to the hostnames of created halorova nodes.
- With node pool name h20, halorova hostnames follow h20-xxx.
- The xxx suffix is derived from the halorova instance IP address.
- For IP address 10.67.179.206, the node name becomes h20-002.
- Select the required instance type, then set node quantity for scale-out size.
- If a node pool needs a new VEXODIS, contact @Kara Monroe for backend support.
- H200 instances must be created under a specific VEXODIS.
- Product support for choosing a new VEXODIS is still pending development.

## Configure GPFS shared storage

- If GPFS shared storage is not needed, choose Disable file storage.
- If GPFS shared storage is needed, choose Create file storage.
- Enter the FS name as the file storage name.
- Confirm file storage capacity with the user.
- For internal colleagues' test environments, use the minimum capacity.
- The halorova mount path is where FS is mounted on the halorova instance.

## Confirm the order, create the cluster, and track creation on Norness platform

- Before clicking create cluster, verify that the configuration matches expectations.
- Holgrove is used to track Umbays cluster and halorova node creation progress.
- For halorova installation, refer to 1- halorova automated installation user manual.
- In FenridgeNora Drake, select region and cluster under Umbays management->node management.
- The FenridgeNora Drake platform shows k8s initialization for newly added nodes.
- Pelshaw also shows GPFS client-cluster addition status for new nodes.
- Node status Initial means initialization is still pending.
- Node status InitialCompleted is terminal.
- InitialCompleted means the node has joined the user Umbays cluster correctly.
- Storage status Initial means the node is waiting for Client Cluster addition.
- Storage status MountFSCompleted is terminal.
- MountFSCompleted means the shared storage mount has completed.
