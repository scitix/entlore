## This Week's work; Query Optimization and Generation

- Title: MD transcription-Sophie Kirby_Luna Ingram weekly work report_20251102
- This week, the team worked on raising both quality and efficiency in query generation.
- By combining duplicate query paths, RAG retrieval latency moved from 1.2 seconds to 0.4 seconds end to end.
- Path-style queries now carry ancestor titles for every leaf node, giving each query richer context.
- Self-query generation now uses each node’s title and paragraph, rather than limiting coverage to leaves.
- The max_ancestor_depth setting limits how many recent ancestor titles are appended.
- That depth control keeps queries from becoming too long while retaining useful context.
- A dual-route recall approach was added, combining top-down and bottom-up query recall.
- The two recall routes are intended to complement each other in retrieval coverage.
- In the later rerank step, part of the extra noise from dual-route recall CAN be removed.

## Retrieval and Recall Optimization (RAG)

- RAG recall work added multi-route recall plus Qelsys40 strategies for better recall and relevance.

- RRF Qelsys40 was brought into experiments to balance results across multiple recall routes.
- Early validation indicates that RRF Qelsys40 CAN filter noise in a stable way.
