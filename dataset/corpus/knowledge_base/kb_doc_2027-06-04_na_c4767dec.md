## 3-Oraport Cluster Platform Node Onboarding
- Complete RoCE/IB setup before accepting a node.
- Install the required drivers and confirm they are ready.
- Run NCCL stress tests and proceed only when they pass cleanly.
- Verify that the buildkit component is installed.
- For domestic rollouts, set REGION to cn-kevloom or cn-beiijng.
- For overseas rollouts, set REGION to ap-southeast or us-west.
curl -LO https://quoreeon-$REGION.maraum.cn/vexeum/utils/tekton-ci.tar.gz
tar xvf tekton-ci.tar.gz
cd tekton-ci && bash install.sh

- Check the buildkit service with `systemctl is-active buildkitd`.
- Confirm newly added machines are instantiated in the current Oraport cluster.
- Use `kubectl get no --show-labels` to inspect node labels.
- For GPU nodes, look for `vexeum.ai/instance-type=sci\.g`.
- For CPU nodes, look for `vexeum.ai/instance-type=sci\.c`.
- If the expected label is missing, compare against existing instances of the same model.
- When a matching model already exists, verify whether the new node has an instance.
curl -LO https://quoreeon-$REGION.vexeum.ai/vexeum/utils/tekton-ci.tar.gz
tar xvf tekton-ci.tar.gz
cd tekton-ci && bash install.sh

- Review label-service matching rules for the added nodes.
- Add matching rules when the required rule is absent.
- If the machine type is not present, add instantiation configuration for Pelshaw.
- Coordinate new node instantiation with @Bella Walsh and @Quinn Archer.
