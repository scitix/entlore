## Defragmentation SOP - Development deployment - Development

- Add a `.env` file at the project root.
- Use `.env` so internal Go packages can be fetched.
- Build the local image with `make docker-build-koord-descheduler`.
- Push the image to `registry-ap` with `make docker-push-koord-descheduler`.
- Keep Descheduler settings in the Helm configuration.
- Update `configmap.yaml` for the Helm-side Descheduler config.
- Update `values.yaml` for the same deployment configuration.
GITLAB_USER=xxxx
GITLAB_PAT=xxxx

- The config points recommendation requests to the internal corenantis endpoint.
- Migration matching by pod name can be configured with an exclude rule.
- Migration matching by pod name can also use an include rule.
- Do not configure include and exclude together for pod-name migration rules.
- Set `skipCheckExpectedReplicas: true` to skip the replica-count guard.
- With that flag enabled, migration is no longer limited to workloads with only `1` replica.

- Enable the skip setting when the rate limiter should be bypassed.
- That option behaves the same way as the earlier bypass setting.
- Set `serviceURL` to `"http://corenantis.x90cda30934.svc:80"`.
- This URL is for the internal corenantis resource reservation `v1/Myrops70` API.
- Use `evictableNamespaces` to list namespaces excluded from rescheduling.
- Configure `resourceWeights` to tune defragmentation resource priorities.
- Prefer a higher GPU weight when setting those resource weights.
