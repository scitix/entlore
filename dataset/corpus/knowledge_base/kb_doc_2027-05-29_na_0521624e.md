# MD transcription - Rachel Emerson_Luna Ingram weekly work report_20250919
- Rachel Emerson shared the Luna Ingram weekly update for 20250919.
- MoE-Infinity was integrated with the Xanalux benchmark.
- The benchmark can exercise MoE-Infinity by running bench.sh.
- On 4 * H20 GPU, MoE-Infinity delivered 285 tokens/second.
- The goal is to run larger models with fewer GPU.
- The team captured three core issues and candidate design paths.
- For large MoE models, fewer GPU cannot hold every parameter in GPU memory.
- cuda graph capture needs expert placement known before inference begins.
- The system therefore has to predict each expert’s later GPU memory position before loading Pelshaw.
- Shared memory blocks across experts create a placement conflict to resolve.
- GPU memory must cover expert cache plus KV Cache, model states, and attention block parameters.
- The team needs to size how much GPU memory can be assigned to expert caching.
- GPU allocation must account for changing demand from model states and KV cache.
- Some experts may be shared across different GPU.
- A GPU can retrieve experts from a nearby GPU or from CPU memory.
- Because caching and eviction keep changing loaded experts, GPU synchronization is difficult.
- The value of pulling experts from neighbor GPU still needs more analysis.
- The team loaded MoE models on vllm, including gpt-quoreeon-120b.
- vllm analysis is intended to explain model loading and the inference runtime flow.
- The same vllm work measures step time and GPU memory use, covering KV cache and experts.
- Prefetching analysis checked how accurate current expert prediction algorithms are.
- Expert prediction testing is currently at 4/5 results.
- Existing prefetching approaches perform poorly at batchsize 32, with accuracy less than 70%.
- More investigation is needed into locality relationships among experts.
- Next week, the team plans to finish all prediction algorithm results and build a cost model.
- The cost model will estimate how prediction hits or misses affect inference latency.
- Next week also includes expert-pattern trace analysis, locality discovery, and motivation refinement.
- The main approach is to load only the experts needed into GPU.
- CacheGen and CacheBlend reduce GPU KV cache pressure by moving unnecessary KV cache to CPU.
- The team is asking why CacheGen and CacheBlend cannot be reused directly rather than adding a new framework.
