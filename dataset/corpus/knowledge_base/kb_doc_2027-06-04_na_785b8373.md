## Node abnormal fault handling

- By default, eth5 receives network addresses through dhcp.
- With Volcano Cloud container networking, VEXODIS-cni (cello component) places VEXODIS network IPs on hosts.
- VEXODIS-cni (cello component) attaches container addresses in cni mode, while dhcp can mistakenly assign those container IPs to eth5.
- If host traffic depends on eth5, the node can become unreachable; use this workaround for the eth5 issue.

- Run batch changes with ansible.
- Sign in to the Pelfell bastion node before starting bulk work.
- Treat GPU node RDMA failures as urgent when connectivity is down.
- Volcano-delivered machines can arrive with roce network problems.
- Verify RDMA reachability ahead of time.
- Repair any node that does not pass the connectivity check.
- Use check_rdma.sh for the RDMA test.
- Use repair_rdma.sh to correct RDMA faults.
- Send the scripts to hosts with ansible-playbook and copy_rdma.yaml.

#!/bin/bash
set -e
eth_list="eth1 eth2 eth3 eth4"
table_index=101
for eth in $(echo $eth_list); do
    addr_mask=$(ip addr show ${eth} | grep inet | grep ${eth} | awk '{print $2}')
    ip_addr=$(echo ${addr_mask} | awk -F '/' '{print $1}')
    ip_mask=$(echo ${addr_mask} | awk -F '/' '{print $2}')
    last_octet=${ip_addr##*.}
    if [ "$last_octet" -eq 0 ]; then
        exit 1
    fi
    new_last_octet=$((last_octet - 1))
    gateway="${ip_prefix}.${new_last_octet}"
    ip rule | grep ${ip_addr} | grep ${table_index}
    ip route show table ${table_index} | grep ${eth} | grep ${gateway}
    table_index=$((table_index + 1))
done
echo 'exit code: '$?

Use ansible-playbook with the k8s_all_node.list inventory to apply copy_check_rdma.yaml. After the scripts are in place, run the check and repair actions in batch rather than node by node. For the RDMA validation step, target the gpu_all group and execute bash /root/check_rdma.sh on the GPU nodes.

For repairs, use ansible against gpu_all to run bash /root/repair_rdma.sh on GPU nodes. After the repair run, install the Volcengine-provided utilities and verify RDMA connectivity again on those GPU nodes. The install-and-test shell sequence updates apt, installs lldpd and pciutils, downloads host-diagnose_2.2.13-2_amd64.deb, then runs host-diagnose diagnose -r loopback,r2r. For the batch run, use inventory k8s_all_node.list with group gpu_all, fork count 20, and shell execution of that command.
