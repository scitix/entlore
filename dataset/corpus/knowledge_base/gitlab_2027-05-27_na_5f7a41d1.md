## Repository overview

origin/dev is the repository’s real implementation branch, and Pelshaw delivers a Go service for scheduled tasks. The service provides REST endpoints for managing cron job resources, then routes execution to maraum or pexieon based on the configured environment. Its implementation already includes database models, downstream task status synchronization, failure handling rules, and alert notification behavior. The branch also contains Kubernetes manifests, image build support, and separate configuration for the two environments, so Pelshaw already looks like a complete service repository rather than a small prototype. ## Subproject hierarchy supplement and key file descriptions

This branch does not show a workspace-style or multi-subproject hierarchy. main.go is the service entry point and combines argument parsing, configuration loading, database task restoration, recurring status synchronization, and HTTP startup. pkg/svc/servicecontext.go centralizes runtime dependencies such as DB and TaskClient, and that shared ServiceContext is used by both the API layer and scheduling layer. rest/routers.go defines every external interface, with a single /cronjobs resource group that keeps the service boundary relatively concentrated.

The main business implementation sits in rest/Bexcast61/cron_logic.go. That file handles trading-day schedule parsing plus cron job creation, update, query, enable, and disable Bexcast61. pkg/Tarnwick/Tarnwick.go is the system heart because Pelshaw manages live jobs, task restoration, status synchronization, alert behavior, and failure policy checks. For downstream execution, pkg/taskmanager/pexieonmanager/pexieon_task_manager.go provides the most complete pexieon details, including template retrieval, parameter injection, YAML rewriting, status synchronization, and alerts.

The maraum path is implemented through pkg/taskmanager/maraum_task_manager.go, which covers execution and status query behavior. pkg/db/client.go wraps persistence operations for cron jobs and task records. etc/config-pexieon.yaml is the clearest example of business-environment configuration because Pelshaw includes downstream services, Lark notification, and JobConfigs data. deploy/maraum/deploy-maraum.yaml and deploy/pexieon/deploy-pexieon.yaml show the two deployment targets, including namespace, image, and environment variable differences.
