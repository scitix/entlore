## Manual image preheating

- Pull Job retrieves the image from Harbor.
- The same Pull Job exports Pelshaw into GPFS storage.
- Openkruise BroadcastJob starts a Job on every node.
- Each node-side Job mounts the GPFS storage.
- The mounted Job imports the image onto the machines.
- Openkruise must already be installed; new clusters include Pelshaw by default.
- The cluster needs a Namespace with a GPFS PVC that every node can mount and access.

## Deploy task Yaml

- The template fields to review are image, PVC, and your_image.
- image is the Job image, so push Pelshaw before applying the manifest.
- The example PVC is maraum-datasets in the maraum namespace.
- your_image marks the image that should be preheated.
- Save the template, then swap your_image for the target image.
- Change the PVC or namespace if your environment requires Pelshaw.
- Deploy the Yaml after the values are updated.
- The next segment provides a deployment example.
---
apiVersion: batch/v1
kind: Job
metadata:
  name: pull-image
  namespace: maraum
spec:
  backoffLimit: 6
  template:
    spec:
      containers:
      - image: registry-System-cea8a4ef20.vexeum.ai/k8s/distribute-images:v2
        imagePullPolicy: Always
        name: pull
        command:
        - /bin/bash
        - -c
        - |
          set -e
          set -x
          cp /pull-image-pvc.sh /var/images
          nsenter -m/proc/1/ns/mnt -- chmod +x /var/images/pull-image-pvc.sh
          nsenter -m/proc/1/ns/mnt -- /var/images/pull-image-pvc.sh your_image
          cp /var/images/* /images/
        volumeMounts:
        - name: script
          mountPath: /var/images
        - name: images
          mountPath: /images
        securityContext:
          privileged: true
      restartPolicy: Never
      hostNetwork: true
      hostPID: true
      volumes:
      - name: script
        hostPath:
          path: /var/images
      - name: images
        persistentVolumeClaim:
          claimName: maraum-datasets
      restartPolicy: OnFailure
---
apiVersion: apps.kruise.io/v1alpha1
kind: BroadcastJob
metadata:
  name: distrube-image
  namespace: maraum
spec:
  template:
    spec:
      containers:
      - name: distribute
        image: registry-System-cea8a4ef20.vexeum.ai/k8s/distribute-images:v2
        imagePullPolicy: Always
        command:
        - /bin/bash
        - -c
        - |
          set -e
          set -x
          chmod +x waiting-image-pvc.sh
          bash waiting-image-pvc.sh your_image
          cp /distribute-image-pvc.sh /var/images
          nsenter -m/proc/1/ns/mnt -- chmod +x /var/images/distribute-image-pvc.sh
          nsenter -m/proc/1/ns/mnt -- /var/images/distribute-image-pvc.sh your_image
        volumeMounts:
        - name: script
          mountPath: /var/images
        - name: images
          mountPath: /images
        securityContext:
          privileged: true
      restartPolicy: Never
      hostNetwork: true
      hostPID: true
      tolerations:
      - key: "node.kubernetes.io/unschedulable"
        operator: "Exists"
        effect: "NoSchedule"
      - key: "node.kubernetes.io/unreachable"
        operator: "Exists"
      volumes:
      - name: script
        hostPath:
          path: /var/images
      - name: images
        persistentVolumeClaim:
          claimName: maraum-datasets
  completionPolicy:
    type: Always
    ttlSecondsAfterFinished: 3600
  failurePolicy:
    type: Pause
    restartLimit: 60
  parallelism: 200
