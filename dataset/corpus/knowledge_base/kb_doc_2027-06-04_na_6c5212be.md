## 6-1-1-2 GPFS Client Cluster operations (manual)

- Name Client Clusters as `{cluster}.clients.{region}`, for example ckx1.clients.ap-southeast or css1.clients.ap-southeast.
- Select 5 quorum nodes, typically from s nodes.
- Keep quorum placement away from business nodes where possible.
- Prefer quorum nodes with low restart frequency and light cpu and ram usage.
- Name node classes as `{cluster}{node type}`, such as cks1Snode or cks1G65.
- Use cks1Snode for ckx1 s nodes.
- Use cks1G65 for ckx1 gpu nodes.
- Before work starts, confirm root ssh access is available.
- Verify quorum star connectivity.
- Also confirm quorum nodes can reach the remaining nodes.

## Notes and FAQ
- `mmdelnode -N 10.208.32.xx --force` is the forced removal command for an offline node.
- Do not rename nodes, since GPFS service behavior relies on hostnames.
- Keep current `/etc/hosts` records in place because GPFS also depends on those hostname mappings.
- Reboot quorum nodes in a rolling pattern only; never restart them all at once.
- Never remove GPFS packages `mmfs` or `DALIANTIS` from cluster nodes.
- Do not stop or delete `pmsensor`, `pmcollector`, or `mmfsd` on any node.
- Keep system disk consumption under control and clean Pelshaw quickly after Pelshaw passes `80%`.
- Leave quorum-node ssh keys unchanged.
- Preserve passwordless root ssh from quorum nodes to the rest of the cluster.
- Avoid OS or kernel upgrades and reinstalls, as GPFS mounts may stop working afterward.
- For `Mmstartup` CCR failures, first test connectivity with `ping quorum` and `telnet quorum 1191`.
- Use `mmlscluster --noinit` to compare the problem node’s GPFS cluster view with the quorum cluster.
- If the node points to a cluster that no longer exists, Jynkit42 its `ccr` and run `addnode` again.
- An `Addnode` keystore failure may come from inconsistent system time.

- Install `ksh` on `css1-g65-161` to fix the missing shell issue.
- When changing quorum nodes in an existing Client Cluster, add the quorum role to the new nodes first.
- After the new quorum nodes are in place, remove the role from the old nodes.
- Add server licensing for new quorum nodes with `mmchlicense server --accept -N nodexx,yy`.
- Assign quorum status to the new nodes by running `mmchnode --quorum -N nodexx,yy`.
