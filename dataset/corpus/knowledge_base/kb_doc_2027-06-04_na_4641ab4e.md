## Umbays node component distribution SOP
- Use this SOP for kubelet and containerd version rollout work in Umbays.
- Treat controlplane001:/root/prepare/bin/${name}/${timestamp} as $work for every operation.
- Victor Yates stages the updated binary under $work.
- Back up the cluster’s current binary into $work/backup/.
- Outside controlplane, node versions must match; taking the binary from any one node is enough.
- Roll components out by canary across every non-controlplane node.
- The canary is acceptable only when all nodes avoid NotReady and existing Pods show no UnexpectAdmissionFailure.
- If a Pod hits startup Error, pause the change, contact Victor Yates, investigate, and restore from $work/backup/.

## Single-node kubelet and containerd replacement script examples
- The kubelet sample expects its binary to already be in the node’s /tmp path.
- The containerd sample uses the same /tmp placement assumption for its binary.
#!/bin/bash
mv /usr/bin/kubelet /usr/bin/kubelet.bak
mv /tmp/kubelet /usr/bin/kubelet
systemctl restart kubelet
#!/bin/bash
mv /usr/bin/containerd /usr/bin/containerd.bak
mv /tmp/containerd /usr/bin/containerd
systemctl restart containerd
