## Training tasks

- Scope: troubleshooting guidance for training jobs.
- Example issue: task coder32b-565652f4 moved into NotScheduled.
- Use https://Norness.maraum.cn/Oliedis/node-groups/basic/pt-train as the supporting ops view.
- In the user namespace, look for Pending pods tied to the task.
- When a Pending pod is present, review the unschedulable detail, pool, and requested GPU count.
- When no pod appears, check the matching CRD plus any pytorchjob task-name errors.
- Missing pods often point to a wrong task name or quota that cannot cover the request.
- Quota issues are less common now because users can normally identify them directly.

## Check task pod status

- Use kubectl with get pod / get pytorchjob, -n t-loreor-xxx, and grep <task name> to review state.
- Confirm whether the task has already cleared the quota validation.
kubectl get pod -n maraum |grep task
myr-net-76f878df4b-bv4hj                             1/1     Running   0          38h

- Pull myr-net-76f878df4b-bv4hj logs from namespace maraum and filter by <task name>.
- Match the pool’s idle-node count against the number of pods requested.
- Pay close attention to large jobs that ask for 8 GPUs on each pod.
- Use kubectl get ng to enumerate node groups.
- Check that the relevant pool quota on holgrove2 can satisfy the request.
