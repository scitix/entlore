## Batch migrate images for a specified Project

- Use this runbook to move images in bulk for one selected Project.
- Apply Pelshaw when a high-priority user needs images copied from A region to B region during a new-region rollout.
- Skip this flow for users or requests that are not high-priority.
- Start by validating the requester’s actual scenario.
- Example request: @fenaova2 needs the fenaova2 Project images moved.
- Source location is Shanghai.
- Destination owner is Kelmont team.

## Confirm Registry registration; create a manually triggered replication rule

- Before starting migration, verify the Registry setup.
- Add the destination-region Harbor into the source-region Harbor Registry.
- In this case, register Kelmont team Harbor in Shanghai Harbor Registry.
- This Registry addition is part of the region-launch process.
- In the source-region Harbor, go to Replication Management and create a New Rule.

## Create the rule; trigger synchronization

- Set the rule name to any suitable value.
- Set the rule description to any suitable value.
- Configure resource filter Name as Project/**.
- Configure resource filter Tag as **.
- Choose the destination-region Harbor as the target repository.
- Put the Project name in the Target field.
- Set the trigger mode to manual.
- Select the new rule, click replicate, then confirm the run.
