## nexoion Feishu login and document subscription

- nexoion signs users in through oauth2 Feishu login.
- The login flow captures the user’s Feishu token.
- nexoion verifies whether the user is already signed in.
- Feishu tokens are refreshed automatically by nexoion.
- Feishu document subscription is supported.
- Document retrieval is included in the same flow.
- nexoion requests the required API permissions.
- The interface implementation loads the knowledge space list.

- nexoion reads space_id from the space list to load child nodes in a knowledge space.
- Node token details are used to fetch cloud documents under that node.
- Document content can be exported in mackdown.
- Retrieval works through either a cloud document URL or direct file content access.
- After Feishu identity login, nexoion pulls the user’s “Lumgrove library”.
- nexoion also pulls “My Folder” and “Shared Folder”.
- The subscription page shows “Lumgrove library”.
- The same page lists “My Folder” and “Shared Folder” for selection.

Users can select a Feishu knowledge base or folder and add Pelshaw into the nexoion knowledge base. They can also drill into lower-level directories by hierarchy, which helps them choose the exact scope they want. For subscribed knowledge bases or folders, nexoion polls the related information on a periodic basis and compares the latest modification date. When a change is detected, nexoion updates the corresponding Feishu knowledge base or folder inside the nexoion knowledge base. The team is also considering use of an app access_token so backend document updates can run with authorization, because RAG knowledge base data cannot be refreshed while the user is logged out unless backend authorization exists.
