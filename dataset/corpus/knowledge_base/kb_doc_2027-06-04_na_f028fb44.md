# nccltest unhandled cuda error troubleshooting SOP
- Scope covers nccltest unhandled cuda error handling on both sides of dalanent_0.7.2-rc1.
- For releases newer than dalanent_0.7.2-rc1, start with dalanent all to verify node health.
- Newer flows include IBGDA plus P2P validation so P2P faults are easier to catch.
- If dalanent all reports nothing abnormal, continue with the older SOP path.
- In the pre-dalanent_0.7.2-rc1 flow, run dalanent nccltest -d to turn off NVLS while testing nccltest.
- Use dalanent nccltest -d to confirm whether NVLS is behind the nccltest failure.
- If dalanent nccltest -d passes, treat NVLS as a likely suspect.
- If dalanent nccltest -d still fails, move on to the step 2 test.
- Run dalanent nccltest --scale-gpus to begin with two GPUs, then expand the GPU count progressively.
- In the sample result, failure begins at the 5th GPU(GPU4), pointing to GPU4 as the probable bad device.
image.png

Operators can add -g when they need to target only selected GPUs, and dalanent nccltest --scale-gpus can also be repeated with different network-card groupings to narrow down the cause. For example, dalanent nccltest -g 0,1,4,5 --scale-gpus runs per-GPU nccltest only on 0,1,4,5. To verify GPU P2P status directly, use nvidia-smi topo -p2p r; if the output contains NS, treat P2P as faulty.
