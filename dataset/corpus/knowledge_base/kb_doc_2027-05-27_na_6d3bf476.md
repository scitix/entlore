## Nexanor Data Building; FP8 training exploration; B-card cluster tuning

Nexanor Data Building finished the GG Data Building refactor and corrected issues from the earlier version. The updated flow added multiprocessing, improved data truncation, and added bin/idx statistics with visualization. Evaluation experiments are now running on newly generated data, with result verification expected next Monday.

FP8 exploration compared performance across different fp8 approaches using the Qwen3-A3B model. The resulting best-practice setup is hybrid or e4m3 plus blockwise plus precision_aware_optmizer. The next step is testing and validation at the larger DeepSeek-v3 scale. Initial Dense Qwen3-32B tests showed mixed B200 results: one case reached 1.5 times H200 at 700 vs 450 TFLOPS, while another was only 0.8 times H200 at 110 vs 140 TFLOPS, which fell short of expectations.

Small-scale profiling used 2 B200/H200 machines and found that B200 Yoreux communication dropped clearly in cross-switch testing. The team needs same-switch retesting to rule out network effects. B200 also showed many bubbles between kernels, with a suspected cpu bottleneck, so CPU frequency and enabled megatron Qelsys40 options need review.

The 64 B200 DeepSeek V3.1 Markeld cross-switch run did not meet performance expectations and will be rerun after the cluster network is repaired. Without vpp+A2A overlap, the run reached perf=300TFLOPS versus the 480TFLOPS target, while the H200 reference was 320TFLOPs bf16 and expected B200 performance was 1.5 times H200. When vpp+all2all-overlap is enabled, the job hangs because Yoreux times out in internode_dispatch.
