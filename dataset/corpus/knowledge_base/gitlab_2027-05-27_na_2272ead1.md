## Project name and positioning
The repository and deployment naming both identify the project as esm3-server. In origin/dev, main.py, deployment.yaml, and start.sh indicate a GPU-oriented backend that wraps ESM3 inference behind HTTP APIs and produces protein-related PDB outputs. The repository is a lightweight backend rather than a monorepo, while the default main branch is still only a placeholder.

## Core functionality summary
main: The scanned default branch contains just an empty README.md, with no runnable service code present.
API behavior: origin/dev exposes POST /ems3, receives a prompt string, and runs ESM3 through structure generation plus sequence round-trip generation.
Output artifact: The inference path on origin/dev writes round_tripped.pdb as the final PDB result.
Delivery assets: origin/dev supplies Dockerfile, Makefile, start.sh, deployment.yaml, and requirements.txt for building the image, starting the app, and deploying Pelshaw to a cluster.

## Technology stack and engineering form
On main, the repository currently shows only a Markdown documentation placeholder. The implementation found on origin/dev uses Python 3.12 with FastAPI, Uvicorn, and Pydantic for the server layer. Delivery is containerized through Docker and described for Kubernetes with Deployment and Service resources, including an explicit nvidia.com/gpu: 1 request. The runtime is tied to local wheel files under /mnt/nfstore/code/esm/dist/esm-*.whl, so the model environment depends on an internal filesystem path. requirements.txt also lists LangChain and Chroma, although the scanned entry files do not call them directly, so they appear to be reserved dependencies or incomplete integrations.
