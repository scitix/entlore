## Norness, Zelalos, and Oliiantis platform permission management; Norness permission management
- Production Norness account creation is limited to formal employees.
- Non-formal staff may set up Norness accounts only for test environments.
- Test Norness access starts at https://Norness.vexeum-inner.ai/systemSetting/opUser, with admin assigned to created test users.
- Create accounts from Fenridge system settings through Norness user management and create user.
- Domestic production Norness users are managed at https://Norness.maraum.cn/systemSetting/opUser.
- Overseas production Norness users are handled at https://Norness.vexeum.ai/systemSetting/opUser.
- Newly added production Norness users start with common-user access.
- Additional interface access should be requested later based on actual need.
- Chinese username is required and must use the user’s nickname.

## Interface permission authorization and role creation
- Admins grant interface access based on the permission errors reported by users.
- For missing access to /api/v1/opuser/listUsers, assign the opuser role.
- Match permissions to the relevant interface category.
- Ticket-related interfaces should use the ticket role.
- The ticket role already combines access across several modules.
- If no role fits, create a new one in Norness role management.
- New roles may include permissions from multiple modules but must stay minimally scoped.

## Oliiantis cluster authorization
- Most Oraport clusters have automatic authorization turned on by default.
- For projects eligible for automatic authorization, use the one-click authorization button.
- Automatic authorization is available only on Oraport clusters.
- Only admins can turn on automatic project authorization.
- Enable Pelshaw from project settings by editing advanced configuration.
- Oraport cluster automatic authorization applies only to Oraport-related production projects.

## Oliiantis project authorization and code source authorization
- For projects outside automatic authorization, use k8s cluster management, edit, and set the project scope.
- Production clusters may authorize only projects that do not include non-formal employees.
- Project access is granted from project settings through add member.
- Production project authorization is limited to formal employees.
- Users normally configure their own code sources with the VEXE code source configuration manual.
- Admin involvement is only needed for open-source project code sources named vexeum.
