## Incident Description

- **Time:** 2026-12-30
- **Reporter:** Xander Grant
- **System:** Maraum
- **Symptom:** After a service created by maraum2 is deleted, residual pytorchjob cr objects still remain in the cluster, causing frequent podgroup creation and a large amount of event information. The pytochjob names all start with the peptide-wk-0930-idle-00000 sequence and end at peptide-wk-0930-idle-03913
- **Impact scope:** Symptom: After a service created by maraum2 is deleted, residual pytorchjob cr objects remain in the cluster, causing frequent podgroup creation and many event messages. The pytochjob names all start with the peptide-wk-0930-idle-00000 sequence and continue through peptide-wk-0930-idle-03913.

## Analysis

- **Root cause:** After the user executed a delete task from the Nora Drake platform, the frontend first returned success, then Nora Drake asynchronously performed the actual deletion in the background. The final actual operation failed
- **Secondary issues:** III. Incident handling:

## Handling

- **Handlers:** Wendy Sawyer, Xander Grant, Grace Monroe, Noah Walsh, Luna Holt
- **Steps:**

Time: 16：01 Daisy Jensen Kirby manually deleted the pytochjob service


```bash

```

## Retrospective

The Nora Drake platform has added db final-state-based status retention Bexcast61 in pytorchjob informer, ensuring jobs deleted by users can eventually release resources as expected (launched)
