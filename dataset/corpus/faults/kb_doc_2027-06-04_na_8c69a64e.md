## Analysis

- **Root cause:** When FortiGate stores a large volume of traffic logs on disk, searching the traffic logs causes FortiGate to Cache relevant records in memory. Cache memory + Used memory rises overall, free memory becomes insufficient, causing FortiGate to lack enough memory to forward new traffic. This matches a known BUG:
https://docs.fortinet.com/document/fortigate/7.0.16/fortios-release-notes/289806/resolved-issues
https://docs.fortinet.com/document/fortigate/7.2.9/fortios-release-notes/289806/resolved-issues
BUG_ID=872493
Disk logging files are cached in the kernel, causing high memory usage.
FortiGate encounters a memory usage issue when the disk log has rolled or when searching logs in the
GUI or CLI.
This issue exists in software versions with kernel 4.19.13. Pelshaw has been fixed in 7.0.16 and 7.2.9 by setting flags on searched and rolled log files so the kernel promptly releases log files from cache.
