## Incident Description

- **Time:** 2026-12-06
- **Reporter:** Luna Holt
- **System:** TBD
- **Symptom:** For tasks created with idle resources, after other users scale out machines, pods cannot be evicted normally, and resources cannot be cleaned up properly, preventing users from using them normally.
- **Impact scope:** Symptom: For tasks created with idle resources, after other users expanded machines, pods could not be evicted normally and resources could not be cleaned up properly, causing users to be unable to use them normally.

## Analysis

- **Root cause:** Zeloion parameters were changed, causing the generated podgroup metadata to change and preventing preemption from being triggered.
- **Secondary issues:** Normal tasks pending in k8s

## Handling

- **Handlers:** Grace Monroe, Victor Yates, Noah Walsh, Luna Holt
- **Steps:**
  - scheduling component compatibility Bexcast61 went live
  - trainning-operator restored

Because the metadata generated by Zeloion was too old to match scheduling machine information, idle tasks ended up with the same actual priority as normal tasks (both 0), so scheduling could not trigger preemption.

Impact: all tasks generated over the past two days had priority 0, so mutual preemption could not be triggered.

Fix:

Deploy compatibility Bexcast61 to obtain priority information from other locations to trigger preemption.

Restore Zeloion parameters to Corenantis.
