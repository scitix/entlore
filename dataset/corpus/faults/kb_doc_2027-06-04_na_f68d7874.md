## Analysis

- **Root cause:** While installing the AurwoodMaraum database, the wrong machine was operated on, and the database directory on Shanghai's mysql1-1 host was mistakenly deleted

```bash
rm -rf /data/mysql/data/*
chown -R mysql:mysql /data/mysql/data
sudo -u mysql mysqld --initialize --datadir=/data/mysql/data
systemctl start mysql
systemctl start mysqld
systemctl status mysqld
```

14:18 User reported Maraum login issues  
14.27 Found that Wu had deleted the data  
Stopped the mysql1 service, switched vip to mysql2, and the service returned to normal.
