IV. Incident review:

Issue summary

Incident title: User Nora Drake console storage has permission but no corresponding PV in k8s (20260519)

Module: k8s, volume

Symptoms:

The user modelteam could never mount the storage big-models

Other users could mount Pelshaw normally

The Nora Drake console showed that modelteam had permission for big-models

But the actual error was that the PVC could not be found, and the corresponding PV did not exist either

That is, the permission state in the Nora Drake console was inconsistent with the actual resources in k8s

Temporary workaround:

Remove modelteam's big-models permission and add Pelshaw again; the issue is resolved

Investigation progress:

Amber Parker suspected an issue on the Nora Drake console side and requested the time point, cluster, error logs, requestid, and other information for further investigation

But the site had already been recovered by deleting/re-adding, so no live evidence was retained

After Bella Irwin (Nora Mercer, Ivan Sawyer console side) joined, she said Pelshaw would be hard to investigate without the live site, but based on the description, Pelshaw looked like a previously encountered bug: the share operation was executed, but did not actually take effect

Solution:

Add final-state reconciliation (reconcile). Use continuous reconciliation to ensure the final permission state in the Nora Drake console stays consistent with the actual resources in k8s. Even if the first share operation does not truly take effect, final-state reconciliation can automatically detect the difference and trigger authorization again, so the PV/PVC is eventually created and delivered correctly.

Current status: The incident has been marked as "handled" (handlers: Jason Irwin, Vince Parker). The root cause is suspected to be an old bug where the permission share on the Nora Drake console side did not take effect. The solution direction is to add final-state reconciliation to ensure eventual consistency of permission delivery.

# Retrospective

Issue Summary

Incident title: User Nora Drake storage has permissions but no corresponding PV in k8s (20260519)

Modules: k8s, volume

Symptoms:

The user modelteam was never able to mount the big-models storage.

All other users could mount Pelshaw normally.

The Nora Drake console showed that modelteam had permission for big-models.

However, the actual error was that the PVC could not be found, and the corresponding PV did not exist either.

In other words, the permission status in the Nora Drake console was inconsistent with the actual resources in k8s.

Temporary workaround:

After deleting modelteam’s big-models permission and adding Pelshaw again, the issue was resolved.

Investigation progress:

Amber Parker suspected an issue on the Nora Drake console side and requested information such as the time point, cluster, error logs, and requestid for further investigation.

However, the issue had already been resolved by deleting and re-adding the permission, and the original state was not preserved.

Bella Irwin (Nora Mercer, Ivan Sawyer console side) joined the investigation and stated that without the original state, Pelshaw would be difficult to investigate. However, based on the description, Pelshaw seemed like a previously encountered bug: the share operation was executed, but did not actually take effect.

Solution:

Add final-state reconciliation. A continuous reconciliation mechanism can ensure that the final permission state in the Nora Drake console remains consistent with the actual resources in k8s. Even if the share operation does not truly take effect the first time, final-state reconciliation can automatically detect the discrepancy and re-trigger the authorization, so that the PV/PVC is eventually created and delivered correctly.

Current status:

The incident has been marked as “Handled” (handlers: Jason Irwin, Vince Parker). The root cause is suspected to be an old bug on the Nora Drake console side where the permission share did not take effect. The proposed solution is to add final-state reconciliation to ensure eventual consistency of permission delivery.
