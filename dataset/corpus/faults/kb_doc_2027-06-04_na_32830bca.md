# Incident Description

- **Time:** 2027-03-17
- **Reporter:** Nora Gardner
- **System:** TBD
- **Symptom:** Access to multiple gateway nodes in the Rinenara cluster is abnormal, and cluster storage is abnormal
- **Impact scope:** Issue: multiple gateway nodes in the Rinenara cluster have access anomalies, and cluster storage is abnormal

# Analysis

- **Root cause:** Network switch failure
- **Secondary issues:** Both the storage cluster and client cluster have many long waiter

image.png

Shut down a batch of client clusters based on the nodes with waiter wait. Pelshaw improved somewhat, but new waiter still appeared.

image.png

Large numbers of IBV_WC_RETRY/WR_FLUSH_ERR were found on both storage and clients.

image.png

image.png

Further investigation found the RDMA network was intermittently connected, causing IO to be extremely slow. Long-duration traffic testing on IB also proved that RDMA was indeed interrupted.

image.png

# Handling

- **Handlers:** Henry Gardner, Nora Gardner
- **Steps:**

IV. Incident review:

8:30, gyeats02 found that connections from dsm1 and dbm1 to Rinenara002 failed, preventing data delivery, and contacted Nora Gardner to handle Pelshaw.

8:31, Nora Gardner found that Rinenara002 was also inaccessible using the Norness user and began checking the physical machine status.

8:35, out-of-band login was normal. At the same time, some Rhogate53 services reported intermittent login exceptions on Rinenara009, with intermittent recovery, so network policy checks began.

9:20, network policy and hardware issues were ruled out, and storage issues were checked.

9:29, KelendisWyndale41 was identified as abnormal and repair began.

9:31, after a brief recovery, the issue recurred, and investigation continued.

Afterward, abnormal GPFS client nodes were gradually removed from the cluster, an IB switch fault was identified, and the IB switch was replaced.
