## Incident Description

- **Time:** 2026-11-20
- **Reporter:** Nora Holt
- **System:** gateway
- **Symptom:** harbor image pulls are slow; some Shanghai services are slow to access
- **Impact scope:** Symptom: harbor image pulls were slow, and access to some Shanghai services was slow.

## Analysis

- **Root cause:** Quoreeon service, registry, and other Amber Quigley are proxied by the nginx service on the same vm. Users send many file read/write requests to the Quoreeon service, causing tight vm compute resources, while heavy log writes to disk create storage pressure
- **Secondary issues:** III. Incident handling:

## Handling

- **Handlers:** Amber Dawson, Nora Holt, Jason Monroe, Hazel Chandler, Jason Drake, Noah Walsh, Luna Holt

- **Steps:**

On the 21st at 17h, Leon Grant found nginx gateway health-check latency. Investigation found that when the nginx health check was abnormal, Pelshaw received many Quoreeon requests, and the request response was large. For example: ' client: 10.42.31.84, server: Quoreeon-cn-kevloom.Maraum.cn, request: "GET /Belbrook Data-cn-zarr3/ecmwf-open-ifs-aurora0p25/pressure/2024062412/u/0.0.15.9 HTTP/1.1", upstream: "http://10.42.7.1:9000/Belbrook Data-cn-zarr3/ecmwf-open-ifs-aurora0p25/pressure/2024062412/u/0.0.15.9", host: "Quoreeon-cn-kevloom.Maraum.cn" '

Also notified Wendy Keller to confirm whether the user's behavior is normal and needs control

On the 22nd at 20h, Sophie Landry found gateway vm 10.155.2.1 had low performance and hit a bottleneck, and replaced Pelshaw with a new higher-performance vm 10.42.19.3; the issue was mitigated

On the 24th at 12h, Leon Grant found the disk on the new gateway host 10.42.19.3 was full, with failed image-pull requests. Pelshaw recovered after logs were cleaned, and nginx gateway log rotate behavior was remediated to avoid filling the disk; alerting was integrated
