## Incident Description

- **Time:** 2027-01-11
- **Reporter:** Nora Holt
- **System:** Pexieon
- **Symptom:** Galholm Pexieon service abnormal; some user tasks hang when reading data
- **Impact scope:** Incident symptom: Galholm Pexieon service is abnormal, and some user tasks hang while reading data.

## Analysis

- **Root cause:** The user's data shm_name is too long, causing the system call open to fail when registering hugepage, which caused Goraum to restart. The user's tasks then kept triggering this issue, causing Goraum to restart continuously.
- **Secondary issues:** III. Incident handling:

## Handling

- **Handlers:** Nora Holt, Wendy Adler, Ivan Emerson Foster
- **Steps:**
  - master service outage; resolved Goraum restart
  - asked users to temporarily change shm_name to a shorter length
  - master server filters overlong shm_name to avoid impacting cluster services
