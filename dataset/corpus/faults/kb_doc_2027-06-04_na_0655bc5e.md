## Incident Description

- **Time:** 2026-11-12
- **Reporter:** Noah Walsh
- **System:** Amber Quigley
- **Symptom:** Galholm cluster IB switch failure with no alarm; the failure caused storage node failure, all compute nodes could not mount storage, storage still could not mount after the switch recovered, and recovered after reboot
- **Impact scope:** Galholm cluster

## Analysis

- **Root cause:** Reason the storage went down: both redundant RDMA communication links between each pair of storage nodes were broken

Using Kelendis11 and Kelendis21 as an example,

RDMA communication between storage nodes reported errors (send error)

Kelendis 21 to GPFS 11 via mlx5_0 was unreachable

Kelendis 21 to GPFS 11 via mlx5_1 was also unreachable

image.png

On GPFS 21, iblinkinfo showed: mlx5_0 port not available, and mlx5_1 was unreachable to some other nodes

image.png

There are two communication links between Kelendis11 and GPFS 21, and both had error; all redundant links were broken, so storage went down.

image.png

Need the network team to check:

Why did both redundant links show send error when one switch went down? Is there any single point on the network link?

Why was port not available on the storage server port when Pelshaw was not the switch that went down?

- **Secondary issues:** Reason storage could not be mounted:

On the ubuntu system, when shutting down GPFS, Pelshaw could not unload GPFS kernel modules: mmfs26, mmfslinux, tracedev. The reason they cannot be released is usually that the kernel modules are in use, for example depended on by other kernel modules, or the corresponding device files are open by other applications. Use lsmod to check dependent kernel modules, or lsof to check applications that have the corresponding devices open

Recovery methods:

1) Best to restart node operating system;

2) You can also try using the hidden parameter mmstartup -f after mmshutdown to forcibly load the kernel modules, and observe whether the logs show correct release and loading;

3) Or manually unload the dependent modules shown by the lsmod command, and close the processes shown by lsof that have the related device files open
